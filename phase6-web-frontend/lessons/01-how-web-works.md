# レッスン 01: Web の仕組み

## 学習目標

- URL を入力してからページが表示されるまでの流れを説明できる
- HTTP リクエスト/レスポンスの構造を理解する
- Chrome DevTools の Network タブを使って通信を観察できる
- ブラウザのレンダリングパイプラインの概要を把握する

---

## 1. URL とは何か

URL (Uniform Resource Locator) は、ネットワーク上のリソースを一意に特定するための「住所」です。

```
https://example.com:443/path/to/page?key=value#section
  |       |          |   |            |          |
  |       |          |   |            |          +-- フラグメント識別子
  |       |          |   |            +------------- クエリパラメータ
  |       |          |   +-------------------------- パス
  |       |          +------------------------------ ポート番号(省略可)
  |       +----------------------------------------- ホスト名(ドメイン)
  +------------------------------------------------- スキーム(プロトコル)
```

## 2. DNS 解決

ブラウザは `example.com` という名前を、コンピュータが通信に使える IP アドレス(例: `93.184.216.34`)に変換する必要があります。
この変換を担うシステムを **DNS (Domain Name System)** と呼びます。

```
[ブラウザ]
    |
    | "example.com の IP アドレスは？"
    v
[DNS リゾルバ(通常はルーター or ISP)]
    |
    | キャッシュになければ権威 DNS サーバーへ問い合わせ
    v
[権威 DNS サーバー]
    |
    | "93.184.216.34 です"
    v
[ブラウザ] → IP アドレスが判明
```

## 3. TCP 接続と TLS ハンドシェイク

IP アドレスが分かったら、ブラウザはサーバーと **TCP (Transmission Control Protocol)** 接続を確立します。
HTTPS(スキームが `https://`)の場合、その上に **TLS (Transport Layer Security)** による暗号化層が追加されます。

TLS ハンドシェイクでは、サーバーの証明書を検証し、通信を暗号化するための鍵交換を行います。

## 4. HTTP リクエストとレスポンス

接続が確立したら、ブラウザは **HTTP (HyperText Transfer Protocol)** リクエストを送信します。

### HTTP リクエストの構造

```
GET /index.html HTTP/1.1          ← リクエストライン(メソッド パス バージョン)
Host: example.com                 ← ヘッダー
Accept: text/html,application/xhtml+xml
Accept-Language: ja,en-US
Connection: keep-alive
                                  ← 空行(ヘッダー終端)
                                  ← ボディ(GET では通常なし)
```

主要な **HTTP メソッド**:

| メソッド | 用途 |
|----------|------|
| GET | リソースの取得(副作用なし) |
| POST | リソースの新規作成、フォーム送信 |
| PUT | リソースの完全置換 |
| PATCH | リソースの部分更新 |
| DELETE | リソースの削除 |

### HTTP レスポンスの構造

```
HTTP/1.1 200 OK                   ← ステータスライン(バージョン ステータスコード 理由句)
Content-Type: text/html; charset=UTF-8
Content-Length: 1234
Cache-Control: max-age=3600
                                  ← 空行
<!DOCTYPE html>                   ← ボディ(HTML コンテンツ)
<html>
...
```

### 主要なステータスコード

| コード | 意味 |
|--------|------|
| 200 OK | 成功 |
| 301 Moved Permanently | 恒久的リダイレクト |
| 304 Not Modified | キャッシュが有効(変更なし) |
| 400 Bad Request | クライアントのリクエストが不正 |
| 401 Unauthorized | 認証が必要 |
| 403 Forbidden | アクセス拒否 |
| 404 Not Found | リソースが存在しない |
| 500 Internal Server Error | サーバー側のエラー |

## 5. ブラウザのレンダリングパイプライン

HTML が届いたら、ブラウザは次のステップでページを構築します。

```
HTML テキスト
    |
    | パース(解析)
    v
DOM ツリー (Document Object Model)
    |
CSS テキスト
    |
    | パース
    v
CSSOM ツリー (CSS Object Model)
    |
DOM + CSSOM
    |
    | 結合
    v
レンダーツリー (表示されるノードのみ)
    |
    | レイアウト(各ノードのサイズ・位置計算)
    v
    | ペイント(ピクセルに色を塗る)
    v
    | コンポジット(GPU で合成)
    v
画面表示
```

**重要な概念**:
- **DOM (Document Object Model)**: HTML を JavaScript から操作できるツリー構造のオブジェクト
- **クリティカルレンダリングパス**: 初回表示に必要な最小限の処理フロー
- **リフロー(Reflow)**: レイアウト計算のやり直し(高コスト)
- **リペイント(Repaint)**: 色の塗り直し(リフローよりは低コスト)

## 6. Chrome DevTools の使い方

### Network タブを開く

1. Chrome で任意のページを開く
2. `F12` または `Cmd + Option + I`(Mac) / `Ctrl + Shift + I`(Windows)で DevTools を開く
3. 「Network」タブをクリック
4. ページをリロード(`Cmd + R` / `F5`)

### 確認できる情報

- **Name**: リクエストしたリソースのファイル名
- **Status**: HTTP ステータスコード
- **Type**: リソースの種類(document, stylesheet, script, fetch など)
- **Size**: レスポンスのサイズ
- **Time**: 通信にかかった時間
- **Waterfall**: リクエストのタイムライン

### リクエストの詳細を見る

Network タブで任意のリクエストをクリックすると:
- **Headers** タブ: リクエスト/レスポンスヘッダー
- **Preview** タブ: レスポンスのプレビュー
- **Response** タブ: レスポンスの生テキスト
- **Timing** タブ: 各フェーズ(DNS, TCP, TLS, TTFB 等)の時間

### Elements タブ

DOM ツリーをリアルタイムで確認・編集できます。
要素にカーソルを当てると、ページ上でハイライトされます。

### Console タブ

JavaScript のエラーや `console.log()` の出力が表示されます。
直接 JavaScript を入力して実行することもできます。

## 7. HTTP/1.1 vs HTTP/2 vs HTTP/3

| バージョン | 特徴 |
|------------|------|
| HTTP/1.1 | テキストベース。1 接続 1 リクエスト(Keep-Alive で改善) |
| HTTP/2 | バイナリフレーム。1 接続で複数リクエストを多重化 |
| HTTP/3 | UDP ベースの QUIC を使用。ヘッドオブラインブロッキングを解消 |

現代の多くのサイトは HTTP/2 以上を使用しています。DevTools の Network タブの「Protocol」列で確認できます。

## 💡 コラム: 「曖昧だが、面白い」— Web 誕生の瞬間

1989年、スイスの CERN(欧州原子核研究機構)で働く物理学者ティム・バーナーズ=リーは、研究情報の共有システムの提案書を上司に提出しました。上司マイク・センドールが余白に書いたコメントが歴史に残っています — 「**曖昧だが、面白い(Vague but exciting)**」。

この「曖昧だが面白い」提案が World Wide Web になりました。世界初の Web サイトは今も `info.cern.ch` で見られます(飾り気ゼロの白いページです)。

見逃せないのは彼の決断です。バーナーズ=リーは Web の技術を**特許にせず、使用料も取らず、人類に無償開放**しました。もし Web が1クリックごとに課金される技術だったら、今日のインターネットはありません。あなたがこれから無料で学べる HTML も HTTP も、この決断の恩恵です。彼は後にこう言っています。「これは万人のためのものだ(This is for everyone)」。

## まとめ

- URL は `スキーム://ホスト/パス?クエリ#フラグメント` の構造を持つ
- DNS がドメイン名を IP アドレスに変換する
- HTTPS では TCP 接続の上に TLS 暗号化が加わる
- HTTP はリクエスト/レスポンス構造のテキストプロトコル
- ブラウザは HTML → DOM、CSS → CSSOM → レンダーツリー → レイアウト → ペイントの順で描画する
- DevTools の Network タブで通信を詳細に観察できる

## 確認問題

1. ブラウザが `https://example.com/about` にアクセスするとき、DNS 解決から HTML 受信までの手順を順番に説明してください。

2. HTTP ステータスコード 301 と 404 の違いを説明してください。

3. DevTools の Network タブで、あるリクエストが `304 Not Modified` を返しているとき、これは何を意味しますか？

4. DOM と HTML の違いを説明してください。

5. リフローとリペイントの違いは何ですか？どちらがより高コストですか？

## よくある間違い

### 間違い 1: HTTP と HTTPS を同一視する

HTTP と HTTPS は別物です。HTTPS は HTTP に TLS による暗号化を追加したものです。
現代の Web では、すべての通信を HTTPS で行うことが標準です。
HTTP のみのサイトはブラウザに「保護されていない通信」と表示されます。

### 間違い 2: ステータスコード 200 が「完璧」を意味すると思う

ステータスコード 200 は「サーバーがリクエストを処理して何かを返した」という意味に過ぎません。
返ってきたデータが期待通りかどうかは、ボディを確認する必要があります。

### 間違い 3: DOM = HTML ファイルだと思う

HTML ファイルはテキストです。DOM はそれをブラウザが解析して作ったメモリ上のオブジェクトツリーです。
JavaScript で DOM を操作しても、元の HTML ファイルは変わりません。
また、JavaScript が DOM を動的に変更した後の状態は、Elements タブで確認できますが、
「ページのソースを表示」では元の HTML が表示されます。
