## 中心にある1つの考え方

> **Python の変数は「箱」ではなく「名札」である。**

代入 `b = a` は中身を複製しません。同じオブジェクトにもう一枚名札を貼るだけです。ここから、この演習のほぼすべてが導けます。

| 操作 | 何が起きるか |
|---|---|
| `b = a` | 名札を増やす。オブジェクトは1つのまま |
| `b.append(4)` | **オブジェクト自体**を変更 → `a` からも見える |
| `b = b + [4]` | **新しいオブジェクト**を作って `b` の名札を貼り替え → `a` は無傷 |
| `b += [4]`(list) | `extend` と同じ。オブジェクト自体を変更 → `a` からも見える |
| `x += " world"`(str) | 文字列は変更不可なので新オブジェクト → 元は無傷 |

`+=` がリストと文字列で挙動が違って見えるのは、**ミュータブルかどうかの違い**です。`+=` は可能ならその場で変更し、できなければ新規作成します。

## 問題 3: なぜクラス変数が共有されるのか

```python
class Student:
    grades = []            # クラスの定義時に 1 回だけ作られる

    def add_grade(self, g):
        self.grades.append(g)   # ← self に grades が無いのでクラス変数を探す
```

`self.grades` の解決順は「インスタンス属性 → クラス属性」です。インスタンスに `grades` が無いので、クラスが持つ**全員共有のリスト**が見つかり、それを `append` します。

紛らわしいのは、**代入なら共有されない**ことです。

```python
self.grades = []        # インスタンス属性を新しく作る(共有されない)
self.grades.append(x)   # クラス変数を変更する(共有される)
```

「変更(mutate)」と「代入(rebind)」は別物、というのがここでも効いてきます。

### では、クラス変数はいつ使うのか

共有したい定数には適切です。

```python
class Circle:
    PI = 3.14159            # ○ イミュータブルで、全インスタンス共通
    ALLOWED = ("red", "blue")  # ○ タプルなので変更されない
```

**ミュータブルなオブジェクトをクラス変数にしない**、と覚えておけば事故りません。

## 問題 4: デフォルト引数は「関数定義時」に 1 回だけ評価される

```python
>>> add_item_buggy.__defaults__
([1, 2, 3],)
```

関数オブジェクトがそのリストを保持し続けている様子が、`__defaults__` で直接見えます。ここが理解の核心です。デフォルト値は呼び出しのたびに作り直されません。

修正は `None` を番兵にする形が定石です。

```python
def add_item(item, lst=None):
    if lst is None:
        lst = []
```

`if not lst:` と書くと、**空リストを渡したときにも新しいリストを作ってしまいます**。`is None` で書くこと。

同じ罠は日付でも起きます。

```python
def log(msg, when=datetime.now()):   # ✗ 起動時刻で固定される
def log(msg, when=None):             # ○
    when = when or datetime.now()
```

## 問題 5: 「純粋関数」がなぜ強いか

バグ版の実行結果を見てください。

```
バグ版の結果    : [1, 2, 4]     ← 3 が消えている
引数も破壊される: [2, 3, 1]     ← 呼び出し側のデータが壊れた
```

2つの問題が同時に起きています。

1. **ループ中の削除で要素が飛ばされる**(レッスン 10 の 5.2 と同じ現象)
2. **引数を破壊している**(呼び出し側は自分のリストが変わるとは思っていない)

修正版は引数を一切触らず、新しいリストを返します。こういう関数を**純粋関数(pure function)** と呼びます。

- 同じ入力なら必ず同じ出力
- 外部の状態を変更しない

純粋関数はテストが簡単で、並行実行しても安全で、`lru_cache` も付けられます。Phase 9 の設計、Phase 8 の並行処理まで、この性質がずっと効いてきます。

**「関数が引数を変更するなら、それは名前で明示する」**のが作法です。`sort_in_place(lst)` と `sorted(lst)` のように。

### `set` を使う理由

```python
seen = set()      # in の判定が O(1)
seen = []         # in の判定が O(n)
```

要素数が 10,000 なら 10,000 倍近い差になります。ただし `set` に入れられるのは**ハッシュ可能な値**だけです。リストや辞書を含むデータでは使えません。

Python 3.7 以降は `dict` が挿入順を保つので、1 行でも書けます。

```python
list(dict.fromkeys(data))
```

## 問題 6: タプルは何を保証しているのか

```python
t = ([1, 2], [3, 4])
t[0].append(3)   # OK    → ([1, 2, 3], [3, 4])
t[0] = [9, 9]    # TypeError
```

タプルが保証するのは「**どのオブジェクトを指すか**」が変わらないことだけです。「指している先の中身」は保証しません。

実害が出るのはハッシュ化のときです。

```python
{t: "value"}   # TypeError: unhashable type: 'list'
```

タプルのハッシュ値は要素のハッシュ値から計算されるため、中にリストがあると計算できません。**「タプルだから辞書のキーにできる」は誤り**で、正しくは「中身まですべてイミュータブルなタプルならキーにできる」です。

## 問題 7: 整数キャッシュ — 実装詳細に依存しない

CPython は `-5` 〜 `256` の小整数をあらかじめ作って使い回します。この範囲では `is` が `True` になります。

**しかし、範囲外でも書き方によって結果が変わります。**

```python
a = 257
b = 257
a is b        # → True(同じコードブロック内では定数がまとめられる)
```

```
>>> a = 257     # REPL に 1 行ずつ入力すると
>>> b = 257     # 別々にコンパイルされるので
>>> a is b
False
```

つまり `is` の結果は、**値ではなく「どう書いたか」で変わります**。これは CPython の最適化(定数畳み込み)の副作用であり、言語仕様ではありません。他の実装や将来のバージョンで変わりえます。

### 結論

| 用途 | 使うもの |
|---|---|
| 値が等しいか | `==` |
| 同じオブジェクトか | `is` |
| `None` の判定 | `is None`(慣習として必ずこちら) |

`is` を使ってよいのは、`None` / `True` / `False` のように**プロセス内で唯一であることが保証されたオブジェクト**だけです。

`count is 1000` と書くと Python 自身が警告します。

```
SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
```

**警告は黙らせるものではなく読むもの**です。この警告は実際にバグを指しています。

## 問題 8: 参照カウントとサイクル GC

Python の主たるメモリ管理は**参照カウント**です。参照が 0 になった瞬間に解放されます。

```
node_a の参照カウント: 2
  ローカル変数 node_a  ... 1
  node_b.partner       ... 1
```

`del node_a; del node_b` としても、互いを指す参照が残るためカウントは 0 になりません。これが**循環参照(reference cycle)** です。

そこで Python は補助的に**サイクル GC** を持ち、到達不能になった循環を検出して回収します。解答スクリプトでは `gc.collect()` が 2 個のオブジェクトを回収したことが確認できます。

### 実務で意識すべきこと

普段は意識不要ですが、次の場合は注意します。

- **双方向リンク**(親 ⇔ 子、ノード ⇔ 隣接ノード)を作るとき → `weakref` を検討する
- 大量の循環参照 → GC の実行時間がレイテンシに影響しうる
- 長時間動くサーバー → メモリ使用量の監視(Phase 10 の可観測性へ)

`sys.getrefcount(x)` は引数として渡された分だけカウントが 1 増えるため、解答では `-1` しています。こうした細かい罠も、実際に動かして確かめると身につきます。

## この演習で身につく判断

| 場面 | 判断 |
|---|---|
| 変数を代入する | 複製ではなく名札が増えるだけ |
| クラス属性を書く | ミュータブルなものを置かない |
| デフォルト引数 | ミュータブルなら `None` を番兵に |
| 関数を書く | 引数を変更しない(するなら名前で明示) |
| 重複除去・存在判定 | `set` か `dict`(`list` の `in` は遅い) |
| タプルをキーにする | 中身までイミュータブルか確認する |
| 値を比較する | `==`。`is` は `None` などにだけ |
| 警告が出た | 黙らせず読む |
