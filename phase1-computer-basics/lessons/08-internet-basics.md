## 学習目標

- IP アドレス（IP address）の役割を説明できる

## 1. ネットワークの基礎概念

### コンピュータのネットワーク

インターネットは、世界中のコンピュータを繋ぐ巨大なネットワークです。
コンピュータ同士が通信するには「どこに送るか（宛先）」を識別する仕組みが必要です。

```
あなたの PC ─── ルーター ─── インターネット ─── サーバー
              (自宅/会社)    (世界中のネットワーク)
```

## 2. IP アドレス（IP Address）

### IP アドレスとは

IP アドレス（Internet Protocol address）は、ネットワーク上の機器を識別する**住所**です。
現在は IPv4 と IPv6 の 2 種類があります。

### IPv4

最も広く使われる形式。32ビットの数値を 8ビットずつ4つのグループに分け、ドット区切りで表記します。

```
192.168.1.100
^^^ ^^^ ^ ^^^
 |   |  |  |
 |   |  |  ホスト部（機器を識別）
 |   |  |
 ネットワーク部（ネットワークを識別）
```

各グループは 0〜255 の値（= 8ビット）。
例: `192.168.1.100`、`10.0.0.1`、`8.8.8.8`

**特殊な IP アドレス:**

| アドレス | 意味 |
|---------|------|
| `127.0.0.1` | ループバックアドレス（localhost）。自分自身を指す |
| `192.168.x.x` | プライベートアドレス。自宅 LAN など内部ネットワークで使用 |
| `10.x.x.x` | プライベートアドレス（大きなネットワーク向け） |
| `0.0.0.0` | すべてのインターフェースを表す |

### IPv6

IPv4 のアドレス枯渇問題を解決するために作られた次世代規格。128ビットで表現します。

```
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

### IP アドレスの確認

```bash
# macOS
$ ifconfig | grep "inet "

# Linux
$ ip addr show
# または
$ hostname -I

# 外部から見えるグローバル IP アドレスを確認
$ curl ifconfig.me
203.0.113.42
```

## 3. DNS（Domain Name System）

### DNS とは

人間は `192.0.2.1` のような数字の羅列より `google.com` のような名前を覚えやすいですね。
DNS は**ドメイン名（domain name）を IP アドレスに変換する**電話帳のような仕組みです。

```
あなたのブラウザ
  |
  | 1. "google.com の IP アドレスを教えて"
  ↓
DNS サーバー
  |
  | 2. "142.250.x.x です"
  ↓
あなたのブラウザ
  |
  | 3. 142.250.x.x に接続
  ↓
Google のサーバー
```

### DNS 解決の流れ（詳細）

```
ブラウザ → キャッシュを確認
         → OS のキャッシュを確認（/etc/hosts）
         → DNS リゾルバ（プロバイダのDNSサーバーなど）に問い合わせ
           → ルートDNSサーバー → .com DNS サーバー → google.com DNS サーバー
         → IP アドレスを取得
```

### /etc/hosts

`/etc/hosts` は DNS より前に参照されるローカルの名前解決ファイルです。

```bash
$ cat /etc/hosts
127.0.0.1   localhost
::1         localhost

# 開発中にローカルサーバーに名前をつけたりする
127.0.0.1   myapp.local
```

### DNS の確認コマンド

```bash
# ドメイン名から IP アドレスを調べる
$ nslookup google.com
Server:     192.168.1.1
Address:    192.168.1.1#53

Non-authoritative answer:
Name:    google.com
Address: 142.250.185.46

# dig コマンド（より詳細な情報）
$ dig google.com
; <<>> DiG 9.10.6 <<>> google.com
...
;; ANSWER SECTION:
google.com.    60    IN    A    142.250.185.46
```

### DNS レコードの種類

| レコード | 意味 | 例 |
|---------|------|-----|
| `A` | ドメイン → IPv4 アドレス | `google.com → 142.250.x.x` |
| `AAAA` | ドメイン → IPv6 アドレス | `google.com → 2404:...` |
| `CNAME` | ドメイン → 別のドメイン（エイリアス） | `www.example.com → example.com` |
| `MX` | メールサーバーの指定 | `example.com のメールは mail.example.com へ` |
| `TXT` | テキスト情報（認証など） | SPF レコードなど |

## 4. URL（Uniform Resource Locator）

### URL の構造

URL はインターネット上のリソース（ファイル・ページなど）の場所を表す文字列です。

```
https://www.example.com:443/path/to/page?key=value&foo=bar#section
^^^^^   ^^^^^^^^^^^^^^^^ ^^^ ^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^ ^^^^^^^
  |           |           |       |               |              |
スキーム    ホスト名     ポート  パス          クエリパラメータ   フラグメント
(プロトコル)            (省略可)
```

| 部分 | 名称 | 説明 |
|------|------|------|
| `https` | スキーム（scheme）| 通信プロトコル |
| `www.example.com` | ホスト名（hostname）| サーバーのドメイン名または IP |
| `:443` | ポート番号（port）| アクセス先のポート（省略可） |
| `/path/to/page` | パス（path）| サーバー上のリソースの場所 |
| `?key=value` | クエリ文字列（query string）| 追加パラメータ |
| `#section` | フラグメント（fragment）| ページ内の位置 |

### ポート番号

ポート（port）は、コンピュータの「窓口番号」です。1台のコンピュータが複数のサービスを同時に提供するために使います。

| ポート番号 | プロトコル | 用途 |
|-----------|-----------|------|
| 80 | HTTP | Web（暗号化なし） |
| 443 | HTTPS | Web（暗号化あり） |
| 22 | SSH | リモートログイン |
| 21 | FTP | ファイル転送 |
| 25 | SMTP | メール送信 |
| 3306 | MySQL | データベース |
| 5432 | PostgreSQL | データベース |
| 3000 / 8080 | （慣例）| 開発サーバー |

## 5. HTTP / HTTPS

### HTTP（HyperText Transfer Protocol）

HTTP は Web ブラウザとサーバー間で**データをやり取りするためのプロトコル（通信規約）**です。

**リクエストとレスポンス:**

```
ブラウザ（クライアント）              サーバー
       |                               |
       | ─── HTTP リクエスト ────────→ |
       |  GET /index.html HTTP/1.1     |
       |  Host: www.example.com        |
       |                               |
       | ←─── HTTP レスポンス ─────── |
       |  HTTP/1.1 200 OK              |
       |  Content-Type: text/html      |
       |  <html>...</html>             |
       |                               |
```

### HTTP メソッド

| メソッド | 意味 | 主な用途 |
|---------|------|---------|
| `GET` | リソースを取得 | ページの閲覧 |
| `POST` | データを送信（作成） | フォーム送信、新規作成 |
| `PUT` | データを更新（全体置換） | 情報の更新 |
| `PATCH` | データを一部更新 | 一部の情報更新 |
| `DELETE` | リソースを削除 | データの削除 |

### HTTP ステータスコード

| コード | 分類 | 意味 | 例 |
|--------|------|------|-----|
| 2xx | 成功 | リクエスト成功 | |
| `200` | | OK（正常） | ページ取得成功 |
| `201` | | Created（作成成功） | 新規登録成功 |
| 3xx | リダイレクト | 別の場所へ転送 | |
| `301` | | Moved Permanently | URL が変わった |
| `302` | | Found（一時的な転送） | 一時リダイレクト |
| 4xx | クライアントエラー | 要求に問題あり | |
| `400` | | Bad Request | リクエストが不正 |
| `401` | | Unauthorized | 認証が必要 |
| `403` | | Forbidden | アクセス禁止 |
| `404` | | Not Found | ページが見つからない |
| 5xx | サーバーエラー | サーバー側の問題 | |
| `500` | | Internal Server Error | サーバーエラー |
| `503` | | Service Unavailable | サービス利用不可 |

### HTTPS

HTTPS（HTTP Secure）は HTTP に**TLS（Transport Layer Security）**による暗号化を加えたものです。

```
HTTP:  データが平文（盗み見られる可能性がある）
HTTPS: データが暗号化される（盗み見られても読めない）
```

現代のWebサイトは原則として HTTPS を使うべきです。ブラウザのアドレスバーの鍵マークが HTTPS の証拠です。

### curl コマンドで HTTP を体験

```bash
# GET リクエストを送る
$ curl https://httpbin.org/get
{
  "headers": {
    "Host": "httpbin.org",
    "User-Agent": "curl/7.88.1"
  },
  "url": "https://httpbin.org/get"
}

# レスポンスヘッダも表示
$ curl -I https://www.google.com
HTTP/2 200
content-type: text/html; charset=ISO-8859-1
date: Sat, 05 Jul 2024 10:00:00 GMT
...

# POST リクエストを送る
$ curl -X POST https://httpbin.org/post \
  -H "Content-Type: application/json" \
  -d '{"name": "Alice", "age": 25}'
```

## 💡 コラム: 人類最初のインターネット通信は「LO」

1969年10月29日、インターネットの祖先 ARPANET で最初の通信が行われました。UCLA からスタンフォード研究所へ「LOGIN」と送信しようとして — **「L」「O」の2文字を送ったところでシステムがクラッシュ**しました。

人類のネットワーク時代の第一声は「LO」。関係者は後に「"Lo and behold"(見よ、驚くべきものを)みたいで、これ以上ない始まりだった」と振り返っています。この2文字から60年たらずで、地球上の数十億人が動画をリアルタイムで送り合う世界になりました。

仕組みの本質は郵便に似ています: **IP アドレスは住所**、**DNS は電話帳**(名前から住所を引く)、**パケットは小包**(大きな荷物は分割して送り、届け先で組み立てる)。この3つの例えを覚えておけば、ネットワークの議論の8割についていけます。

## 6. まとめ図: Web アクセスの全体像

```
1. ユーザーがブラウザに URL を入力
   https://www.example.com/page

2. DNS 解決
   www.example.com → 93.184.216.34

3. TCP 接続（ポート 443）
   ブラウザ ─── 3ウェイハンドシェイク ─── サーバー

4. TLS ハンドシェイク（HTTPS の場合）
   暗号化通信の確立

5. HTTP リクエスト送信
   GET /page HTTP/2
   Host: www.example.com

6. HTTP レスポンス受信
   HTTP/2 200 OK
   <html>...</html>

7. ブラウザがHTMLを解析して画面表示
```

---

## まとめ

- IP アドレスはネットワーク上の機器の住所。`127.0.0.1` は自分自身
- DNS はドメイン名（human-readable）を IP アドレス（machine-readable）に変換する
- URL はスキーム・ホスト・パス・クエリパラメータで構成される
- HTTP はクライアントとサーバーが通信するプロトコル。メソッドで操作を指定する
- ステータスコード: 2xx（成功）、4xx（クライアントエラー）、5xx（サーバーエラー）
- HTTPS は HTTP に暗号化を加えたもの。現代の Web では必須

## 確認問題

**Q1.** IP アドレスを「電話番号」、DNS を「電話帳」に例えて、Web アクセスの流れを説明してください。

**Q2.** 次の URL の各部分を説明してください:
```
https://api.example.com:8080/users/123?format=json#profile
```

**Q3.** HTTP ステータスコード 404 と 500 の違いは何ですか？

**Q4.** `curl https://httpbin.org/get` を実行したとき、何が起きますか？（DNS から HTTP レスポンスまでの流れを書いてください）

**Q5.** なぜ HTTP ではなく HTTPS を使うべきなのですか？

<details>
<summary>解答（自分で考えてから開いてください）</summary>

**A1.**
「google.com に接続して」と入力する = 「山田さんに電話したい」というリクエスト。
DNS（電話帳）に「google.com の番号は何番？」と問い合わせる。
DNS が「142.250.x.x です」と教えてくれる = 電話帳に「山田さんは 090-xxxx-xxxx」と載っている。
その番号（IP アドレス）に接続する = 電話をかける。

**A2.**
- `https`: スキーム（HTTPS プロトコルで通信する）
- `api.example.com`: ホスト名（接続先サーバーのドメイン名）
- `:8080`: ポート番号（8080 番ポートに接続する）
- `/users/123`: パス（サーバー上のリソースの場所。ID=123 のユーザー）
- `?format=json`: クエリパラメータ（JSON 形式で返してほしいという指定）
- `#profile`: フラグメント（ページ内の「profile」セクションへジャンプ）

**A3.**
- 404: クライアントエラー。指定したページ・リソースがサーバーに存在しない。URL が間違っているか、削除されている
- 500: サーバーエラー。サーバー側でプログラムのバグや設定ミスなどが発生している。クライアントのリクエストに問題はない

**A4.**
1. OS が `httpbin.org` の IP アドレスを DNS に問い合わせる
2. DNS サーバーが IP アドレスを返す
3. curl がその IP アドレスのポート 443 に TCP 接続する
4. TLS ハンドシェイクで暗号化通信を確立する
5. `GET /get HTTP/2` リクエストを送信する
6. サーバーが `200 OK` とともに JSON レスポンスを返す
7. curl が受け取った内容を画面に表示する

**A5.**
HTTP では通信内容が平文（暗号化なし）で送られるため、途中でデータを傍受された場合にパスワードやクレジットカード番号などの機密情報が読まれてしまう。HTTPS は通信を暗号化するため、傍受されてもデータが読めない。

</details>
