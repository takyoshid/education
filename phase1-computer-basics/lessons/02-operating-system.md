# Lesson 02: OS の役割

## 学習目標

- OS（オペレーティングシステム）が何をしているかを説明できる
- プロセス（process）とは何かを理解する
- ファイルシステム（file system）の構造を理解する
- パーミッション（permission）の読み方・変え方を習得する

---

## 1. OS（Operating System）とは

OS は、ハードウェア（CPU、メモリ、ストレージ）とアプリケーション（ブラウザ、エディタなど）の間に立つ「管理者」です。

```
+---------------------------+
|   アプリケーション         |  ← ユーザーが使うソフト
|  (Chrome, VS Code, ...)   |
+---------------------------+
|     OS (macOS / Linux)    |  ← 管理者
+---------------------------+
|      ハードウェア          |  ← 物理的な機械
|  (CPU, RAM, SSD, ...)     |
+---------------------------+
```

**OS がなければ:**
- 各アプリが直接ハードウェアを制御しなければならない
- 複数のアプリが同時にメモリや CPU を使うとき、衝突が起きる
- アプリ開発者はすべての CPU の種類に個別対応しなければならない

**OS があると:**
- ハードウェアの違いを隠蔽（いんぺい）し、統一した API（Application Programming Interface）を提供する
- 複数のアプリが安全に共存できるよう管理する
- ファイルやネットワークへのアクセスを制御する

### 主要な OS

| OS | 主な用途 | カーネル |
|----|----------|---------|
| macOS | Mac コンピュータ | Darwin（Unix 系） |
| Linux | サーバー、開発環境 | Linux カーネル |
| Windows | 一般 PC | Windows NT カーネル |
| iOS / Android | スマートフォン | Darwin / Linux ベース |

エンジニアとして働く場合、**Linux** の知識は必須です。世界のサーバーの大部分が Linux で動いています。macOS は Unix 系なので、Linux のコマンドが多数使えます。

## 2. プロセス（Process）

### プロセスとは

プロセスとは、**実行中のプログラムの1つのインスタンス（instance）**です。

- Chrome を起動する → Chrome のプロセスが作成される
- Chrome を 2 つ起動する → 2 つのプロセスが作成される

### プロセスが持つもの

| 要素 | 説明 |
|------|------|
| PID（Process ID） | プロセスを一意に識別する番号 |
| メモリ領域 | プロセス専用の仮想メモリ空間 |
| CPU 時間 | OS から割り当てられた計算時間 |
| ファイルディスクリプタ | 開いているファイルへの参照 |
| 環境変数 | プロセスが参照できる設定値 |

### プロセスの確認

ターミナルで実行中のプロセスを確認できます。

```bash
$ ps aux
```

実行例（一部抜粋）:
```
USER       PID  %CPU %MEM    VSZ   RSS   STAT  COMMAND
takuya   12345   0.5  1.2  12345  5678   S     /Applications/Xcode.app/...
takuya   12346   2.1  3.4  23456  8901   R     Google Chrome
root         1   0.0  0.1   1234   456   Ss    /sbin/launchd
```

- **USER**: プロセスの所有者
- **PID**: プロセス ID
- **%CPU**: CPU 使用率
- **%MEM**: メモリ使用率
- **COMMAND**: コマンド名

```bash
# プロセスを名前で検索
$ ps aux | grep chrome

# より見やすい形式
$ top
```

### プロセスの終了

```bash
# PID を指定してプロセスを終了（丁寧な停止要求）
$ kill 12345

# 強制終了（応答しないプロセスに使う）
$ kill -9 12345
```

### 親プロセスと子プロセス

プロセスは「親子関係」を持ちます。

- OS が起動 → 最初のプロセス（PID=1）が生成される
- PID=1 が他のプロセスを生成する（子プロセス）
- ターミナルを開く → シェルプロセスが起動
- シェルでコマンドを実行 → コマンドの子プロセスが生成される

## 3. ファイルシステム（File System）

### ファイルシステムとは

ファイルシステムは、ストレージ上のデータを**ファイルとディレクトリ（directory）のツリー構造**で管理する仕組みです。

ディレクトリとフォルダは同じものです（GUI では「フォルダ」、CLI では「ディレクトリ」と呼ぶことが多い）。

### Unix/Linux のディレクトリ構造

Unix/Linux（macOS を含む）では、すべてのファイルは `/`（ルート、root）から始まるツリー構造に配置されます。

```
/                          <- ルートディレクトリ（最上位）
├── bin/                   <- 基本コマンドの実行ファイル（ls, cp など）
├── etc/                   <- システムの設定ファイル
├── home/                  <- ユーザーのホームディレクトリ（Linux）
│   └── takuya/            <- ユーザー takuya のホーム
├── tmp/                   <- 一時ファイル（再起動で削除される）
├── usr/                   <- ユーザー向けのプログラムやライブラリ
│   ├── bin/               <- 追加コマンド
│   └── local/             <- ユーザーがインストールしたソフト
└── var/                   <- 可変データ（ログファイルなど）
    └── log/               <- ログファイル
```

**macOS の場合の違い:**
```
/Users/takuya/             <- ホームディレクトリ（Linux の /home/takuya に相当）
/Applications/             <- アプリケーション
```

### パス（Path）

ファイルやディレクトリの場所を表す文字列を**パス（path）**といいます。

**絶対パス（absolute path）:**
`/` から始まるパス。どこにいても同じ場所を指す。
```
/Users/takuya/Documents/memo.txt
/etc/hosts
```

**相対パス（relative path）:**
現在地（カレントディレクトリ）からの相対的な位置を表すパス。
```
Documents/memo.txt      <- カレントが /Users/takuya の場合
../                     <- 1つ上のディレクトリ
./script.sh             <- カレントディレクトリの script.sh
```

**特殊なパス表記:**

| 表記 | 意味 |
|------|------|
| `~` | ホームディレクトリ（例: `/Users/takuya`） |
| `.` | カレントディレクトリ |
| `..` | 1つ上のディレクトリ（親ディレクトリ） |

## 4. パーミッション（Permission / 権限）

### パーミッションとは

Unix/Linux では、すべてのファイルとディレクトリに「誰が何をできるか」という権限が設定されています。これが**パーミッション（permission）**です。

### 所有者の種類

| 種別 | 説明 |
|------|------|
| **owner（所有者）** | ファイルを作成したユーザー |
| **group（グループ）** | 所有者が属するグループ |
| **others（その他）** | 上記以外の全ユーザー |

### パーミッションの種類

| 権限 | ファイルの場合 | ディレクトリの場合 |
|------|-------------|----------------|
| **r（read / 読み取り）** | ファイルの内容を読める | ディレクトリの一覧を見られる |
| **w（write / 書き込み）** | ファイルを変更・削除できる | ファイルを作成・削除できる |
| **x（execute / 実行）** | ファイルをプログラムとして実行できる | ディレクトリに移動できる（cd できる） |

### パーミッションの表示

```bash
$ ls -l
```

実行例:
```
-rw-r--r--   1 takuya  staff   1234 Jul  5 10:00 readme.txt
drwxr-xr-x   3 takuya  staff    102 Jul  5 09:00 Documents
-rwxr-xr-x   1 takuya  staff    456 Jul  5 11:00 script.sh
```

最初の10文字を読む方法:

```
- r w x r - x r - -
^ ^^^ ^^^ ^^^
|  |   |   |
|  |   |   +-- others（その他）の権限: r--（読み取りのみ）
|  |   +------ group（グループ）の権限: r-x（読み取り・実行）
|  +---------- owner（所有者）の権限: rwx（読み書き実行）
+------------- ファイル種別: - はファイル、d はディレクトリ
```

### 数値表記（octal / 8進数）

パーミッションは数値でも表現できます。

| 権限 | 数値 |
|------|------|
| r    | 4    |
| w    | 2    |
| x    | 1    |
| なし | 0    |

例: `rwxr-xr--`
```
rwx = 4+2+1 = 7（所有者）
r-x = 4+0+1 = 5（グループ）
r-- = 4+0+0 = 4（その他）
→ 754
```

よく使う数値:
| 数値 | 意味 | 使いどころ |
|------|------|-----------|
| `644` | rw-r--r-- | 通常のファイル |
| `755` | rwxr-xr-x | 実行可能ファイル、ディレクトリ |
| `600` | rw------- | 秘密鍵などの機密ファイル |
| `777` | rwxrwxrwx | 全員が全権限（通常は避けるべき） |

### パーミッションの変更

```bash
# chmod（change mode）コマンドで変更する
# 数値で指定
$ chmod 755 script.sh

# 記号で指定（+で追加、-で削除、=で設定）
$ chmod +x script.sh      # 実行権限を全員に追加
$ chmod u+x script.sh     # 所有者（u=user）に実行権限を追加
$ chmod go-w file.txt     # グループ（g）・その他（o）から書き込み権限を削除
```

### 所有者の変更

```bash
# chown（change owner）コマンドで変更する
# 注意: 通常 sudo が必要
$ sudo chown takuya file.txt
$ sudo chown takuya:staff file.txt  # 所有者とグループを同時に変更
```

### スーパーユーザー（root）

`root` はすべての権限を持つ特別なユーザーです。

```bash
# sudo（superuser do）: 一時的に root 権限でコマンドを実行
$ sudo コマンド
```

**警告:** `sudo` を使うコマンドはシステム全体に影響します。コマンドの意味を完全に理解してから実行してください。特に `sudo rm -rf /` のようなコマンドはシステムを破壊します。絶対に実行しないでください。

## 💡 コラム: 「大したものにはならない」と言われた OS

1991年、フィンランドの21歳の大学生がネット掲示板にこう投稿しました。「フリーの OS を趣味で作っています。GNU みたいに大きくてプロフェッショナルなものにはなりません」。投稿者の名前はリーナス・トーバルズ。その「趣味の OS」が Linux です。

現在、Linux は世界のスーパーコンピュータ TOP500 の 100%、ほぼすべての Web サーバー、そして Android として数十億台のスマホで動いています。「大きくてプロフェッショナルなものにはならない」は、コンピュータ史上屈指の外れた予言になりました。

OS をビルの管理人に例えると: 部屋の割り当て(メモリ管理)、入居者の管理(プロセス管理)、各部屋の鍵(パーミッション)、そして「管理人室の窓口」(システムコール)。アプリは勝手に設備をいじれず、必ず窓口を通す — この秩序が、複数のプログラムの同時実行を可能にしています。

## まとめ

- OS はハードウェアとアプリの間の「管理者」。Linux はサーバーの主流
- プロセスは実行中のプログラム。PID で識別し、`ps aux` で確認できる
- ファイルシステムは `/` を起点とするツリー構造。パスで場所を指定する
- `~` はホームディレクトリ、`.` はカレント、`..` は親ディレクトリ
- パーミッションは「誰が（owner/group/others）」「何をできるか（r/w/x）」を定義する
- `chmod` でパーミッション変更、`sudo` で root 権限の操作ができる
