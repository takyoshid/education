## 1. クラウドとは

### 従来のオンプレミス（On-Premises）

```
自社サーバー室
├── サーバー機器（購入・保守）
├── ネットワーク機器（購入・保守）
├── 電源・冷却設備
└── データセンター契約
   → 初期費用が大きい
   → キャパシティの変更が難しい
   → ハードウェア障害の対応が必要
```

### クラウドコンピューティング

必要なときに必要なだけ、インターネット経由でコンピュータリソースを借りるサービスです。

**主な特徴**:
- **オンデマンド**: 必要なときにすぐ調達できる
- **従量課金**: 使った分だけ支払う
- **弾力性**: トラフィックに応じてスケールアップ/ダウンできる
- **可用性**: 世界中にデータセンターを持ち、冗長化されている

## 2. IaaS / PaaS / SaaS

クラウドサービスは「どこまでクラウドに任せるか」によって分類されます。

### サービスモデルの比較

```
オンプレ     IaaS         PaaS         SaaS
--------    --------     --------     --------
アプリ       アプリ        アプリ        [提供済み]
ランタイム   ランタイム    [提供済み]   [提供済み]
OS          OS           [提供済み]   [提供済み]
仮想化       [提供済み]   [提供済み]   [提供済み]
サーバー     [提供済み]   [提供済み]   [提供済み]
ネットワーク  [提供済み]   [提供済み]   [提供済み]

[提供済み] = クラウド側が管理
```

### IaaS（Infrastructure as a Service）

**インフラをクラウドで提供**するサービスです。
VM・ストレージ・ネットワークを貸し出し、OS 以上の管理はユーザーが行います。

例: **AWS EC2**、Google Compute Engine、Azure Virtual Machines

```
用途: OS からカスタマイズしたい、既存のシステムをそのまま移行したい
メリット: 柔軟性が高い
デメリット: OS・ミドルウェアの管理が必要
```

### PaaS（Platform as a Service）

**アプリケーションの実行基盤を提供**するサービスです。
コードをデプロイするだけで動く。OS・ランタイムの管理不要。

例: **AWS Elastic Beanstalk**、**Heroku**、**Render**、Google App Engine

```
用途: アプリ開発に集中したい、インフラ管理を減らしたい
メリット: インフラ管理が不要
デメリット: カスタマイズの自由度が低い
```

### SaaS（Software as a Service）

**完成したソフトウェアをクラウドで提供**するサービスです。
ユーザーはソフトウェアを使うだけ。

例: Gmail、Slack、GitHub、Salesforce、Notion

```
用途: ソフトウェアをそのまま利用したい
メリット: インストール・管理不要
デメリット: カスタマイズは限定的
```

## 3. AWS の主要サービス

### コンピューティング

| サービス | 説明 | 使用場面 |
|---------|------|---------|
| **EC2** (Elastic Compute Cloud) | 仮想サーバー（VM）| Web サーバー、API サーバー |
| **ECS** (Elastic Container Service) | コンテナオーケストレーション | Docker コンテナの実行・管理 |
| **EKS** (Elastic Kubernetes Service) | マネージド Kubernetes | 大規模コンテナ管理 |
| **Lambda** | サーバーレス関数実行 | イベント処理、API バックエンド |
| **Elastic Beanstalk** | PaaS（アプリをデプロイするだけ） | 手軽なアプリデプロイ |

### ストレージ

| サービス | 説明 | 使用場面 |
|---------|------|---------|
| **S3** (Simple Storage Service) | オブジェクトストレージ | 画像・動画・静的ファイルの保存 |
| **EBS** (Elastic Block Store) | EC2 用のブロックストレージ | OS ディスク、DB データ |
| **EFS** (Elastic File System) | マネージドファイルシステム | 複数 EC2 からの共有ストレージ |

### データベース

| サービス | 説明 | 使用場面 |
|---------|------|---------|
| **RDS** (Relational Database Service) | マネージド RDB（MySQL, PostgreSQL など） | アプリのデータベース |
| **DynamoDB** | マネージド NoSQL DB | 高速な Key-Value ストア |
| **ElastiCache** | マネージド Redis / Memcached | キャッシュ、セッション管理 |
| **Aurora** | RDS の高性能版（MySQL/PostgreSQL 互換） | 高可用性 DB |

### ネットワーク

| サービス | 説明 | 使用場面 |
|---------|------|---------|
| **VPC** (Virtual Private Cloud) | 仮想ネットワーク | リソースの隔離・ネットワーク設計 |
| **Route 53** | DNS サービス | ドメイン管理・ルーティング |
| **CloudFront** | CDN（コンテンツ配信ネットワーク） | 静的ファイルの高速配信 |
| **ELB** (Elastic Load Balancing) | ロードバランサー | トラフィックの分散 |
| **API Gateway** | API の管理・公開 | REST / WebSocket API |

### セキュリティ・管理

| サービス | 説明 | 使用場面 |
|---------|------|---------|
| **IAM** (Identity and Access Management) | 認証・認可 | ユーザー・ロールの権限管理 |
| **Secrets Manager** | シークレット管理 | DB パスワード、API キーの保存 |
| **CloudWatch** | モニタリング・ログ管理 | メトリクス収集・アラート |
| **CloudTrail** | API 操作の監査ログ | セキュリティ監査 |
| **WAF** | Web アプリケーションファイアウォール | SQL インジェクション対策など |

## 4. AWS の全体像（典型的な構成）

```
インターネット
     |
[Route 53]  ← DNS
     |
[CloudFront] ← CDN（静的ファイルをキャッシュ）
     |
[ELB: Application Load Balancer]
     |
     +--- [EC2 / ECS コンテナ (AZ-a)]
     +--- [EC2 / ECS コンテナ (AZ-b)]  ← 複数 AZ で冗長化
     |
     +--- [RDS（マスター, AZ-a）] ←→ [RDS（スタンバイ, AZ-b）]
     +--- [ElastiCache (Redis)]
     |
[S3]  ← 静的ファイル・バックアップ

[CloudWatch]  ← 全サービスのログ・メトリクス
[IAM]         ← 全リソースへのアクセス制御
```

**AZ（Availability Zone）**: 同一リージョン内の独立したデータセンター。
複数 AZ にリソースを置くことで、1つの DC が落ちても継続稼働できます。

## 5. AWS 無料枠（Free Tier）

### 12ヶ月無料（アカウント作成から1年間）

| サービス | 無料枠 |
|---------|--------|
| EC2 | t2.micro（または t3.micro）1台を月 750 時間 |
| S3 | 5 GB ストレージ、20,000 GET リクエスト |
| RDS | db.t2.micro（または db.t3.micro）1台を月 750 時間 |
| CloudFront | 1 TB データ転送/月 |

### 常に無料

| サービス | 無料枠 |
|---------|--------|
| Lambda | 100 万リクエスト/月、400,000 GB-秒 |
| DynamoDB | 25 GB ストレージ |
| CloudWatch | 基本モニタリング（5分間隔） |
| SNS | 100 万件の通知/月 |

### 費用を抑えるためのコツ

```
1. 使わない EC2・RDS は停止しておく（停止中は課金されない）
2. 必要なければ EIP（Elastic IP）を解放する
3. 課金アラートを設定しておく（$1 超えたら通知するなど）
4. Cost Explorer で毎週コストを確認する
5. 学習用なら EC2 t3.micro + RDS は数百円/月程度
```

## 6. IAM の基本（非常に重要）

### IAM とは

AWS リソースへのアクセスを制御する仕組みです。
「誰が」「何を」「どこに対して」できるかを定義します。

### 最小権限の原則（Principle of Least Privilege）

**必要最低限の権限だけを付与する**のが鉄則です。

```
悪い例: EC2 インスタンスに AdministratorAccess を付与
           → 万が一侵害されると全リソースが危険

良い例: EC2 インスタンスに必要な S3 バケットへの Read 権限のみ付与
```

### IAM の主要概念

```
IAM User    → 人間が使うアカウント（開発者、管理者など）
IAM Role    → サービスやアプリケーションが引き受けるアイデンティティ
              （EC2 インスタンスに Role を割り当てると、
               インスタンス内のアプリが AWS SDK を使える）
IAM Group   → 複数の User をまとめて管理
IAM Policy  → 権限を定義した JSON ドキュメント
```

### ポリシーの例

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject"
      ],
      "Resource": "arn:aws:s3:::my-bucket/*"
    }
  ]
}
```

## 7. ハンズオン: AWS 無料枠で EC2 を立ち上げる

### 手順概要

```
1. AWS アカウントを作成（クレジットカード必要、1年間無料枠あり）

2. IAM ユーザーを作成（root ユーザーは日常使いしない！）
   - IAM → Users → Create user
   - 管理者権限（AdministratorAccess）を付与
   - アクセスキーは作成しない（コンソール操作のみ）

3. 請求アラートを設定
   - Billing → Budgets → Create budget
   - 月 $5 を超えたらメール通知

4. EC2 インスタンスを作成
   - EC2 → Launch instance
   - AMI: Ubuntu 22.04 LTS（無料枠対象）
   - Instance type: t2.micro / t3.micro（無料枠対象）
   - Key pair: 新規作成（.pem ファイルをダウンロード）
   - Security group: SSH（22）と HTTP（80）を許可

5. SSH 接続
   chmod 400 ~/.ssh/my-key.pem
   ssh -i ~/.ssh/my-key.pem ubuntu@<パブリック IP>

6. 使い終わったら必ず Stop（課金を抑える）
```

### セキュリティグループ（Security Group）

AWS の仮想ファイアウォールです。

```
インバウンドルール（外→内）:
  - SSH (22)    : 自分の IP アドレスのみ許可（0.0.0.0/0 は危険）
  - HTTP (80)   : 0.0.0.0/0（全 IP から許可）
  - HTTPS (443) : 0.0.0.0/0（全 IP から許可）

アウトバウンドルール（内→外）:
  - All traffic : 0.0.0.0/0（通常はすべて許可）
```

## 💡 コラム: 自家発電をやめた日 — クラウドは電力会社である

20世紀初頭まで、工場は**自前の発電機**を持っていました。発電は工場経営の重要スキルだったのです。しかし電力網が発達すると、ほぼすべての工場が自家発電をやめました。理由は単純 — **電気は「使った分だけ払う」ほうが、安く、確実で、本業に集中できる**からです。今日「うちは自家発電にこだわる工場です」と聞いたら、よほど特殊な事情を想像するでしょう。

クラウドはこの転換のコンピュータ版です。「サーバーを買い、ラックに設置し、電源と空調を管理する」自家発電の時代から、「クレジットカード1枚で、使った分だけ払う」電力網の時代へ。AWS 自体、Amazon が自社の EC サイトを支えるために磨いた内部基盤を、2006年に外販し始めたのが起源です。

見落とされがちな側面も一つ: クラウドは**個人開発者への民主化**でもありました。かつて大企業しか持てなかった規模のインフラを、学生が数百円で数時間だけ借りられる。あなたがこの Phase でデプロイする練習アプリは、Netflix と同じ発電網につながっています。

## まとめ

| 概念 | 要点 |
|------|------|
| IaaS | VM を貸し出し。OS 以上の管理はユーザーが行う（EC2） |
| PaaS | アプリ実行基盤を提供。コードをデプロイするだけ（Elastic Beanstalk） |
| SaaS | 完成したソフトウェアを使うだけ（Gmail、Slack） |
| AWS 主要サービス | EC2、S3、RDS、VPC、IAM を最初に押さえる |
| 最小権限の原則 | IAM では必要最低限の権限だけ付与する |
| 無料枠 | t2.micro 1台なら月数百円程度で学習できる |
