# Lesson 02: AI コーディングアシスタントの使い方

## 学習目標

- 主要な AI コーディングアシスタントの特徴と位置づけを理解する
- 「補完」「チャット」「エージェント」という 3 つのモードの違いを理解し、場面に応じて使い分けられる
- 各ツールの得意・不得意を把握し、過度な依存を避けながら活用できる

---

## 1. 主要な AI コーディングアシスタント

現在、エンジニアが実務で使う AI コーディングアシスタントは主に以下があります。

### GitHub Copilot

Microsoft と GitHub が提供する AI コーディング支援ツールです。VS Code や JetBrains IDE などに組み込まれ、コードを書きながらリアルタイムで補完を提案します。OpenAI のモデルを基盤としており、GitHub 上のコードを大量に学習しています。

### Claude Code

Anthropic が提供する CLI (コマンドラインインターフェース) ベースの AI コーディングエージェントです。ターミナルから動作し、コードベース全体を読み込んで複数ファイルにまたがる作業を行えます。

### Cursor

AI 機能を前面に押し出したコードエディタです。VS Code をベースに、複数のモデルを選択してチャットや補完が行えます。

### その他

Gemini Code Assist (Google)、Amazon Q Developer など、各クラウドプロバイダーも独自のアシスタントを提供しています。

## 2. 3 つのモードを理解する

AI コーディングアシスタントは大きく 3 つのモードで利用できます。それぞれの特性を理解することが、適切な使い分けの前提です。

### モード 1: 補完 (Completion)

コードを書いているときに、続きをリアルタイムで提案するモードです。GitHub Copilot の主要機能がこれにあたります。

**どんなときに有効か**
- 定型的なコードを素早く書きたいとき (for ループ、if 文、関数の雛形など)
- 関数名や変数名から処理内容が明らかなとき
- テストケースの網羅的な列挙

**注意点**
- 補完は「あなたが書こうとしているコードを推測する」ものです。意図と異なる補完をそのまま採用すると、気づかないバグを生みます。
- 補完を受け入れる前に必ず一読してください。Tab キーを反射的に押す癖は危険です。

```python
# 補完の例: 関数名を書くと、中身が提案される
def calculate_discount(price, discount_rate):
    # AI がここを補完する
    # -> return price * (1 - discount_rate)
    # これは正しいか? discount_rate が 0.2 なら 20% 引き = 正しい
    # しかし discount_rate が 20 (%) なら間違い
    # 「意図」は自分だけが知っている
    pass
```

### モード 2: チャット (Chat)

エディタ内やターミナルで AI に質問したり、コードの説明・修正・生成を依頼するモードです。

**どんなときに有効か**
- 特定のコードについて説明を求めるとき
- バグの原因を一緒に調べたいとき
- 「この関数を〇〇するように変えてほしい」という具体的な依頼
- 設計のアイデア出し (最終判断は自分でする)

**注意点**
- チャットの結果はコードへの自動適用ではなく「提案」です。自分で内容を確認してから適用します。
- 質問が曖昧だと回答も曖昧になります。後述のプロンプト設計が重要です。

### モード 3: エージェント (Agent)

AI がコードベースを読み込み、複数のファイルにまたがる変更・調査・実行を自律的に行うモードです。Claude Code はこのモードを中心に設計されています。

**どんなときに有効か**
- 「このプロジェクトにログイン機能を追加して」のような、複数ファイルにまたがるタスク
- 「既存のコードベースを調査して設計を提案して」
- 反復的なリファクタリング作業

**注意点**
- エージェントは自律的にファイルを変更します。必ず Git で管理されたリポジトリで使ってください。変更を差分として確認できる状態にしておきます。
- エージェントが自信を持って行った変更でも、意図と異なることがあります。変更後は必ず動作確認とコードレビューを行います。
- 「何でもやってもらえる」という感覚が、自分でコードを書く機会を奪います。エージェントに頼む前に「自分ならどうするか」を考える習慣を持ちましょう。

## 3. 使い分けの判断基準

```
タスクの性質
    |
    +-- 短い・定型的 → 補完モード
    |      例: ループ、クラスの雛形、テスト関数の列挙
    |
    +-- 質問・調査・局所的な変更 → チャットモード
    |      例: 「この正規表現は何をしているか」「この関数をより効率的に」
    |
    +-- 複数ファイル・複雑な要件 → エージェントモード
           例: 「新しい API エンドポイントを追加する」
               「型エラーをすべて修正する」
```

## 4. 「使わないほうがいい」場面

AI コーディングアシスタントは万能ではありません。以下の場面では慎重になる必要があります。

### セキュリティに直接関わる実装

認証・認可・暗号化・SQL クエリ構築など、セキュリティに直接関わるコードは AI 生成をそのまま使わないことを強く推奨します。AI はセキュリティのベストプラクティスを知っていますが、あなたの具体的な要件や環境のリスクは知りません。

### 学習中の概念

「理解できていないが AI が書いてくれた」というコードを積み上げると、技術的負債だけでなく、あなた自身の理解の負債も積み上がります。学習中の概念は必ず自分で書き、AI には「答え合わせ」ではなく「理解の補助」として使ってください。

### 機密情報を含む文脈

API キー・パスワード・顧客データ・社内の機密コードなどを AI アシスタントに送ることは、その情報が学習データに使われる可能性があります (サービスによって規約が異なります)。業務での利用前に組織のポリシーを確認してください。

## 5. GitHub Copilot の基本的な使い方

実際の使い方の流れを理解しておきましょう。

```
1. VS Code に GitHub Copilot 拡張機能をインストール
2. GitHub アカウントでサインイン
3. コードを書き始めると、グレーアウトした補完候補が表示される
4. Tab キーで採用、Esc キーで却下
5. 補完を採用したら、必ず一読して意図に合っているか確認する
```

**インラインチャット**: `Ctrl+I` (Windows/Linux) または `Cmd+I` (Mac) でエディタ内でチャットが開きます。選択した範囲についての質問・変更依頼ができます。

## 6. Claude Code の基本的な使い方

Claude Code はターミナルから使います。

```bash
# インストール
npm install -g @anthropic-ai/claude-code

# プロジェクトディレクトリで起動
cd your-project
claude

# 起動後は会話形式でタスクを依頼する
# 例: "このプロジェクトの構造を説明してください"
# 例: "src/auth.py にある validate_token 関数のバグを見つけてください"
```

Claude Code はコードベースを読み込んで文脈を理解したうえで回答します。単純な質問より、コードベース全体に関連する作業で特に力を発揮します。

## 💡 コラム: 「プログラマー終了」と騒がれた日に、実際に終わったもの

2021年、GitHub Copilot が発表されたとき、世界中の掲示板が「プログラマーの仕事は終わった」という悲鳴で埋まりました。数年経った現在、答え合わせができます。**終わったのはプログラマーではなく、「タイピング」でした。** そして爆発的に需要が伸びたのは、AI の出力を評価できる能力 — つまりレビュー能力です。

AI コーディングアシスタントの正確な人物像は、こうです: 「**百科事典的な知識を持ち、超高速で、疲れを知らず、しかし自信満々に間違える新人**」。ペアプログラミングの相手として超優秀ですが、無監督で本番コードを書かせるには危険 — この距離感がすべてです。

歴史的な比較も役に立ちます。コンパイラが登場したとき、アセンブリ言語のプログラマーたちは「機械にコードを書かせるなんて」と抵抗しました。しかし勝ったのは、コンパイラを道具として使いこなし、より高い抽象度の問題に移った人たちです。AI アシスタントはその再演です。**道具と競争する人は負け、道具を使いこなす人が勝つ** — 産業革命以来、一度も例外のないパターンです。

## まとめ

- AI コーディングアシスタントには「補完」「チャット」「エージェント」の 3 つのモードがある
- モードはタスクの性質 (短い定型作業 / 質問・調査 / 複数ファイル) によって使い分ける
- 補完は Tab を反射的に押す癖が最も危険。必ず読んでから採用する
- エージェントモードは便利だが、Git 管理必須・変更後の確認必須
- セキュリティ・学習中の概念・機密情報には慎重に使う
