# Lesson 05: 学習における AI 活用

## 学習目標

- AI を学習に活用することで生じる「依存」と「深化」の違いを説明できる
- 答えを写すだけの使い方がなぜ有害かを具体的に理解する
- ソクラテス式 (対話型) のプロンプトを使って理解を深める方法を実践できる
- AI を学習の「答え合わせ機」ではなく「思考の壁打ち相手」として使える

---

## 1. 依存か、深化か

AI を学習に使う方法には 2 種類あります。

### 依存する使い方 (避けるべき)

```
問題が出る
-> AI に答えを求める
-> 答えをコピーする
-> 「わかった」と思う
-> 次の問題でまた同じことをする
-> 実力は育たない
```

この使い方をしていると、AI なしでは何もできない「AI 依存エンジニア」になります。面接・ホワイトボードコーディング・障害対応など、AI が使えない状況で完全に無力になります。

### 深化する使い方 (目指すべき)

```
問題が出る
-> まず自分で考える (時間を決めて)
-> 行き詰まったら AI に「ヒント」を求める
-> ヒントをもとに自分で実装する
-> AI に説明させて自分の理解と照合する
-> 「なぜそうなるのか」まで理解する
-> 類似問題を自力で解けるようになる
```

この使い方をしていると、AI は学習のスピードを上げる道具になります。

---

## 2. 「答えを写す」と何が起こるか

一見すると「答えを写して動かした」は進歩のように見えます。しかし実際には何が起きているかを考えてみましょう。

### 記憶の問題

人間の記憶は「自力で考えた経験」から作られます。苦労して解決したことは長く記憶に残りますが、コピーした答えはすぐ忘れます。

### 転用の問題

AI が書いたコードは「この問題のための答え」です。あなたが問題を理解していなければ、少し条件が変わったときに同じコードが使えないことに気づきません。

### 実力評価の問題

「AI と一緒なら解ける」と「自力で解ける」は、エンジニアとしての実力としてまったく異なります。しかし毎回 AI に頼っていると、自分の本当の実力がわからなくなります。

## 3. ソクラテス式プロンプト

ソクラテス式 (Socratic Method) とは、一方的に答えを教えるのではなく、問いかけを通じて相手が自分で答えを導き出す方法です。AI に対して「答えを教えてほしい」ではなく「考えるための問いかけをしてほしい」と依頼することで、深い理解が生まれます。

### ソクラテス式プロンプトの例

**悪い使い方:**
```
「フィボナッチ数列を Python で実装するコードを書いてください」
-> コードをコピーして終わり
```

**良い使い方:**
```
「フィボナッチ数列の実装を学びたいのですが、
答えを教えずに、私が自分で考えられるように
ヒントと問いかけをしてください。

まず: フィボナッチ数列とはどんなパターンを持ちますか?
それを実装する際にどんなアプローチが考えられますか?
(答えは言わずに、考え方の方向性だけ示してください)」
```

### 段階的な深化プロンプト

```
ステップ 1: 最初の問いかけ
「再帰 (recursion) とは何か、概念だけを教えてください。
コード例はまだいりません。」

ステップ 2: 自分なりに説明してみる
「私の理解では、再帰とは 〇〇 です。この理解は正しいですか?
間違っている部分があれば指摘してください。」

ステップ 3: 実装への誘導
「再帰でフィボナッチ数列を実装しようとしています。
まず、ベースケースは何になるか教えてください。
再帰ケースは自分で考えてみます。」

ステップ 4: 自分の実装を見せてレビューしてもらう
「こう書いてみました。動くと思いますが、
改善できる点があれば教えてください。

def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)」

ステップ 5: 理解を深める
「この実装の計算量はどのくらいですか?
大きな n に対して問題になりますか?」
```

## 4. 具体的なプロンプト例集

### コンセプトを理解するプロンプト

```
「[概念] について学んでいます。
以下の形式で説明してください:
1. 一言で言うと何か
2. なぜ存在するのか (どんな問題を解決するか)
3. コードなしの直感的なアナロジー (例え話)
4. 最も単純なコード例 (10 行以内)
5. この概念を誤用しやすい落とし穴 1 つ」
```

### 自分のコードをレビューしてもらうプロンプト

```
「以下は私が書いたコードです。
動作はしますが、改善できる部分があると思います。
以下の観点でレビューしてください:
1. バグや論理的な誤り
2. パフォーマンスの問題
3. 可読性・命名の改善点
4. Python のベストプラクティスに反している点

[コードを貼り付ける]

ただし、修正後のコードを書かないでください。
問題点の指摘と改善の方向性だけ教えてください。
自分で直してみます。」
```

### エラーを自力で解決するためのプロンプト

```
「以下のエラーが出ています。
答えを教えずに、原因を自分で突き止めるための
デバッグ手順を教えてください。

[エラーメッセージを貼り付ける]

私のスキルレベル: Python 基礎は理解している。
エラーメッセージの読み方が分からない。」
```

### 概念の理解を確認するプロンプト

```
「[概念] を学びました。理解できているか確認するために、
この概念についての理解テストを 3 問作ってください。
問題だけ出してください。答えはまだ教えないでください。
私が回答したら、採点と解説をお願いします。」
```

## 5. AI を「壁打ち相手」として使う

「壁打ち」とは、自分の考えを相手にぶつけることで思考を整理する対話の方法です。AI は優秀な壁打ち相手になります。

### 設計の壁打ち

```
「以下の設計を考えています。問題点・改善点・考慮漏れを指摘してください。
ただし代替案を提示する前に、まず私の設計の問題点を聞かせてください。

[設計の概要を書く]」
```

### 解法の壁打ち

```
「問題: [問題の説明]

私の解法候補:
1. 〇〇を使うアプローチ
2. 〇〇を使うアプローチ

それぞれのトレードオフを聞かせてください。
どちらが良いかは自分で判断したいので、最終的な推薦はいりません。」
```

## 6. 「AI なし」の時間を作る

意識的に AI を使わない時間・場面を作ることが、基礎力の維持に重要です。

### AI なしで練習する場面

- **LeetCode / AtCoder などのアルゴリズム問題**: まず自力で解く。行き詰まったら解説を読む (AI ではなく)。
- **写経**: 本やチュートリアルのコードを自分の手でタイプして動かす。コピーしない。
- **リファレンスを引く**: 関数の使い方を AI に聞く前に、公式ドキュメントを読む習慣を作る。

### なぜ公式ドキュメントを読む習慣が大切か

AI はドキュメントの内容を要約してくれますが、あなたがドキュメントを「読む力」を持っているかどうかは別問題です。新しいライブラリを使うとき、ドキュメントを自力で読んで理解できるエンジニアは強いです。AI に頼り切っていると、この力が育ちません。

---

## 7. 自己評価の仕方

AI を使って学習しているとき、「本当に理解しているか」を確認する方法があります。

### ファインマン・テクニック

ノーベル物理学賞を受賞したリチャード・ファインマンが実践した学習法です。

1. 学んだ概念を紙に書き出す
2. 初心者 (あるいは子ども) に説明するように書く
3. 詰まった箇所が「本当は理解できていない箇所」
4. 詰まった箇所だけ教材に戻って再学習する

```
実践例:
「クロージャを今日学びました。
AI に向けて、クロージャを知らない人に説明してみます。
間違っている箇所や理解が浅い箇所を指摘してください。

[自分の説明を書く]」
```

## 💡 コラム: 電卓は数学教育を滅ぼしたか

1970年代、安価な電卓が普及したとき、教育界で大論争が起きました。「子どもたちの計算力が滅びる」「暗算もできない世代が育つ」— 現在の「AI で学ぶと考える力が育たないのでは」という不安と、驚くほど同じ構図です。

数十年を経た教育界の答えは、興味深いバランスでした。**筆算の原理は今も教える**(位取りの概念がないと、電卓の答えのケタ違いに気づけない)。**しかし原理を理解した後の単純計算は電卓に任せ、人間はより高次の問題に時間を使う。** 電卓は計算力を滅ぼさず、数学教育の重心を「計算の実行」から「問題の定式化」へ動かしたのです。

AI と学習の関係も、同じ着地点に向かっています。ただし、一つだけ絶対の条件があります — **原理を学ぶ段階で、ショートカットしないこと**。基礎の練習問題を AI に解かせるのは、筋トレをロボットに代行させるようなものです。重りは持ち上がりますが、あなたの筋肉は1グラムも増えません。AI に「答え」ではなく「ヒント」や「解説」を求める — 使い方の設計次第で、AI は史上最強の家庭教師にも、成長を止める麻薬にもなります。

---

## まとめ

- AI は「答えを出す機械」ではなく「思考の補助」として使う
- 「答えを写す」と記憶・転用・実力評価のすべてで問題が起きる
- ソクラテス式プロンプトで「考える過程」に AI を巻き込む
- 「AI なし」の時間を意図的に作り、基礎力を維持する
- ファインマン・テクニックで「本当に理解しているか」を定期確認する

## 確認問題

1. 「AI に答えを出してもらって写した場合」と「自力で悩んでから AI にヒントをもらった場合」で、1 ヶ月後の理解の深さはどう違うと予想しますか? その理由を説明してください。

2. 以下のプロンプトを「ソクラテス式」に改善してください。
   「辞書 (dictionary) のソートのコードを書いてください。」

3. 「公式ドキュメントを読む習慣」と「AI に質問する習慣」はどちらが良いですか? それとも両立できますか? あなたの考えを述べてください。

4. ファインマン・テクニックを使って、Lesson 01 で学んだ「ハルシネーション」を知らない人に説明してみてください。書いた説明に「理解が浅い/間違っている」と思う箇所はありますか?

5. あなたが今学んでいる技術的概念を一つ選び、「概念を理解するプロンプト」を実際に作成してください (実行してみることを推奨します)。
