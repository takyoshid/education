# 演習 04: CLAUDE.md の作成と活用

## 目的

実際のプロジェクト (または学習用のプロジェクト) に CLAUDE.md を作成し、プロジェクト文脈を AI に効果的に伝える練習をします。

## 所要時間

45〜60 分

## 前提

- Lesson 03 を完了していること
- Claude Code または Claude.ai が使えること

---

## 課題 1: CLAUDE.md の作成

以下のいずれかを選んで、CLAUDE.md を作成してください。

### 選択肢 A: 自分のプロジェクトに作成する

今取り組んでいるプロジェクトがあれば、そのルートディレクトリに `CLAUDE.md` を作成してください。

### 選択肢 B: 想定プロジェクトに作成する

以下の想定プロジェクトを選んで `CLAUDE.md` を作成してください。

**プロジェクト 1: 読書記録 API**
- Python 3.12 + FastAPI
- SQLite (開発) / PostgreSQL (本番)
- 認証: JWT
- 機能: 本の登録・検索・読書ステータス管理

**プロジェクト 2: タスク管理 CLI ツール**
- Python 3.12
- SQLite でローカル保存
- コマンドライン: Click ライブラリ使用
- 機能: タスクの追加・完了・一覧・削除

**プロジェクト 3: 天気通知ボット**
- Python 3.12
- OpenWeatherMap API を使用
- LINE または Slack への通知
- GitHub Actions で毎朝 8 時に実行

---

## 必須セクション

作成する `CLAUDE.md` には以下をすべて含めてください。

```markdown
# [プロジェクト名]

## プロジェクト概要
[1〜3 行の説明]

## 技術スタック
[使用する言語・フレームワーク・ライブラリとバージョン]

## ディレクトリ構成
[ファイルツリー形式]

## コーディング規約
[守るべき規約を 3-5 項目]

## テスト
[テストの書き方・実行方法]

## よく使うコマンド
[開発でよく使うコマンドとその説明]

## 禁止事項・注意事項
[やってはいけないこと 2-3 項目]
```

---

## 課題 2: CLAUDE.md の効果を検証する

作成した `CLAUDE.md` を使って、以下の質問を AI に送ってみてください。

### CLAUDE.md なしで質問する

まず CLAUDE.md の内容を AI に渡さずに以下を質問します。

```
「このプロジェクトに新しいエンドポイントを追加する場合、
どのファイルを変更すればいいですか?」
```

### CLAUDE.md の内容を先に渡してから質問する

次に「以下は私のプロジェクトの CLAUDE.md です。[内容を貼り付け]」と送ってから同じ質問をします。

### 比較する

2 つの回答を比較して、以下を記録してください。

- CLAUDE.md なし: どんな回答が返ってきたか
- CLAUDE.md あり: どんな回答が返ってきたか
- 具体的にどこが違ったか

---

## 評価基準

以下の観点で自分の CLAUDE.md を評価してください。

1. **具体性**: 曖昧な表現がなく、実際のファイル名・コマンド・バージョンが書かれているか
2. **完結性**: これを読めば AI が適切に開発を支援できるか
3. **実用性**: 実際にこのプロジェクトで Claude Code を使いたいと思えるか
4. **簡潔さ**: 必要な情報だけが書かれているか (不必要に長くなっていないか)

---

## 提出物

1. 作成した `CLAUDE.md` の全文
2. CLAUDE.md なし/あり での AI の回答比較
3. 気づいたこと・改善点

---

## ヒント

- CLAUDE.md は一度書いたら終わりではありません。プロジェクトが進むにつれて更新します
- 「AI が毎回同じ間違いをする」ことがあれば、それを CLAUDE.md に「禁止事項」として追加する
- コマンドは実際に動くものを書いてください。動かないコマンドが書かれていると AI も混乱します
