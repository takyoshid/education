# Phase 5: データ構造とアルゴリズム

## 学習目標

このフェーズでは、世界で通用するソフトウェアエンジニアとして必須の「データ構造とアルゴリズム」を習得します。

- 計算量(Time/Space Complexity)を理解し、コードの効率を定量的に評価できる
- 主要なデータ構造(配列、スタック、キュー、連結リスト、ハッシュテーブル、木、グラフ)を自分で実装できる
- 代表的なアルゴリズム(探索、ソート、BFS/DFS)を実装・説明できる
- Two Pointers、Sliding Window、動的計画法などの問題解決パターンを使いこなせる
- コーディング面接(Coding Interview)で LeetCode Medium レベルの問題を解ける

---

## 🌟 旅の始まりに: アルゴリズムがなければ、人類はブラックホールを見られなかった

2019年4月、人類は史上初めて**ブラックホールの姿**を見ました。あのオレンジ色のリングの画像です。しかし、あの「写真」はシャッターを押して撮れたものではありません。

ブラックホールを直接撮影するには「地球サイズの望遠鏡」が必要でした。物理的に不可能です。そこで研究チームは、世界中8ヶ所の電波望遠鏡を同期させて観測し、**地球サイズの望遠鏡が捉えたはずの、ごく一部の断片データ**を集めました。歯抜けだらけのデータから正しい画像を復元する — それを可能にしたのがアルゴリズムです。当時20代の研究者ケイティ・バウマンらが開発に貢献した画像復元アルゴリズムが、断片から「唯一もっともらしい像」を導き出しました。画像が現れた瞬間、両手で口を覆って目を輝かせる彼女の写真は世界中に拡散しました(彼女自身は「これは約200人のチームの成果」と強調しています)。

アルゴリズムとは、計算の手際の話にとどまりません。**人類が見えないものを見るためのレンズ**です。この Phase で学ぶ一つひとつの技法は、そのレンズの磨き方です。

## 修了条件チェックリスト

以下をすべて満たしたとき、Phase 5 修了とみなします。

### 知識・理解

- [ ] Big-O 記法で O(1)、O(log n)、O(n)、O(n log n)、O(n^2) の違いを口頭で説明できる
- [ ] 任意のコードを見て、おおよその時間計算量と空間計算量を答えられる
- [ ] 各データ構造の代表的な操作(挿入・削除・検索)の計算量を答えられる
- [ ] 安定ソートと不安定ソートの違いを説明できる

### 実装

- [ ] 連結リスト(単方向)を Python で一から実装できる
- [ ] スタックとキューをリストと連結リストの両方で実装できる
- [ ] ハッシュテーブルをチェイン法(Chaining)で実装できる
- [ ] 二分探索木(BST)の挿入・検索・中順走査を実装できる
- [ ] マージソートとクイックソートを再帰で実装できる
- [ ] BFS と DFS を隣接リスト表現のグラフで実装できる

### 問題解決

- [ ] LeetCode Easy を 10 問以上解いた
- [ ] LeetCode Medium を 5 問以上解いた
- [ ] Two Pointers パターンの問題を 3 問解いた
- [ ] Sliding Window パターンの問題を 2 問解いた
- [ ] 動的計画法の基本問題(フィボナッチ、コイン問題)をメモ化で解いた

### プロジェクト

- [ ] project/ の自作データ構造ライブラリが全テストを通過する
- [ ] benchmark.py を実行して各データ構造の性能差を確認・説明できる
- [ ] [Phase 5 実技試験](assessment/)に合格した

## 学習の進め方

通常課題とプロジェクトの後に、[Phase 5 実技試験](assessment/)を受験してください。アルゴリズム名の暗記ではなく、未知の依存関係問題をモデル化し、正しさ・決定性・計算量・大規模入力を説明できるかを評価します。

1. **レッスンを読む** - lessons/ のファイルを順番に読む(飛ばし読み禁止)
2. **手でコードを書く** - コピペ禁止。必ずキーボードで打ち込む
3. **演習を解く** - exercises/ の問題を解いてから solutions/ を見る
4. **繰り返す** - 解けなかった問題は 3 日後に再挑戦する

> コーディング面接(Coding Interview)は英語圏企業への就職・転職に必須です。
> 各レッスンで英語の技術用語を必ず覚えてください。

## ⚠️ この Phase だけでは面接の演習量が足りません

このフェーズの演習は、**アルゴリズムの概念を理解するには十分**ですが、**コーディング面接の対策としては問題数が足りません。**

グローバル企業の面接を突破する水準としては、一般に **LeetCode の Medium を中心に 150〜300 問**程度が実質的な要件とされています。この教材にその量は含まれていません(未整備であることを明記しておきます)。

**推奨する進め方**:

```
このフェーズでパターンを理解する
  (二分探索 / two pointers / スライディングウィンドウ / DFS・BFS / 動的計画法)
        ↓
外部プラットフォームで量を積む(このフェーズと並行、または直後から)
        ↓
英語トラック Lesson 07 で「英語で考えながら解く」練習をする
```

順序が重要です。パターンを理解する前に量から入ると、**解法の暗記**になります。暗記した解法は、少しひねられた初見問題で通用しません。

| リソース | 使い方 |
|---|---|
| [NeetCode 150](https://neetcode.io/) | **最初はこれを推奨。**頻出パターンを 150 問に絞り、取り組む順序が設計されている |
| [LeetCode](https://leetcode.com/) | 問題数が最多。企業別の出題傾向も確認できる |
| Blind 75 | 時間が無い場合の最小セット |

1 日 1〜2 問を、Phase 5 開始から Phase 12 までの期間で続ければ、自然に 200 問を超えます。**一気にやろうとせず、毎日に分散してください。**
