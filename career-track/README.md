# キャリアと市場

この教材の中で、**特定の時代・特定の国の労働市場に依存する部分**をここにまとめてあります。

## なぜ分けてあるのか

理由は 2 つあります。

### 1. 最も早く古くなるから

給与の相場、求められるスキル、面接の形式、有名な企業の名前。これらは 5 年で変わり、20 年で原形をとどめません。

一方、この教材の他の部分 — 計算の仕組み、データ構造、並行処理、設計判断、学び方 — は数十年単位で変わりません。**寿命の違うものを混ぜておくと、短い方に引きずられて全体が古びます。**

### 2. 読む必要がない人がいるから

この教材は、転職を目指す社会人だけのものではありません。**技術そのものを学びたい人、まだ働く年齢ではない人**が読むこともあります。

そういう読者にとって、年収の話や面接対策は不要です。不要なだけでなく、**学習の動機を「お金」に置き換えてしまう**という害があります。機械がどう動くかを知る楽しさは、それ自体で十分な動機です。

**この層は、丸ごと後回しにできます。** 必要になったときに読んでください。

## 数字が変わっても変わらないこと

この層にも、腐らない部分があります。**そこだけは覚える価値があります。**

### 給与データの読み方

数字そのものより、**読み方**のほうが長持ちします。

| 確認すること | なぜ |
|---|---|
| 平均値か中央値か | 「平均年収 600 万円」は、200 万円の人と 1,000 万円の人がいても成り立つ |
| 範囲はどれだけ広いか | 中央値だけでは、自分がどこに入るか分からない |
| サンプル数は十分か | 数十件のデータは参考程度にしかならない |
| 地域は絞られているか | 同じ国でも都市によって倍近く違うことがある |
| 経験年数が混ざっていないか | 未経験と 10 年目を平均した数字に意味はない |
| いつのデータか | 3 年前の数字は、もう現在の数字ではない |

**この 6 つは、統計を読むときの一般的な作法**でもあります。給与に限らず使えます。

### 待遇は給与だけではない

数字が比較しやすいので、給与だけを見てしまいがちです。しかし実際に生活を左右するのは次の合計です。

- 現金の給与
- 賞与・株式など、後から確定する報酬
- 社会保険・年金・医療
- 働く場所と時間の自由度
- 学習にかけられる時間
- **誰と働くか**

最後の項目は数値化できませんが、**成長速度に最も効きます。**技術力が伸びる環境と伸びない環境の差は、数年で年収の差を上回ります。

### 2 つの道がある

エンジニアのキャリアは、伝統的に 2 方向あります。

- **技術的専門家(Individual Contributor)** — 技術で深さと影響力を出す
- **エンジニアリングマネージャー** — 人と組織で成果を出す

**どちらが上でもありません。**また、一度選んだら戻れないものでもありません。行き来する人は普通にいます。

この 2 分法は 1960 年代から存在し、名前を変えながら今も続いています。おそらく今後も続きます。

### 等級の違いは「扱える曖昧さ」の量

ジュニア・ミドル・シニアの違いは、知識の量ではありません。**どれだけ曖昧な状態から仕事を進められるか**です。

| 段階 | 与えられるもの | 求められること |
|---|---|---|
| ジュニア | 明確なタスク | 正しく実装し、質問できる |
| ミドル | 課題 | 設計を決め、自力で完成させる |
| シニア | 曖昧な問題 | 何を作るべきかから決め、他人を動かす |

この定義は会社が変わってもほぼ同じで、**肩書きより実態を測る物差し**になります。

## コーディング面接の演習量

[README の「既知の未整備領域」](../README.md#-既知の未整備領域)にあるとおり、この教材には面接対策としての**問題数**が足りていません。Phase 5 と並行して、外部で量を積む必要があります。

### 変わらないこと

- **理解が先、量は後。** Phase 5 のパターン(二分探索、two pointers、スライディングウィンドウ、DFS/BFS、動的計画法)を理解してから量に入る。逆にすると解法の暗記になり、少し形を変えられただけで解けなくなる
- **解けた問題こそ振り返る。** 解けなかった問題より、「解けたが時間がかかった」問題のほうが伸びしろがある
- **時間を計る。** 面接には制限時間がある。時間を計らない練習は、本番の練習になっていない
- **声に出して説明しながら解く。** 面接で評価されるのは答えだけでなく、考える過程が説明できるかどうか

### 変わること

必要な問題数、定番のプラットフォーム、出題の傾向。**ここは自分で最新を調べてください。**

現時点(2026年)では、Medium 難度を中心に 150〜300 問程度が一つの目安とされ、頻出パターンを絞った学習リストが複数公開されています。「コーディング面接 頻出問題 リスト」で検索すれば、現在主流のものが見つかります。

**この数字を鵜呑みにしないでください。**目標は問題数ではなく、初見の問題に対して考え方を組み立てられることです。

## この層を更新するとき

数字や事例が古びたら、**この層の中だけを直してください。**他の Phase には手を入れる必要がありません。それがこの層を分けてある理由です。

更新するときは、**具体的な数字を書き写さないほうが長持ちします。**「どこで、どう調べるか」を書いておけば、読む人が自分で最新を得られます。書き写した数字は必ず古くなり、**古い数字は無いより悪い**からです。読んだ人が信じてしまうためです。
