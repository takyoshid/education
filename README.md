# 世界で通用するソフトウェアエンジニアへの道

完全初学者が、世界のどこでも通用するソフトウェアエンジニアになるための体系的教材。

## 🌟 旅の始まりに: 180年前、最初のプログラマーは詩人の娘だった

1843年、コンピュータが物理的に存在するより100年も前に、世界初のプログラムを発表した人物がいます。詩人バイロンの娘、**エイダ・ラブレス**です。彼女はチャールズ・バベッジの「解析機関」(歯車式の計算機械の設計)について論文の注釈を書き、その中で機械にベルヌーイ数を計算させる手順 — 史上初の公開されたプログラム — を記述しました。

彼女の言葉は、機械の本質を誰よりも早く見抜いていました。

> 「解析機関は、ジャカード織機が花や葉を織り上げるのとまったく同じように、**代数のパターンを織り上げる**。」

さらに彼女は「この機械はいつか、精緻で科学的な音楽を作曲するかもしれない」とまで予言しています。存在しない機械の可能性を、数学と想像力だけで見通した — 彼女は自分の方法を「**詩的科学(poetical science)**」と呼びました。

これからあなたが始める学習は、この180年続く人類の物語の続きです。ようこそ。

## この教材の設計思想

1. **手を動かして学ぶ** — 各Phaseに演習・模範解答・実技試験・総仕上げプロジェクトがある。読むだけでは修了できない
2. **なぜ動くかを理解する** — 暗記ではなく原理から。CS基礎を省略しない
3. **世界基準** — 技術用語は英語併記。英語ドキュメントを読み、英語で発信できる力を育てる
4. **プロの現場を再現** — Git、コードレビュー、テスト、設計を初期から習慣化する
5. **AI時代対応** — AIツールを使いこなしつつ、AIに依存しない基礎力を築く

## 「修了」の定義

この教材では、読了や自己申告だけを修了としません。通常演習に加えて、初見課題、口頭説明、実行ログ、第三者レビューによって到達度を確認します。

- [客観的到達度評価ガイド](assessment/) — AI利用可・不可の評価、Phase別ゲート、証拠の残し方
- [Phase横断プロジェクト](longitudinal-project/) — Phase 2から9まで同じプロダクトを変更・運用し続ける実務課題

各Phaseのチェックリストは学習範囲の確認、上記の評価ゲートは能力の確認です。両方を満たして修了とします。

### なぜ番号順ではないのか

Phase 12(並行処理)と Phase 13(分散システム)は、教材の拡充時に**後から追加**したため、番号が末尾に付いています。しかし内容の前提から、学習順は次の位置が適切です。

| Phase | 学習順での位置 | 理由 |
|---|---|---|
| [12](phase12-concurrency-reliability/) 並行処理 | **Phase 6 の直後** | API と DB を書けるようになった直後が最適。Phase 7 の設計より前に「壊れ方」を知る |
| [13](phase13-distributed-systems/) 分散システム | **Phase 8 の直後** | インフラを触った後、システム設計面接(Phase 10)より前に必要 |

Phase 10(英語)と Phase 11(AI活用)を最後に置いてはいけません。特に Phase 11 は、基礎力の形成期に AI へ答えを出させると「動くが説明できない」状態が固定されます。**Phase 2 を終えたら、まず [Lesson 01・02・05](phase11-ai-era/) を読んでください。**

## 学習の進め方

1. 上の「本流」の表を**学習順の列に従って**進める(Phase 番号順ではない)
2. **Phase 2 を終えたら、上の「並走」の4つを同時に始める** — Git(Phase 4)、英語(Phase 10)、AI活用(Phase 11)、[Phase横断プロジェクト](longitudinal-project/)
3. 各レッスンの演習を解いてから解答を見る
4. Phase 末のチェックリストに加え、[客観的到達度評価](assessment/)のPhaseゲートを満たしてから次へ進む
5. わからないことは 15 分自力で調べ、それでも解けなければ質問する(質問の仕方も Phase 0 で学ぶ)

推奨する学習順:

```
Phase 0 → 1 → 2 ─┬─────────────────────────────────────────────▶ (以降ずっと並走)
                 │   Phase 4 Git / Phase 10 英語 / Phase 11 AI活用 / 横断プロジェクト
                 │
                 └─ Phase 3 → 5 → 6 → 12 → 7 → 8 → 13 → 9
```

## ⚠️ 既知の未整備領域

この教材にも、まだ十分に整備できていない領域があります。**隠さず書いておきます。該当する時期には外部リソースで補ってください。**

### 1. コーディング面接の演習量(未着手)

Phase 3 の演習は**概念の理解には十分**ですが、**面接対策としての問題数が足りません。**

グローバル企業のコーディング面接を突破する水準としては、一般に **LeetCode の Medium を中心に 150〜300 問**程度を解くことが実質的な要件とされています。この教材にはその量がなく、到達量の目安や外部演習への導線も用意できていません。

**当面の補い方**: Phase 3 と並行して、外部の演習プラットフォームで量を積んでください。定番は次のとおりです。

| リソース | 内容 |
|---|---|
| [NeetCode 150](https://neetcode.io/) | 頻出パターンを 150 問に絞ったリスト。取り組む順序が設計されている |
| [LeetCode](https://leetcode.com/) | 問題数が最多。企業別の出題傾向も見られる |
| [Blind 75](https://www.teamblind.com/post/New-Year-Gift---Curated-List-of-Top-75-LeetCode-Questions-to-Save-Your-Time-OaM1orEU) | 最小限に絞りたい場合の 75 問 |

Phase 3 で学ぶパターン(二分探索、two pointers、スライディングウィンドウ、DFS/BFS、動的計画法)を**先に理解してから**量を積むのが効率的です。順序を逆にすると、解法の暗記になります。

### 2. 英語アウトプットの並走の仕組み(未整備)

やること自体は [Phase 10 の「推奨学習ペース」](phase10-global-career/#推奨学習ペース)に定義されています(毎朝10分の記事購読、コミットメッセージを英語で書く、週1回の模擬面接など)。内容は妥当です。

**未整備なのは、それを Phase 2 から実行させる仕組みのほうです。**

- Phase 2 を学んでいる学習者には、**Phase 10 の README を開く理由がありません**
- 各 Phase のチェックリストに、英語の継続を確認する項目が**ありません**
- [客観的評価ガイド](assessment/)の Phase ゲートに、英語の証拠提出が**Phase 10 まで登場しません**

結果として「Phase 2 から並走」は方針として書かれているだけで、**続かなくても誰も気づかない**状態です。語学は最後にまとめて習得できないため、ここが空いていると Phase 10 で詰みます。

**当面の補い方**: [Phase 10 の推奨学習ペース](phase10-global-career/#推奨学習ペース)を**今すぐ開いて**、次の 2 つだけでも Phase 2 の時点から始めてください。

1. **コミットメッセージと PR の説明をすべて英語で書く**(Phase 4 開始時から。追加コストがほぼゼロで、毎日続く)
2. **英語の技術記事を週 1 本読み、3 行で要約して記録する**(記録を残すことが重要)

そして各 Phase の証拠フォルダ `evidence/phase-N/` に `english-log.md` を自分で追加し、継続の記録を残してください。仕組みが無いなら、自分で作るのが最短です。

重要なのは分量ではなく**毎週続くこと**です。週 15 分でも、18 か月続けば別人になります。
