# Phase 3: Git / GitHub と開発ツール

## 学習目標

このフェーズでは、プロのソフトウェアエンジニアが日常的に使うバージョン管理ツール「Git」と、チーム開発プラットフォーム「GitHub」を習得します。単なるコマンド暗記ではなく、Git の内部モデルを理解することで、どんな状況でも自分で判断して操作できる力を身につけます。

フェーズ終了時には以下のことができるようになります。

- Git の内部構造(スナップショット、blob / tree / commit オブジェクト)を説明できる
- init から始めてコミット履歴を積み上げ、ブランチを切ってマージできる
- コンフリクト(競合)を自力で解決できる
- GitHub 上でリモートリポジトリを管理し、Pull Request を作成・レビューできる
- GitHub Flow に従ったチーム開発フローを一人でシミュレーションできる
- 誤操作をしたときに restore / reset / revert / stash / reflog で復旧できる
- .gitignore、README、Markdown、ライセンスなど実務的な周辺知識を使いこなせる
- VS Code のショートカット・マルチカーソル・デバッガを活用できる

## 🌟 旅の始まりに: 社長がコードを読んだ — 岩田聡の伝説

任天堂の社長だった岩田聡は、こんな言葉を残しています。

> 「名刺の上では、私は社長です。頭の中では、ゲーム開発者です。**しかし心の中では、私はゲーマーです。**」

彼が HAL 研究所の社長だった頃の伝説があります。開発が4年間も難航していたゲーム『MOTHER2』を見て、彼はこう言いました。「**今あるものを活かして直すなら2年かかります。イチから作り直していいなら、半年でやります**」— そして本当に、開発ツールから作り直して完成させました。『ポケットモンスター 金・銀』では、彼が書いた圧縮ツールで容量に余裕が生まれ、**前作の舞台カントー地方を丸ごとおまけとして収録**できたという逸話も有名です。仕様書のない『ポケモン』の対戦プログラムをソースコードだけ読んで別機種に移植した、という話まであります。

彼を伝説にしたのは肩書きではなく、**コードを自在に読み、道具を自在に作る力**でした。Phase 3 で学ぶ Git やエディタは、まさにその「読む力・道具の力」を鍛える章です。道具に習熟した人は、プロジェクトを救えます。

## Phase 0 で学び、Phase 2 から常用する Git 最小セット

Phase 0 の環境構築演習で次の操作を練習済みです。Phase 2 の各演習・プロジェクトでは、詳細を学ぶ前でもこの最小セットを実行してください。

```bash
git init
git status
git add <変更したファイル>
git commit -m "feat: describe the change"
git log --oneline
```

- 1つの意味ある変更を1コミットにする
- 秘密情報や仮想環境をコミットしない
- 動作確認してからコミットする
- Phase 3開始時に、それまでの履歴を教材として読み返す

## 修了条件チェックリスト

以下をすべて達成したらPhase 3修了です。

### Git 基礎

- [ ] `git init` でリポジトリを作成し、ファイルをコミットできる
- [ ] `git status`, `git log`, `git diff` の出力を読み解ける
- [ ] ステージングエリアの役割を説明できる
- [ ] blob / tree / commit オブジェクトの関係を図で説明できる

### ブランチとマージ

- [ ] `git branch`, `git checkout`, `git switch` でブランチを作成・切り替えできる
- [ ] `git merge` でブランチをマージできる
- [ ] コンフリクトが発生したとき、マーカーを読んで手動解決できる
- [ ] fast-forward マージと 3-way マージの違いを説明できる

### GitHub

- [ ] GitHub にリモートリポジトリを作成し、`git push` できる
- [ ] `git pull` と `git fetch` の違いを説明できる
- [ ] Pull Request を作成し、コメントに対応してコードを修正できる
- [ ] Issue をリンクした PR を作成できる

### チーム開発フロー

- [ ] GitHub Flow の手順を自分の言葉で説明できる
- [ ] Conventional Commits の形式でコミットメッセージを書ける
- [ ] コードレビューで建設的なコメントを書ける

### やり直しと救出

- [ ] `git restore` でワーキングディレクトリの変更を戻せる
- [ ] `git reset --soft`, `--mixed`, `--hard` の違いを説明できる
- [ ] `git revert` で安全にコミットを取り消せる
- [ ] `git stash` で作業を一時退避できる
- [ ] `git reflog` で失ったコミットを復元できる

### 実務ツール

- [ ] .gitignore を適切に設定できる
- [ ] Markdown でプロジェクトの README を書ける
- [ ] MIT ライセンスと Apache 2.0 の違いを説明できる

### VS Code

- [ ] よく使うショートカット 10 個以上を使いこなせる
- [ ] マルチカーソルで複数行を同時編集できる
- [ ] デバッガでブレークポイントを設定し、変数の値を確認できる

### 総仕上げ

- [ ] 総仕上げプロジェクト(`project/team-sim-project.md`)を完走できる
- [ ] [Phase 3 実技試験](assessment/)に合格し、第三者レビューを受けた

## 学習の進め方

1. レッスンを読み、コマンドを**必ず手元で実行**してください。読むだけでは身につきません。
2. 各レッスン末尾の「確認問題」に答え、自分の理解を確認してください。
3. 演習(`exercises/`)に取り組み、詰まったら解説付き模範解答(`exercises/solutions/`)を参照してください。
4. すべてのレッスンと演習が終わったら、総仕上げプロジェクトに挑戦してください。
5. 最後に[Phase 3 実技試験](assessment/)でコンフリクト解消、PR、レビュー対応、復旧を実践してください。
