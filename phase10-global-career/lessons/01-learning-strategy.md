# Lesson 01: エンジニア英語の学習戦略

## はじめに

「英語が苦手だから海外では働けない」と思っている日本人エンジニアは多いです。しかし実際には、英語が完璧でなくても世界で通用するエンジニアはたくさんいます。必要なのは「完璧な英語」ではなく、「技術コミュニケーションに特化した英語」です。

このレッスンでは、エンジニアとして英語を最短で実用レベルに引き上げるための戦略を学びます。

---

## 1. エンジニア英語の特性を理解する

一般的な英語学習と、エンジニア英語学習は根本的に異なります。

### 一般英語 vs エンジニア英語

| 項目 | 一般英語 | エンジニア英語 |
|------|---------|-------------|
| 語彙 | 日常会話・文学・ニュース | 技術用語・略語・スラング |
| 文体 | 感情表現・比喩が多い | 簡潔・正確・命令形が多い |
| 頻出シーン | 旅行・買い物・雑談 | PR レビュー・Issue 報告・設計議論 |
| 必要な文法 | 広範囲 | 現在形・受動態・条件文が中心 |

エンジニア英語の特徴は「シンプルさ」です。ネイティブエンジニアも、技術コミュニケーションでは短く明確な文を好みます。文学的な表現や凝った文法は不要です。

### エンジニア英語の現実

世界のエンジニアの多くは英語を第二言語として話しています。インド、東ヨーロッパ、東南アジア、南米のエンジニアが英語で協業しているとき、全員が完璧な発音や文法を持っているわけではありません。重要なのは「意図が伝わるか」です。

---

## 2. 4技能の優先順位

英語には「読む・書く・聞く・話す」の4技能があります。エンジニアにとっての優先順位は以下の通りです。

### 優先順位 1: リーディング(読む)

最も即効性が高く、最初に投資すべき技能です。

理由:
- 公式ドキュメント、GitHub Issues、Stack Overflow、技術書は全て英語が原点
- 翻訳待ちや機械翻訳に頼っていると情報が1〜2年遅れる
- 読めるようになると学習速度が飛躍的に上がる

目標: 公式ドキュメントを辞書なしで読み進められること。100% 理解できなくていい。80% 理解で問題ない。

### 優先順位 2: ライティング(書く)

毎日使う実践的な技能です。

理由:
- コミットメッセージ、PR 説明、Issue 報告は毎日書く
- 非同期コミュニケーションが中心のリモートチームでは、書く力が特に重要
- 書くことで読む力も伸びる

目標: 文法が完璧でなくても意図が正確に伝わる文を書けること。

### 優先順位 3: リスニング(聞く)

スタンドアップや会議で必要になりますが、完璧さより「慣れ」が重要です。

理由:
- アクセントの多様性に慣れることが中心
- リーディングと語彙が伸びると自然と伸びる

目標: 標準的な速度の英語技術会議で、大意を掴めること。

### 優先順位 4: スピーキング(話す)

最も練習時間がかかりますが、一番恐れすぎている技能でもあります。

理由:
- 多くのリモートチームでは、テキストでのコミュニケーションが主流
- 話すよりもコードで貢献する機会の方が多い
- 「流暢さ」より「明確さ」が求められる

目標: 自分の考えを、ゆっくりでもいいので英語で説明できること。

## 3. 毎日の学習ルーチン

英語は「短期集中」より「毎日継続」が圧倒的に効果的です。1日2時間を週3回より、1日30分を毎日続ける方が定着します。

### 推奨ルーチン(最小版: 1日30分)

**朝 10 分: インプット**
- 技術記事を 1 本読む
- 推奨ソース: DEV.to, Medium (Engineering), Hacker News, GitHub Trending

**作業中: アウトプット統合**
- コミットメッセージを英語で書く
- 変数名・関数名・コメントを英語にする
- エラーメッセージを英語で Google 検索する

**夜 20 分: スキルビルド**
- レッスンを読む(週 2 回)
- 英語のポッドキャストを聴く(週 3 回)
- 面接練習(週 1 回)

### 推奨ルーチン(標準版: 1日1時間)

| 時間 | 内容 |
|------|------|
| 15 分 | 英語の技術記事精読(わからない単語メモ) |
| 15 分 | 英語ライティング練習(日記 or PR の模擬説明) |
| 20 分 | リスニング(ポッドキャスト・YouTube) |
| 10 分 | 単語・フレーズの復習 |

## 4. 教材の選び方

### リーディング教材

**無料で最高品質のもの:**
- MDN Web Docs (https://developer.mozilla.org)
- AWS Documentation
- React / Vue / Next.js 公式ドキュメント
- GitHub の人気 OSS リポジトリの Issues と PR

**技術記事:**
- DEV.to — 実用的な記事が多い、レベル幅広
- The Morning Paper (Adrian Colyer) — 論文解説、上級者向け
- Hacker News — リンク集として使う

### リスニング教材

**ポッドキャスト(無料):**
- Syntax.fm — フロントエンド、会話が自然
- Software Engineering Daily — 毎日更新、多様なトピック
- CoRecursive — エンジニアのストーリー、聞き取りやすい
- The Changelog — OSS・キャリア

**YouTube:**
- Fireship — 短くテンポよい、エンジニアスラングが学べる
- Theo (t3.gg) — リアルな開発者トーク
- GOTO Conferences — 本格的な技術講演

### スピーキング練習

**無料ツール:**
- Pramp (https://www.pramp.com) — エンジニア向け模擬面接、無料
- interviewing.io — コーディング面接の練習
- Discord / Reddit の英語コミュニティ

**有料だが効果的:**
- iTalki — ネイティブまたは英語話者との 1on1 レッスン
- Speeko — スピーキング専用アプリ

### 単語・文法

**避けるべきもの:**
- 一般英会話のアプリ(Duolingo、スタディサプリ英会話など)をメインにすること
  - エンジニア英語と乖離が大きい

**推奨:**
- Anki + 自分で作った技術用語デッキ
- 読んでいて出会った単語をその文脈のまま保存する

## 5. 効果を最大化するマインドセット

### 完璧主義を捨てる

「完璧な英語を書いてから送ろう」と思うと何も送れなくなります。ネイティブエンジニアも typo をするし、文法ミスをします。大切なのは「伝わること」です。

### 量をこなす

最初の 3 ヶ月は、意味よりも量です。毎日英語で何かを書く。毎日英語で何かを読む。質は後からついてきます。

### 日本語を経由しない

英語を読むとき、頭の中で日本語に翻訳するのをやめましょう。「なんとなくこういう意味だな」という感覚でどんどん読み進めることが速読と英語脳の構築につながります。

### エラーを恐れない

英語の間違いを指摘してくれる同僚は、あなたの成長を助けてくれています。感謝して、次に活かしましょう。ネイティブでも文章を見直して推敲します。

---

## まとめ

- エンジニア英語はシンプルさが本質。完璧な文法より明確な意図伝達が優先
- 4技能の優先順位は読む > 書く > 聞く > 話す
- 毎日30分の継続が最重要。短期集中より長期継続
- 教材は本物の技術コンテンツ(ドキュメント、OSS、技術ポッドキャスト)を使う
- 完璧主義を捨てて量をこなす
