# Lesson 10: オファー交渉と入社後の立ち上がり

## はじめに

面接を通過してオファーを受けたとき、多くの日本人エンジニアは最初の数字を受け入れてしまいます。しかし統計的に、交渉を行うことでオファー金額は平均 10〜20% 上がります。交渉は「図々しい行為」ではなく、採用プロセスにおいて期待されるビジネス慣行です。

---

## 1. 交渉の基本原則

### 原則 1: 必ず交渉する

どんな状況でも一度は交渉を試みましょう。断られたとしても、オファーが取り消されることはありません(誠実に交渉している限り)。

### 原則 2: 書面で確認されるまで口頭のオファーに決断しない

"I'm very excited about this opportunity. Could you send the offer letter in writing?"
(この機会にとても興奮しています。オファーレターを書面で送っていただけますか?)

### 原則 3: 総合報酬(Total Compensation)で考える

給与(Base Salary)だけで比較しないでください。

```
Total Compensation = Base Salary + Signing Bonus + Equity (RSU/Options) + Benefits

Benefits の例:
- Health insurance (健康保険)
- 401k match (米国の退職年金マッチ)
- Remote work stipend (リモートワーク手当)
- Learning & development budget (学習予算)
- Unlimited PTO (無制限有給)
- Equity refresh grants (株式の定期追加付与)
```

### 原則 4: 競合オファーが最強の交渉カード

複数の会社から同時にオファーをもらうことで、交渉力が大幅に上がります。そのため、面接のスケジュールを揃えることが重要です。

---

## 2. 交渉のスクリプト

### 最初のオファーを受け取ったとき

口頭でオファーを受けた際、その場で即決しないでください。

```
"Thank you so much — I'm really excited about this opportunity.
Could I have a few days to review everything carefully?
I want to make sure I'm making the right decision."

  // ありがとうございます。この機会に本当に興奮しています。
  // すべてを慎重に検討するために数日いただけますか?
  // 正しい判断をしたいと思っています。
```

通常 2〜5 営業日は普通にもらえます。

### 給与交渉: 基本スクリプト

```
"I'm really excited about this role and I'd love to join the team.
I've done some research and, based on my experience level and
the market rates for this role, I was hoping we could get to [希望額].
Is there any flexibility on the base salary?"

  // このポジションにとても興奮しており、チームに参加したいと強く思っています。
  // 調査をしたのですが、私の経験レベルとこのポジションの市場レートに基づいて、
  // [希望額]まで届けることを期待していました。
  // 基本給に柔軟性はありますか?
```

**重要:** 「[希望額]」には、自分が実際に希望する額より少し高い数字を入れます。交渉の余地を残すためです。

### 競合オファーを使った交渉

```
"I'm very enthusiastic about this role. I want to be transparent with you —
I do have another offer from [会社名 or "another company"] at [金額].
I'm genuinely more excited about this opportunity, but is there anything
you can do to close the gap?"

  // このポジションにとても熱意があります。透明性を持って伝えたいのですが、
  // [会社名]から[金額]の別のオファーを持っています。
  // 本当にこちらの機会の方により興奮しているのですが、
  // その差を縮めることはできますか?
```

### 給与が上げられない場合の代替交渉

給与が固定されている場合でも、他の条件を交渉できます。

```
"I understand base salary may be fixed at this level. Is there
any flexibility on the signing bonus or the equity grant?
Alternatively, could we discuss an earlier performance review —
say at 6 months instead of 12?"

  // 基本給がこのレベルで固定されていることは理解しています。
  // 契約一時金や株式付与に柔軟性はありますか?
  // あるいは、業績評価を早める — 12ヶ月ではなく6ヶ月で — ことを
  // 話し合うことはできますか?
```

### オファーを断るとき

断る際も丁寧に。業界は狭く、将来また会うことがあります。

```
"After careful consideration, I've decided to pursue another opportunity
that is a better fit for my current career goals. I really appreciate
the time the team spent with me throughout this process, and I have
tremendous respect for what you're building. I hope our paths cross again."

  // 慎重に検討した結果、現在のキャリア目標により適した別の機会を選ぶことにしました。
  // このプロセスを通じてチームが割いてくれた時間に本当に感謝しています。
  // 皆さんが構築しているものに大きな敬意を持っています。またどこかでお会いできることを願っています。
```

## 3. オファーを評価するチェックリスト

オファーを比較するときに確認すべき項目:

```
給与・報酬
[ ] Base salary はいくらか?
[ ] Signing bonus はあるか?
[ ] 株式(RSU/Options)の総額は?
[ ] Vesting schedule は? (通常 4年 cliff 1年が標準)
[ ] 年次昇給・ボーナスの仕組みは?

働き方
[ ] フルリモート・ハイブリッド・オフィスどれか?
[ ] 勤務時間・タイムゾーンの期待値は?
[ ] 有給日数は?

成長・文化
[ ] L&D (Learning and Development) 予算はあるか?
[ ] エンジニアリングカルチャーはどうか? (コードレビュー文化、技術的負債への向き合い方)
[ ] マネージャーと会ったか? (上司との相性は最重要)
[ ] チームは何人? 自分の成長を支えてくれる環境か?

安定性
[ ] 直近の資金調達状況は?
[ ] Runway は? (スタートアップの場合)
[ ] 業績は安定しているか?
```

## 4. 入社後の90日プラン

良いスタートを切るための戦略です。

### 最初の30日: 学ぶ

```
Goals:
- Understand the codebase architecture
- Meet every team member (schedule 1:1s)
- Learn the deployment process
- Complete 1-2 small, well-defined tasks

Mindset: Listen more than you speak.
Don't suggest big changes yet. Build trust first.
```

日本語訳:
```
// 目標:
// - コードベースのアーキテクチャを理解する
// - チームメンバー全員と会う(1on1を設定する)
// - デプロイプロセスを習得する
// - 小さく明確に定義されたタスクを1〜2個完了させる
//
// マインドセット: 話すより聴く
// まだ大きな変更を提案しない。まず信頼を築く
```

### 31〜60日: 貢献する

```
Goals:
- Ship a meaningful feature or fix
- Run your first solo PR review cycle
- Understand team priorities and roadmap
- Identify areas where you can add unique value

Questions to ask your manager:
"What would make the biggest difference to the team right now?"
"What would success look like for me at the 3-month mark?"
```

### 61〜90日: インパクトを出す

```
Goals:
- Own a full feature end-to-end
- Proactively identify a problem and propose a solution
- Build relationships outside your immediate team
- Request a 90-day feedback session with your manager

At 90-day check-in:
"Here's what I've accomplished in the first 90 days: [リスト]
Here's what I'm planning to focus on in the next 90 days: [リスト]
Is there anything you'd add or change?"
```

## 5. リモートワークで信頼を築くコツ

リモートチームでの立ち上がりは対面より難しいです。

```
1. Over-communicate (伝えすぎるくらい伝える)
   - 作業中に Slack で進捗を共有する
   - ブロッカーを早く伝える

2. Be reliable (信頼できると示す)
   - 言ったことを必ずやる。できない場合は早めに言う

3. Be visible (存在感を示す)
   - 会議では発言する
   - Slack のスレッドにリアクションや短いコメントをする

4. Build relationships (関係を築く)
   - バーチャルコーヒーチャットを自分から申し込む
   - チームメンバーの投稿に反応する
```

---

## まとめ

- オファーは必ず交渉する。断られることはない
- 給与だけでなく、総合報酬(サインオンボーナス、株式、福利厚生)で考える
- 競合オファーが最強の交渉カード。面接スケジュールを揃える
- 入社後の90日は「学ぶ→貢献する→インパクトを出す」の3フェーズで計画する
- リモートでは over-communicate が鉄則
