# 模範解答 03: 質問文作成演習

## この解答の使い方

演習 3-A〜3-D を実施してから読むこと。
自分が書いた質問文と比較して、「何が足りなかったか」「何が良かったか」を評価する。

## 演習 3-A: 悪い質問を改善する — 模範解答

### 悪い質問 1 の改善例

**元の質問:**
「Pythonが動かないです。どうすればいいですか」

**改善後:**

```
【状況】
Pythonの入門チュートリアルを始めようとしています。
公式サイトからPython 3.12をインストールし、最初のプログラムを実行しようとしました。

【問題】
ターミナルで `python hello.py` を実行したところ、以下のエラーが表示されました。

    zsh: command not found: python

【期待していた動作】
`Hello, World!` と表示されるはずでした。

【試みたこと】
1. `python --version` を試した(同じエラーが出た)
2. `python3 --version` を試した(python3 3.12.0 と表示された)
3. Pythonのインストールは完了しているように見える

【環境】
- OS: macOS 14.2 (Sonoma)
- インストールしたPythonのバージョン: 3.12
- シェル: zsh

【関連コード】
# hello.py の内容
print("Hello, World!")
```

**解説:**

「Pythonが動かない」という元の質問では、回答者には何もわからない。
改善後の質問では:
- `python` コマンドが存在しないが `python3` は動く → パスの問題が疑われる
- macOS + zsh という環境 → 「`python3` を使うか、エイリアスを設定する」という回答ができる

情報を整理することで、問題の本質が見えてくる。

### 悪い質問 2 の改善例

**元の質問:**
「CSSでボタンを中央に配置したいのですが、できません」

**改善後:**

```
【状況】
シンプルなランディングページを作っています。
ページ中央にボタンを配置しようとしています。

【問題】
ボタンが左端に表示されてしまい、中央に移動しません。

【期待していた動作】
ブラウザの横幅の中央にボタンが表示されてほしい。

【試みたこと】
1. `margin: 0 auto;` を試した(変化なし)
2. `text-align: center;` を親要素に試した(変化なし)
3. 「CSS ボタン 中央揃え」で検索したがうまくいかなかった

【環境】
- ブラウザ: Chrome 121
- その他: HTMLとCSSのみ使用(JavaScriptは未使用)

【関連コード】
<!-- HTML -->
<div class="container">
  <button class="btn">クリック</button>
</div>

/* CSS */
.container {
  width: 100%;
}

.btn {
  margin: 0 auto;
}
```

**解説:**

この情報があれば、回答者はすぐに問題を特定できる。
`margin: 0 auto` は `display: block` でないと効かないため、
「`.btn` に `display: block;` を追加してください」という具体的な回答ができる。

### 悪い質問 3 の改善例

**元の質問:**
「GitHubにpushしたらエラーが出ました。コードは正しいはずなのに。誰か助けてください」

**改善後:**

```
【状況】
初めてGitHubにコードをpushしようとしています。
ローカルでコミットを作成し、GitHubのリモートリポジトリにpushしようとしました。

【問題】
以下のエラーが表示されました。

    error: src refspec main does not match any
    error: failed to push some refs to 'https://github.com/username/repo.git'

【期待していた動作】
`git push origin main` を実行して、ローカルのコードがGitHubに反映されるはずでした。

【試みたこと】
1. `git status` を確認した(nothing to commit, working tree clean と表示された)
2. `git log --oneline` を確認した(何も表示されなかった)
3. GitHubのリポジトリページを確認した(空の状態だった)

【環境】
- OS: Windows 11
- Git バージョン: 2.43.0
- GitHubのリポジトリ: 新規作成(Initialize with README はチェックしなかった)

【関連コード】
実行したコマンドの順序:
1. git init
2. git remote add origin https://github.com/username/repo.git
3. git push origin main  ← ここでエラー
```

**解説:**

`git log --oneline` で何も表示されないという情報から、
「コミットが1件もない状態でpushしようとした」という原因が特定できる。
対処法: `git add .` → `git commit -m "初回コミット"` → 再度 `git push` という回答ができる。

## 演習 3-D: ラバーダックデバッグ — 模範解答例

**問題のある疑似コード(再掲):**

入力6、期待「大きい」、実際「小さい」

**ラバーダックへの説明文の例:**

```
えっと、このコードはユーザーが入力した数値を2倍にして、
10より大きいかどうか判定するはずなんです。

入力が6なら、6を2倍にして12になって、12は10より大きいから
「大きい」と表示されるはずなんですよね。

でも「小さい」と出てるんです。ということは……

あ、もしかして「2倍にする」処理が実際には実行されていないかもしれない。
変数に2倍した値を代入しているつもりが、元の値のまま比較しているのかな?
つまり6を2倍にした12と比較するはずが、2倍にする前の6と比較してしまっているかも。
6 > 10 は偽(false)だから「小さい」が表示されている……そういうことかな?
```

**仮説:**

「2倍にした結果を変数に代入していない」または「2倍にする処理が条件判定の後に書かれている」

**確認方法:**

2倍にした後の変数の値を `print()` で出力して確認する。
「12と表示されるはず」が「6と表示された」なら代入の問題。
「何も表示されない」なら処理の順序の問題。

## 質問テンプレートを使うことで何が変わるか

**自己解決率が上がる**

テンプレートを埋めようとする過程で、「試みたこと」を書くために実際に試すことになる。
これが「15分ルール」の実践につながる。

多くの場合、テンプレートを埋め終わる前に「あ、これが原因か」と気づく。
これが「ラバーダック効果」だ。

**回答の質が上がる**

テンプレートに従った質問は、回答者が「再現→診断→回答」できる情報を含んでいる。
「なんとなく試してみてください」ではなく「○○の原因なので△△してください」という
具体的で正確な回答が返ってくる確率が上がる。

**信頼が蓄積される**

良い質問ができる人は「この人は自分で調べた上で質問している」という信頼を得る。
チームの中で「質問上手」という評価は、実は非常に高い評価だ。
