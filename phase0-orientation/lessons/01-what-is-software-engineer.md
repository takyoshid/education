# Lesson 01: ソフトウェアエンジニアという職業

## このレッスンで学ぶこと

- ソフトウェアエンジニアの職種の種類と役割
- 日本と世界（主に米国）の違い
- キャリアパスの全体像
- この職業を選ぶ前に知っておくべきリアル

---

## 1. ソフトウェアエンジニア(software engineer)とは何か

「プログラマー」「エンジニア」「開発者(developer)」という言葉は日常的に混用されるが、
職業として正確に理解しておくことは、自分のキャリアを設計するうえで重要になる。

**ソフトウェアエンジニア**とは、ソフトウェア(software)を設計・実装・テスト・運用することを
業務とする職業の総称である。「ソフトウェア」とは、コンピュータに対する命令の集合体のことで、
スマートフォンのアプリ、Webサービス、銀行の基幹システム、自動車の制御プログラムなど、
現代社会のあらゆるところに存在する。

---

## 2. 職種の種類

ソフトウェアエンジニアは一枚岩ではない。専門によって以下のように分かれる。

### フロントエンドエンジニア(Front-end Engineer)

ユーザーが直接目にする部分(画面・インターフェース)を作る。
WebブラウザやスマートフォンのUIを担当する。主要技術はHTML、CSS、JavaScript。

「お客さんが実際に触れるカウンター部分を設計・装飾する人」と考えるとわかりやすい。

### バックエンドエンジニア(Back-end Engineer)

データの処理・保存・ビジネスロジックを担当する。ユーザーからは見えないが、
サービスの心臓部にあたる。主要技術はPython、Ruby、Go、Javaなど。

「お客さんからは見えない厨房で料理を作る人」に相当する。

### フルスタックエンジニア(Full-stack Engineer)

フロントエンドとバックエンドの両方を担当できるエンジニア。
小規模なチームや初期スタートアップで特に重宝される。
「フルスタック」という言葉はキャリアの目標としてよく語られるが、
どちらも深く極めるには相当な年数がかかる。初学者が最初から目指す必要はない。

### インフラ・SREエンジニア(Infrastructure / Site Reliability Engineer)

アプリケーションが動く基盤(サーバー、クラウド、ネットワーク)を担当する。
サービスが安定して動き続けるための仕組みを作る。
主要技術はAWS/GCP/Azureなどのクラウド、Linux、Docker、Kubernetes。

### データエンジニア(Data Engineer) / データサイエンティスト(Data Scientist)

大量のデータを収集・加工・分析する職種。機械学習(machine learning)や
統計を使ってビジネスの意思決定を支援する。主要技術はPython、SQL、各種MLフレームワーク。

### モバイルエンジニア(Mobile Engineer)

iOSやAndroidのスマートフォンアプリを開発する職種。
iOS向けはSwift、Android向けはKotlinが主要言語。
React NativeやFlutterを使うクロスプラットフォーム開発も増えている。

### セキュリティエンジニア(Security Engineer)

システムへの攻撃を防ぎ、脆弱性(vulnerability)を発見・修正する職種。
特にクラウド時代になってから需要が急増している分野。

## 3. 日本と世界の違い

エンジニアの働き方や評価のされ方は、日本と海外(特に米国)で大きく異なる。
この違いを理解することは、将来どこで・どのように働くかを考えるうえで重要だ。

### 給与水準

2024年時点の概算比較。

| | 日本(東京・経験3〜5年) | 米国(SF/NY・経験3〜5年) |
|---|---|---|
| 年収の目安 | 500〜900万円 | 1,500〜3,000万円相当 |
| 差の主な要因 | 市場規模、評価文化、資金調達規模 | - |

日本でも外資系テック企業やメガベンチャーでは1,000万円超が一般的になりつつある。
ただし給与だけで職場を選ぶことには注意が必要で、成長環境・チームの質も同等に重要だ。

### 評価のされ方

日本では「年功序列(seniority-based evaluation)」の文化が残る企業が多い一方、
グローバルなテック企業では「何を作ったか」「どれほどの影響(impact)を出したか」
という成果ベースの評価が主流である。

これは学習姿勢にも影響する。グローバルな基準では、
「会社が教えてくれるのを待つ」姿勢より「自分で学び、チームに貢献する」姿勢が求められる。

### 英語について

英語が読み書きできると、情報へのアクセス量が桁違いに増える。
最新の技術情報の大部分は英語で発信されるため、英語を避け続けることはエンジニアとして
成長の上限を自分で作ることに等しい。読み書きが優先で、最初は話せなくてよい。

## 4. キャリアパスの全体像

エンジニアのキャリアは、大きく次の2方向に分かれる。

### 技術的専門家(Individual Contributor / IC)路線

コードを書き続け、特定分野の深い専門性を磨くルート。
米国では「Principal Engineer」「Distinguished Engineer」「Fellow」といった肩書きで
マネージャーと同等以上の報酬・影響力を持つポジションが存在する。

### エンジニアリングマネージャー(Engineering Manager / EM)路線

チームのマネジメントや採用・組織設計を担うルート。
技術の理解は引き続き必要だが、主な仕事は「人とシステムの設計」になる。

どちらが正解ということはなく、自分の興味・強みに合わせて選べばよい。
入社から2〜4年は、まず「良いIC」になることだけを考えるのが合理的な戦略だ。

### ジュニア・ミドル・シニアの違い

| レベル | 目安の経験年数 | 期待される役割 |
|---|---|---|
| ジュニア(Junior) | 0〜2年 | 与えられたタスクをこなす。不明点は積極的に質問する |
| ミドル(Mid-level) | 2〜5年 | 機能単位で自律して設計・実装できる |
| シニア(Senior) | 5年以上 | プロジェクト全体に責任を持ち、ジュニアを育てられる |

「シニア」の定義は企業によって大きく異なるが、
「アンビギュアスな問題(曖昧で答えが決まっていない問題)を自分で定義・解決できる」
ことが共通した要素として挙げられることが多い。

## 5. この職業のリアル

### 継続的な学習が前提

ソフトウェアエンジニアは「一度学べば終わり」の職業ではない。
技術は常に進化し、5年前の「最新技術」が今日では時代遅れになることも珍しくない。
これを苦痛と感じる人もいれば、生涯学習を楽しめる人もいる。後者に向いている職業だ。

### 孤独な作業とチームワークの両立

コードを書く作業は基本的に個人の集中作業だが、
現代のソフトウェア開発はチームで行うものであり、コミュニケーション能力は不可欠だ。
「技術だけ磨けばよい」という考えは、特にシニアレベル以降では通用しない。

### バグ(bug)と付き合い続ける仕事

完璧なソフトウェアは存在しない。エンジニアの仕事の大部分は、
新機能を作ることよりも「なぜ動かないのか」を調査・修正する作業(デバッグ, debugging)である。
デバッグを嫌いにならないことが、長くエンジニアを続けるコツのひとつだ。

## 💡 コラム: 月に人類を送ったソフトウェアエンジニア

1969年、アポロ11号が月面着陸する直前、誘導コンピュータが「1202」という警告を出しました。計算能力の限界を超えるデータが流れ込んだのです。しかし着陸は続行されました。MIT のマーガレット・ハミルトンのチームが「過負荷になったら、重要度の低い処理を捨てて着陸に必要な計算だけを続ける」という設計をあらかじめ組み込んでいたからです。

ハミルトンは「ソフトウェアエンジニアリング」という言葉を広めた人物としても知られます。彼女が印刷した誘導プログラムのコードを積み上げると、自分の背丈と同じ高さになった写真は有名です。

エンジニアリングとは「動くコードを書くこと」ではなく、**想定外の事態を設計段階で考え抜くこと** — この違いが、月面着陸を成功させました。

---

## まとめ

- ソフトウェアエンジニアには多様な職種がある。最初から「全部」を目指す必要はない
- 日本と世界では給与・評価文化に大きな差がある。グローバル基準を早めに知ることが有利
- キャリアは「IC路線」「EM路線」に分かれる。最初の数年はICとしての基礎を固める
- この職業は継続学習が前提。それを楽しめるかどうかが長期的な成功を左右する

## 確認問題

次の問いに自分の言葉で答えてみよ。答えはレッスンの中にある。

1. フロントエンドエンジニアとバックエンドエンジニアの違いを、比喩を使わずに説明してください。
2. 「年功序列」と「成果ベース評価」それぞれのメリット・デメリットを1つずつ挙げてください。
3. ジュニアエンジニアに期待される役割を、自分の言葉で説明してください。
4. なぜエンジニアにとって英語が重要なのか、具体的な理由を述べてください。
5. 「デバッグ(debugging)」とは何か、一言で説明してください。
