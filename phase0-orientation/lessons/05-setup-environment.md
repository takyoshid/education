## 1. なぜ環境構築が最初のハードルなのか

多くの初学者が「環境構築でつまずいてエンジニアへの道を諦めた」という経験を持つ。
これは珍しいことではなく、環境構築は**実際に難しい**。

理由は次の通りだ:
- OS(オペレーティングシステム)・バージョン・過去にインストールしたものの組み合わせが人によって違う
- エラーメッセージが英語で、かつ専門的
- 「どの手順が自分の状況に当てはまるのか」がわかりにくい

**詰まっても自分を責めないこと。環境構築は熟練のエンジニアでも詰まる作業だ。**

このレッスンでは手順だけでなく「なぜそうするのか」も説明する。
理由を理解することで、想定外のエラーが起きたときに自力で対処しやすくなる。

## 2. ターミナル(Terminal)

### ターミナルとは

ターミナル(terminal)とは、コンピュータに対して**テキストでコマンド(command)を入力して
操作するインターフェース**だ。GUI(グラフィカルユーザーインターフェース)とは異なり、
マウスを使わずにキーボードだけで操作する。

「ターミナル = 怖いもの」というイメージを持つ人は多いが、実態は単純だ。
「コンピュータに日本語ではなく、決まった文法の英語で命令を出すツール」だと考えればよい。

### なぜターミナルを使うのか

エンジニアがターミナルを使う主な理由:
- **速い**: マウスで操作するより速く操作できる
- **自動化できる**: 繰り返し作業をスクリプト(script)で自動化できる
- **サーバーでは必須**: 本番環境(production environment)のサーバーにはGUIがなく、
  ターミナルでしか操作できない
- **開発ツールの多くがターミナルで動く**: Git、パッケージマネージャーなど

### macOS でのターミナルの開き方

**方法1: Spotlight 検索**
1. `Command(Cmd) + スペース` キーを押す
2. 「terminal」と入力する
3. 「ターミナル.app」をクリックする

**方法2: Finder から**
1. Finder を開く
2. 「アプリケーション」→「ユーティリティ」→「ターミナル」をダブルクリック

macOS では**Zsh(ズィーシェル)**というシェル(shell)がデフォルトで使われている。
「シェル」とはターミナルでコマンドを解釈・実行するプログラムのことだ。

### Windows でのターミナルの開き方

Windows では複数の選択肢があるが、**Windows Terminal + PowerShell** の組み合わせを推奨する。

**Windows Terminal のインストール**
1. Microsoft Store を開く
2. 「Windows Terminal」を検索してインストールする

**PowerShell の起動**
1. `Windows キー + X` を押す
2. 「Windows Terminal」を選択する

**Git Bash の代替手段**
後述する Git をインストールすると「Git Bash」が付属する。
これはmacOSや Linux と同じ操作感で使えるため、学習の統一性という点では有用だ。

## 3. ターミナルの基本コマンド

環境構築で最低限必要なコマンドを説明する。

### 現在地の確認

```bash
pwd
```

「Print Working Directory」の略。今どのディレクトリ(フォルダ)にいるかを表示する。

```bash
# 出力例(macOS)
/Users/username

# 出力例(Windows PowerShell)
C:\Users\username
```

### ディレクトリの内容を表示する

```bash
ls        # macOS / Linux / Git Bash
dir       # Windows PowerShell
```

現在のディレクトリにあるファイル・フォルダの一覧を表示する。

### ディレクトリを移動する

```bash
cd フォルダ名       # 子ディレクトリに移動
cd ..              # 親ディレクトリに移動
cd ~               # ホームディレクトリに移動(macOS/Linux)
cd $HOME           # ホームディレクトリに移動(Windows PowerShell)
```

「cd」は「Change Directory」の略。ファイルアプリでフォルダをダブルクリックして
移動する操作と同じことをコマンドで行っている。

### コマンドのキャンセル

実行中のコマンドを止めたいとき: `Control(Ctrl) + C`

## 4. VS Code のインストールと設定

### VS Code とは

Visual Studio Code(ビジュアルスタジオコード)は、Microsoft が開発した**無料のコードエディタ**だ。
「エディタ(editor)」とは、コードを書くための専用ソフトウェアのこと。

VS Code が広く使われる理由:
- 無料
- 多くのプログラミング言語に対応
- 拡張機能(extension)が豊富
- GitHub との連携が容易
- 軽量で動作が速い

### インストール手順

1. ブラウザで `https://code.visualstudio.com/` を開く
2. 「Download for Mac」または「Download for Windows」をクリック
3. ダウンロードしたファイルを実行してインストールする

**macOS の場合の追加手順:**
ダウンロードされた `.zip` ファイルを解凍し、`Visual Studio Code.app` を
`アプリケーション` フォルダに移動する。

### ターミナルから VS Code を開く設定 (macOS)

ターミナルから `code .` と入力してVS Code を開けるようにする設定。

1. VS Code を起動する
2. `Command + Shift + P` を押す(コマンドパレットが開く)
3. 「shell command」と入力する
4. 「Shell Command: Install 'code' command in PATH」を選択してEnter

設定後、ターミナルで `code .` と入力すると、現在のディレクトリを VS Code で開ける。

### 推奨拡張機能

| 拡張機能名 | 用途 |
|---|---|
| Japanese Language Pack for VS Code | VS Code のUIを日本語化 |
| GitLens | Git の変更履歴を視覚化 |
| Prettier | コードの自動整形 |
| ESLint | JavaScript のコード品質チェック |

拡張機能のインストール方法:
1. VS Code の左サイドバーの四角いアイコン(拡張機能)をクリック
2. 検索ボックスに拡張機能名を入力
3. 「インストール」をクリック

## 5. Git のインストールと初期設定

### Git とは

Git(ギット)は**バージョン管理システム(version control system)**だ。
コードの変更履歴をすべて記録し、過去の状態に戻ったり、複数人で同時に作業できる仕組みを提供する。

「Gitはなぜ必要か」を一言で言うと:
**「間違えたときに元に戻せる安全網」かつ「チームで同じコードを同時に編集するための仕組み」**

Git なしの開発は、保存ボタンが1つしかない文書作成ソフトを使うようなものだ。

### macOS での Git インストール

macOS には Git が最初から入っているか、Xcode Command Line Tools と共にインストールできる。

**確認方法:**
```bash
git --version
```

バージョン番号が表示されれば既にインストール済みだ。
「command not found」と表示された場合は次の手順でインストールする。

**インストール:**
```bash
xcode-select --install
```

ポップアップが表示されるので「インストール」をクリックする。

より新しいバージョンを使いたい場合は **Homebrew(ホームブリュー)** 経由でインストールする。
Homebrew は macOS 用のパッケージマネージャー(package manager)だ。

```bash
# Homebrew のインストール
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Git のインストール
brew install git
```

### Windows での Git インストール

1. ブラウザで `https://git-scm.com/download/win` を開く
2. 「64-bit Git for Windows Setup」をダウンロード
3. インストーラーを実行する
4. 基本的にはデフォルト設定で進めてよい
   - ただし「デフォルトのエディタ」は「Visual Studio Code」を選ぶと後で便利

インストール後、Git Bash または Windows Terminal で以下を確認する:
```bash
git --version
```

### Git の初期設定

Git をインストールしたら、最初に必ず以下の設定を行う。
この設定は「このコンピュータで作ったコミット(変更の記録)は誰が作ったのか」を示す情報だ。

```bash
git config --global user.name "あなたの名前"
git config --global user.email "あなたのメールアドレス"
```

設定の確認:
```bash
git config --list
```

**注意**: ここで設定したメールアドレスはコミット履歴に記録される。
GitHub を使う場合は、GitHub に登録したメールアドレスと一致させると連携が正確になる。

## 6. インストール確認チェックリスト

以下のコマンドをターミナルで実行し、エラーなく出力が表示されることを確認する。

```bash
# ターミナルの基本動作確認
echo "Hello, World!"

# Git のインストール確認
git --version

# VS Code のインストール確認(macOS のみ)
code --version
```

### よくあるエラーと対処法

**`command not found: git`**
→ Git がインストールされていない。インストール手順を再実行する。

**`zsh: permission denied`**
→ ファイルの実行権限がない。`chmod +x ファイル名` で権限を付与する。

**macOS で `xcrun: error: invalid active developer path`**
→ Xcode Command Line Tools が壊れている。
  `xcode-select --reset` を実行した後、`xcode-select --install` を再実行する。

**エラーが解決しない場合**
Lesson 03 の「15分ルール」と「良い質問テンプレート」を使って、
エラーメッセージ全文・OS・バージョン情報とともにコミュニティに質問する。

## 💡 コラム: 「私のマシンでは動くんですけど」

"It works on my machine."(私のマシンでは動くんですけど)— これはソフトウェア開発の世界で最も有名なジョークの一つです。あまりに定番すぎて、皮肉を込めた「Works on My Machine 認定バッジ」まで作られました。

新人が書いたコードが先輩のマシンで動かない。原因を調べると、言語のバージョンが違う、必要なツールが入っていない、環境変数が設定されていない…。環境構築の雑さは、こうして「自分だけ動く」謎の時間泥棒を生みます。

だからプロの世界では「環境を揃えること」自体が重要な技術です。このカリキュラムの後半(Phase 8)で学ぶ Docker は、まさにこの問題への人類の回答 — 「環境ごと箱詰めして渡す」技術です。今日の丁寧な環境構築は、その第一歩です。

## まとめ

- ターミナルはテキストでコンピュータを操作するインターフェース。エンジニアの基本ツール
- `pwd`・`ls`・`cd` の3つのコマンドで基本的なナビゲーションができる
- VS Code は無料・多機能・拡張性が高く、エンジニアに広く使われるコードエディタ
- Git はバージョン管理システム。コードを安全に管理するために不可欠
- 環境構築で詰まることは正常。エラーメッセージを読み、15分ルールで対処する
