# 客観的到達度評価ガイド

この教材の修了は、ページを読んだことやチェックボックスを埋めたことではなく、**初見の課題に対して知識を再現し、成果物と判断根拠を示せること**で判定します。

## 4種類の評価

各 Phase の通常演習とプロジェクトに加え、次の4種類を実施します。

| 評価 | 条件 | 測るもの |
|---|---|---|
| Retrieval Check | 教材・検索・AIなし、20〜30分 | 重要概念を思い出せるか |
| Transfer Task | 教材の例と異なる初見課題、60〜120分 | 知識を別の問題へ移せるか |
| Explanation | 5〜10分の口頭説明または録画 | コードを自分の言葉で説明できるか |
| Evidence Review | テスト結果、Git履歴、設計判断を提出 | 再現可能な成果があるか |

## AI利用ルール

評価は2回に分けます。

1. **基礎確認:** AI、検索、模範解答を使わない。言語リファレンスだけ許可する場合は課題に明記する。
2. **実務確認:** AIと検索を利用してよい。ただし、採用した提案、却下した提案、検証方法を `AI-LOG.md` に記録する。

AIを使ったことでは減点しません。理解せず採用した変更、検証できない説明、秘密情報の入力は不合格です。

## 合格基準

Phaseを修了するには、次をすべて満たします。

- 通常演習とPhaseプロジェクトが完了している
- Retrieval Checkが80%以上
- Transfer Taskの必須受け入れ条件をすべて満たす
- 自分の成果物について「なぜ」「別案」「失敗条件」を説明できる
- 第三者がREADMEだけで成果物を実行・検証できる
- 1週間後の再テストで、同じ能力を再現できる

不合格は失敗ではなく診断です。答えを暗記して即再試験せず、弱点を練習してから最低48時間空けます。

## 提出物の標準形

各Phaseについて `evidence/phase-N/` を自分の学習リポジトリに作ります。

```text
evidence/phase-N/
├── README.md          # 課題、実行方法、自己評価
├── decisions.md       # 判断とトレードオフ
├── test-results.txt   # 実行コマンドと結果
├── explanation.md     # 口頭説明の要旨または動画URL
├── AI-LOG.md          # 実務確認でAIを使った場合
└── artifacts/         # コード、図、計測結果
```

`test-results.txt` は手書きの「成功した」ではなく、実際のコマンド、終了コード、主要な出力を保存します。

## Phase別ゲート

| Phase | Transfer Task | 必須証拠 |
|---|---|---|
| 0 | 未知の技術課題を調査し、仮説と検証手順を作る | 情報源、調査ログ、振り返り |
| 1 | 壊れたシェル処理を診断し、安全に修正する | コマンド履歴、修正前後の出力 |
| 2 | 仕様だけから小さなCLIを実装する | 自動テスト、型・lint結果、Git履歴 |
| 3 | 未知の問題を2通りで解き、計測して選ぶ | 計算量分析、benchmark結果 |
| 4 | コンフリクトを解消し、PRレビューに対応する | PR、レビュー会話、復旧手順 |
| 5 | デザイン仕様からアクセシブルな画面を実装する | build、テスト、Lighthouse/a11y記録 |
| 6 | 不完全なAPIに認可・移行・異常系を追加する | APIテスト、マイグレーション往復、脅威メモ |
| 7 | テストのないコードを挙動維持で変更する | characterization test、ADR、差分 |
| 8 | 障害を検知・切り分け・復旧する | timeline、メトリクス、postmortem |
| 9 | 実ユーザーの問題を解き、フィードバックで改善する | 利用記録、外部レビュー、改善差分 |
| 10 | 英語で設計説明と模擬面接を行う | 録画、英文成果物、フィードバック |
| 11 | AI生成変更の欠陥を発見し、evalで回帰を防ぐ | AIログ、eval、手動レビュー記録 |
| 12 | 競合・重複配送・取消・停止を障害注入で再現し修正する | 不変条件、並行test、障害timeline |
| 13 | 要件から分散設計を決め、トレードオフと障害時挙動を説明する | ADR、容量計算、障害演習、第三者レビュー |

## 第三者レビュー

Phase 4、7、9では自己評価だけで合格にしません。メンター、学習仲間、OSSメンテナーなどから最低1回レビューを受け、次を残します。

- 指摘内容
- 採用または却下した判断と理由
- 修正したコミット
- 再検証結果

人によるレビューを得られない間は「仮合格」とし、次Phaseへ進んでもよいですが、Phase 9修了までに解消します。

## 定期的な保持確認

- 1週間後: Phaseゲートの一部を再実施
- 1か月後: 過去Phaseからランダムに1課題
- 3か月ごと: 横断プロジェクトを新しい要件で変更

忘れることを前提に、再学習の速度と自力で復元する力を育てます。
