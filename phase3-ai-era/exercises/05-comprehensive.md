# 演習 05: 総合演習 - AI と協働して機能を実装する

## 目的

Phase 3 で学んだすべての内容を統合し、AI と協働しながら小さな機能を実装します。「AI にすべて任せる」でも「AI を使わない」でもなく、適切に役割分担しながら開発するプロセスを実践します。

## 所要時間

120〜180 分

## 前提

- Phase 3 の Lesson 01〜07 を完了していること
- Python の基礎が理解できていること
- 任意のLLM providerまたは`FakeLLMClient`が使えること。実API keyは不要

---

## 課題: テキスト分析 CLI ツールの実装

以下の仕様を満たす CLI ツールを実装してください。

### 機能仕様

**コマンド名**: `analyze`

**機能一覧**:

1. テキストファイルを読み込み、文字数・行数・単語数を集計する
2. `LLMClient`境界を使ってテキストの要約を生成する (3 行以内)
3. 構造化出力とschema検証で感情分析を行う
4. 結果を JSON ファイルに保存する

**コマンドライン引数**:
```bash
python analyze.py input.txt --output result.json --summarize --sentiment
```

**出力例**:
```json
{
    "filename": "input.txt",
    "stats": {
        "characters": 1234,
        "lines": 45,
        "words": 234
    },
    "summary": "このテキストは〇〇について述べており...",
    "sentiment": {
        "label": "positive",
        "reason": "全体的に肯定的な表現が多く..."
    }
}
```

## 実装プロセスの手順 (重要)

このプロセスに従って実装してください。結果だけでなく「どのように AI を使ったか」のプロセスが評価対象です。

### フェーズ 1: 設計 (AI を使う)

まず AI に以下を質問して、設計のアドバイスをもらってください。

```
「以下の仕様の CLI ツールを Python で実装します。
実装前に、設計について相談したいです。

[仕様を貼り付ける]

質問:
1. どのライブラリを使うべきですか? (引数解析)
2. provider SDKをどのadapterへ隔離すべきですか?
3. エラーハンドリングで考慮すべき点は何ですか?

答えではなく、考え方と選択肢の比較をお願いします。」
```

**記録すること**: AI の回答と、それを踏まえてあなたが下した設計判断。

### フェーズ 2: 実装 (主に自分で書く)

設計が決まったら、以下の順番で実装します。

1. まず AI なしで、コアロジック (ファイル読み込み・集計) を書く
2. 詰まったら AI に「ヒント」を求める (答えは求めない)
3. Fakeとprovider adapterは Lesson 06 のinterfaceを参考に書く
4. 書き終わったら AI にレビューしてもらう

**記録すること**: どの部分を自力で書き、どの部分で AI を使ったか。

### フェーズ 3: レビュー (Lesson 04 のチェックリストを使う)

実装が完了したら、Lesson 04 のレビューチェックリストを使って自分のコードをレビューしてください。

**確認項目**:
- [ ] API キーが環境変数から読まれているか
- [ ] ファイルが存在しない場合のエラーハンドリング
- [ ] API 呼び出しが失敗した場合のエラーハンドリング
- [ ] 出力 JSON ファイルが上書きされる場合の警告
- [ ] コードを一行ずつ読んで理解できるか

### フェーズ 4: テスト

以下のテストケースで動作を確認してください。

1. **正常系**: 通常のテキストファイルで全機能が動く
2. **存在しないファイル**: 適切なエラーメッセージが出る
3. **空のファイル**: エラーにならず、適切な結果が返る
4. **日本語テキスト**: 日本語のファイルで正しく動く
5. **API キーなし**: 環境変数を unset して適切なエラーが出る

## 評価基準

### 実装の評価

| 項目 | 評価の観点 |
|------|-----------|
| 動作 | 仕様通りに動くか |
| コードの可読性 | 変数名・関数分割・コメントが適切か |
| エラーハンドリング | 異常系を適切に処理しているか |
| セキュリティ | API キーのハードコードがないか |

### プロセスの評価 (こちらが重要)

| 項目 | 評価の観点 |
|------|-----------|
| AI の使い方 | 「答えを写した」か「理解して実装した」か |
| 設計判断 | AI の提案を鵜呑みにせず自分で判断しているか |
| レビュー | チェックリストを使って問題を自分で発見できているか |
| 記録 | AI をどう使ったかのプロセスが記録されているか |

## ヒント

- `argparse` は Python 標準ライブラリです。外部ライブラリ不要で引数解析ができます。
- JSONを要求するだけで信用せず、schema検証、再試行上限、不正出力caseをtestしてください。
- テキストが長い場合、API のコンテキストウィンドウに収まるか確認してください。
- 「とりあえず動く」に満足せず、Lesson 04 のチェックリストを必ず使ってください。
