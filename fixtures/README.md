# 教材用ローカル API サーバ

この教材の演習とプロジェクトは、外部のサービスではなく**このサーバ**に対して書きます。

```bash
python3 fixtures/server.py
```

起動したら http://127.0.0.1:8787/ を開いてください。使えるエンドポイントの一覧が返ります。停止は `Ctrl+C` です。

## なぜ外部の API を使わないのか

教材が `https://api.example-service.com` のような外部サービスを叩くように書かれていると、**教材の寿命がそのサービスの寿命に縛られます。**

サービスは止まります。無料枠がなくなります。会社が買収されて API が閉じます。レスポンスの形が予告なく変わります。そのどれが起きても、原因は教材の外にあるのに、困るのは学習者です。「教材のとおりに書いたのに動かない」という体験は、初学者を最も確実に脱落させます。

このサーバをリポジトリに置いておけば、次のことが保証されます。

- **10年後も動く** — 依存パッケージがゼロなので、Python さえあれば動く
- **オフラインで動く** — 通信環境の悪い場所でも、飛行機の中でも学習が止まらない
- **結果が一定** — 同じ入力からは常に同じ出力が返るので、模範解答と手元の結果が食い違わない
- **壊れたら気づける** — CI がこのサーバの契約テストを実行している

外部の実サービスを叩く経験にも価値はあります。それは各プロジェクトの発展課題に置いてあります。**まず動くものを作り、そのあとで現実の不確実性に触れる**という順序です。

## 意図的に用意した「壊れ方」

実在の API では、失敗を狙って起こせません。サーバが落ちるのを待つわけにはいかないので、多くの教材は loading・empty・error の状態を「説明するだけ」で終わります。

このサーバは、**どのエンドポイントでも**次のクエリパラメータを受け付けます。

| パラメータ | 動き | 何の確認に使うか |
|---|---|---|
| `_delay=1500` | 1500 ミリ秒待ってから応答する | loading 状態、タイムアウト、競合するリクエスト |
| `_fail=500` | 指定した HTTP ステータスで失敗する | error 状態、リトライ、サーキットブレーカ |
| `_empty=1` | 結果が 0 件の応答を返す | empty 状態("見つかりません"の表示) |

```bash
# 3 秒待ってから返る。この間に UI が何を表示するかを確認する
curl "http://127.0.0.1:8787/v1/search?name=Tokyo&_delay=3000"

# 503 で失敗する
curl -i "http://127.0.0.1:8787/v1/forecast?latitude=35.6895&longitude=139.69171&_fail=503"

# 0 件で返る
curl "http://127.0.0.1:8787/posts?_empty=1"
```

**これはおまけの機能ではありません。** この教材は一貫して「idle / loading / success / empty / error を区別できること」を受け入れ条件に置いています。狙って起こせない状態は、実装したかどうかを確かめられません。

## エンドポイント

### 天気(Open-Meteo 互換)

Phase 6 の総仕上げプロジェクトが使います。

```
GET /v1/search?name=Tokyo&count=5
GET /v1/forecast?latitude=35.6895&longitude=139.69171&forecast_days=7&timezone=auto
```

収録している都市は `fixtures/data/cities.json` にあります。日本語名でも英語名でも検索できます(`東京` と `Tokyo` のどちらでも引けます)。

気温は実在の観測値ではありませんが、でたらめでもありません。緯度と季節から決定的に組み立てているので、**札幌はシンガポールより寒く、同じ都市の同じ日には必ず同じ値が返ります。** 学習者が画面の数字を見て「おかしい」と気づける程度には現実に沿わせてあります。

`/v1/search` は、一致する都市がないとき `results` キー**そのものを返しません**。これは実在の Open-Meteo の挙動をそのまま再現したものです。「空配列」と「キーが無い」を両方扱えないと実務で事故るので、あえて残しています。

### 一般的なデータ(JSONPlaceholder 互換)

```
GET  /users
GET  /users/{id}
GET  /posts?userId=1&_page=1&_limit=10
GET  /posts/{id}
POST /posts
```

ユーザ 10 件、投稿 100 件。メールアドレスとドメインは `.example`(RFC 2606 で予約された、誰のものにもならない TLD)にしてあります。実在のアドレスに演習のトラフィックが飛ばないようにするためです。

### リクエストの中身を見る(httpbin 互換)

```
GET  /get
POST /post
GET  /response-headers?X-Powered-By=curriculum
GET  /status/{code}
GET  /delay/{seconds}
```

送ったヘッダ・クエリ・ボディをそのまま返します。HTTP の学習で「自分が何を送っているのか」を確認するために使います。

### プレースホルダ画像

```
GET /photos/{seed}/{width}/{height}
```

指定サイズの SVG を返します。同じ seed からは同じ画像が出ます。`role="img"` と `aria-label` が付いているので、教材が要求するアクセシビリティの水準を、教材が配る素材自身も満たしています。

## 別のポートで動かす

```bash
python3 fixtures/server.py --port 9000
```

既定は 8787 です。Phase 7 の FastAPI(8000)や Vite の開発サーバ(5173)とぶつからない番号を選んでいます。

## このサーバ自体を壊していないか確かめる

```bash
python3 -m unittest discover -s fixtures/tests
```

CI でも実行しています。教材の土台なので、ここが壊れると広い範囲が同時に壊れます。

## 収録していないもの

実在のネットワークそのものを扱う場面では、このサーバを使いません。

- **Phase 1 の「インターネットの仕組み」** — DNS 解決や TLS ハンドシェイクが主題なので、`localhost` に向けると学ぶ対象が消えます。ここでは `example.com`(RFC 2606 でドキュメント用に予約されており、消滅しません)を使います。
- **Phase 10 のネットワーク調査演習** — `traceroute` や DNS レコードの調査は、実在の経路がなければ意味がありません。

つまり「データが欲しいだけ」の場面はローカルへ、「ネットワークそのものが主題」の場面は実網へ、と分けてあります。
