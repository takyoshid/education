# Lesson 14: キャリア戦略 — 世界で戦うために

## 学習目標

- セキュリティ業界の主要な職種と、自分の進む道を理解する
- バグバウンティ・CTF で実力を証明し、報酬を得る方法を知る
- 価値ある資格を、目的別に選べる
- 責任ある開示(responsible disclosure)を実践できる
- 世界のコミュニティで学び続け、発信する習慣を作る

---

## 0. セキュリティは「一生の学び」の職業

まず心構えから。セキュリティは、技術が最も速く変化する分野の一つです。新しい攻撃、新しいクラウド、新しい AI——去年の知識が今年通じないこともあります。だから**この職業の本質は「学び続けられること」** です。

朗報もあります。**世界的にセキュリティ人材は圧倒的に不足**しています(数百万人規模の不足と言われる)。実力を証明できれば、国境を越えて働けます。そしてこの分野は、**学歴より実力(何を見つけ、何を守れるか)** が評価される、実力主義の色が濃い世界です。あなたが Lesson 00〜13 で手を動かして得たものは、そのまま武器になります。

---

## 1. セキュリティの職種地図

「セキュリティエンジニア」は一つの職業ではなく、多様な専門の集合です。

| 職種 | 何をするか | このコースの関連 |
|------|-----------|----------------|
| **アプリケーションセキュリティ** | 開発に入り込み、安全なコード/設計を推進 | Lesson 04-08, 13 |
| **ペネトレーションテスター** | 許可を得て攻撃し、弱点を証明 | Lesson 09, 11 |
| **レッドチーマー** | 検知回避まで含む高度な模擬攻撃 | Lesson 01, 11 |
| **SOC アナリスト / ブルーチーム** | 監視・検知・インシデント対応 | Lesson 12 |
| **DFIR** | 侵害の調査・フォレンジック | Lesson 12 |
| **クラウド/インフラセキュリティ** | クラウド・K8s の安全設計 | Lesson 10 |
| **セキュリティエンジニア(基盤)** | 認証基盤・暗号・ツール開発 | Lesson 02, 07 |
| **プロダクトセキュリティ / DevSecOps** | セキュリティの自動化・仕組み化 | Lesson 13 |
| **GRC / セキュリティ監査** | ガバナンス・リスク・コンプライアンス | 全般 |

### まず「T字型」を目指す

一つの専門を深く(Tの縦棒)持ちつつ、全領域を浅く広く(Tの横棒)知る。このコースは横棒を作りました。次は、あなたが最も夢中になれた Lesson を縦棒に育てます。**「攻めが好き」ならペンテスト/レッド、「守り・分析が好き」なら SOC/DFIR、「作るのが好き」ならアプリ/プロダクトセキュリティ**。楽しいと感じた方向が、続けられる方向です。

## 2. バグバウンティ — 合法的に稼ぎ、実力を証明する

**バグバウンティ**は、企業が「うちのシステムの脆弱性を見つけたら報奨を払う」と公開する制度です。**合法的に、実際のシステムで、報酬を得ながら**腕を磨ける最高の実戦場です(Lesson 11 のサンティアゴ・ロペスの道)。

### プラットフォーム

- **HackerOne** / **Bugcrowd** — 世界最大級。多数の企業プログラム
- **Google VRP** / **Meta** / **Microsoft** など各社の独自プログラム
- **Intigriti**(欧州)など

### 鉄則(Lesson 00・11 の再確認)

```
✅ 必ず「プログラムのルール(scope)」を読む。スコープ外は絶対に触らない
✅ 許可された範囲・方法だけ。DoS 禁止など個別ルールを守る
✅ 見つけたら悪用せず、丁寧な再現手順とともに報告する
✅ 重複・既知でも学びになる。焦らず積み重ねる
```

### 最初の一歩

いきなり大企業は難しい。**VDP(報奨なしの開示プログラム)** や、範囲の広いプログラムから始め、まずは1件の有効な報告を目指します。Lesson 11 の報告書テンプレートがそのまま活きます。1件通ると自信になり、世界が変わります。

## 3. CTF — 遊びながら最強になる

**CTF(Capture The Flag)** は、セキュリティの競技です。隠された「フラグ」を、脆弱性を突いて奪取します。**世界中のトップハッカーが本気で遊ぶ**、最高の学習装置です。

```
Jeopardy 形式: Web/Crypto/Pwn(バイナリ)/Reversing/Forensics 等の問題を解く
Attack-Defense 形式: 自陣を守りつつ他チームを攻める(実戦さながら)
```

### 始め方

- **常設練習**: [picoCTF](https://picoctf.org/)(初心者向け・最高の入門)、[Hack The Box](https://www.hackthebox.com/)、[TryHackMe](https://tryhackme.com/)、[OverTheWire](https://overthewire.org/)(Linux/シェルの基礎)
- **暗号特化**: [Cryptopals](https://cryptopals.com/)(Lesson 02 の発展)
- **Web 特化**: [PortSwigger Web Security Academy](https://portswigger.net/web-security)(Lesson 04-08 と完全対応)
- **大会**: [CTFtime](https://ctftime.org/) で世界中の大会日程を確認。チームで出ると一気に伸びる

CTF は「答えのある攻撃練習」です。詰まっても Writeup(解説)で学べる。**遊びが実力になる**、この分野最大の特権です。

---

## 4. 資格 — 目的別に選ぶ

資格は「実力の証明」と「知識の体系化」に役立ちます。ただし**資格より実績(バグバウンティ/CTF/OSS/ポートフォリオ)** が評価される場面も多い。目的に合わせて選びます。

| 資格 | 性質 | 向く人 |
|------|------|--------|
| **OSCP** | 実技試験。24時間で実際にマシンを攻略。ペンテストの登竜門 | 攻撃側を目指す人(実力の証明力が高い) |
| **CEH** | 知識中心。倫理的ハッキングの基礎 | 基礎の体系化・書類要件 |
| **Security+** | 入門・広く浅く | これから始める人・基礎固め |
| **CISSP** | マネジメント・広範。経験要件あり | リーダー/管理職を目指す人 |
| **OSWE / OSEP** | 高度な実技(Web/回避) | 専門を深める人 |
| **GIAC(GCIH/GCFA 等)** | 防御・DFIR に強い | ブルーチーム/フォレンジック |
| クラウド系(AWS/GCP Security) | クラウド特化 | クラウドセキュリティ志望 |

**おすすめの順序(攻撃志望例)**: Security+(基礎)→ 実践(HTB/TryHackMe)→ **OSCP**(実力の決定的な証明)。OSCP の "**Try Harder**"(諦めず粘れ)という標語は、Lesson 00 のクリフォード・ストールの執念と同じ精神です。

## 5. 責任ある開示 — プロの倫理を実践する

偶然、実在のサービスに脆弱性を見つけたら? **正しい開示**がプロの証です。

```
責任ある開示(Responsible / Coordinated Disclosure)の流れ:
1. 悪用しない・データを取らない・被害を出さない
2. ベンダーの窓口(security@, VDP, security.txt)を探して非公開で報告
3. 十分な修正期間を与える(慣例で 90 日など)
4. 修正後、合意の上で公表(または CVE 採番)
```

- ❌ **フルディスクロージャー**をいきなり公開 → 攻撃者に塩を送る
- ❌ 「直さないなら公開するぞ」と**脅す** → 恐喝と見なされうる
- ✅ 誠実に、証拠とともに、静かに報告する

Lesson 11 のコラムを思い出してください。**同じ発見でも、開示の作法一つで英雄にも加害者にもなる。** これを実践できることが、雇う側から見た「信頼できる人材」の条件です。

## 6. 学び続け、発信する

### インプット(世界の一次情報を追う)

```
✅ セキュリティニュース: The Hacker News, Krebs on Security, tldr sec(週刊)
✅ 一次情報: 各社セキュリティブログ(Google Project Zero, PortSwigger Research)
✅ 脅威情報: MITRE ATT&CK の更新、CISA の KEV(悪用が確認された脆弱性)カタログ
✅ 書籍: 『The Web Application Hacker's Handbook』『The Tangled Web』
        『Real-World Bug Hunting』、そして Lesson 00 の『The Cuckoo's Egg』
```

### アウトプット(発信が最強の学習であり、名刺になる)

```
✅ CTF/バグバウンティの Writeup をブログに書く(英語だと世界に届く)
✅ 見つけた脆弱性(開示済み)や学びを技術記事に
✅ 自作の検証ツール・スクリプトを GitHub に(このコースの成果物を公開)
✅ 勉強会・カンファレンス(Black Hat, DEF CON, CODE BLUE 等)に参加/登壇
```

**発信は、あなたの実力を世界から見える形にします。** 採用担当も、バグバウンティのトリアージャーも、あなたのブログと GitHub を見ます。Lesson 11 の総仕上げプロジェクトの報告書は、その第一号になります。

## 💡 コラム: 時給1ドルの少年が、Google を守る側になるまで

このコースを、一人の実在のハッカーの物語で締めくくります。

**サンティアゴ・ロペス**——Lesson 11 でも触れた、アルゼンチンのブエノスアイレス郊外に暮らす少年でした。裕福な家庭ではありません。プログラミングスクールに通う金もない。彼が持っていたのは、一台のコンピュータと、映画『ハッカー』を観て芽生えた好奇心、そして YouTube と無料のブログ記事だけでした。16歳のとき、彼はバグバウンティという仕組みを知ります。「セキュリティの穴を見つけると、企業がお金をくれる制度がある」と。

最初は何も見つかりませんでした。何百時間もかけて、報われない日々。しかし彼はルールを守り抜きました——**スコープの中で、悪用せず、丁寧に報告する**。最初の報奨はわずか50ドルほど。それでも彼は続けました。手法を記事にし、失敗から学び、少しずつ「見つける目」を養っていきました。

そして2019年、彼は世界に衝撃を与えます。**19歳にして、バグバウンティによる報奨の総額が100万ドルを突破した世界初のハッカー**になったのです。Verizon、Twitter、そして数多の企業が、彼の報告によって守られました。彼を雇ったのは大学の学位でも高価な資格でもありません。**1600件を超える、正しく報告された脆弱性**——つまり、彼が実際に世界を安全にした証拠そのものでした。

彼の物語が、このコースのすべてを象徴しています。**必要だったのは、才能でも金でもなく、好奇心と、粘り強さと、一線を越えない規律だった。** クリフォード・ストールが75セントを追った執念(Lesson 00)、ケビン・ミトニックが越えて/越えなかった一線(Lesson 01)、サミー・カムカーが払った代償(Lesson 06)——このコースで出会ったすべての物語が、ロペスの一点に集約されます。

あなたが今持っているのは、彼が始めたときと同じもの——コンピュータと、好奇心です。そこにこのコースで得た知識と、隔離ラボと、手を動かした時間が加わりました。**世界を守る側に立つのに、特別な生まれは要りません。** 要るのは、「おかしい」を追いかける執念と、越えてはいけない一線を守る誠実さ。その2つを、あなたはもう持っています。

ようこそ、セキュリティエンジニアの世界へ。ここからは、あなた自身の物語です。
