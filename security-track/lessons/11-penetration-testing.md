# Lesson 11: ペネトレーションテスト実践

## 学習目標

- ペネトレーションテストの目的と、脆弱性スキャンとの違いを説明できる
- 契約・スコープ・許可(Rules of Engagement)の重要性を理解する
- 偵察 → 列挙 → 攻略 → 権限昇格 → 横展開 → 報告 の一連を実行できる
- 主要ツール(nmap/Burp/sqlmap/Metasploit)を役割で理解する
- プロ品質の診断報告書を書ける(これが最大の成果物)

> ⚠️ この Lesson の技術は、**書面の許可があるシステム、または合法的な練習環境(TryHackMe/HTB/自分のラボ)** でのみ使用してください。無許可の実施は犯罪です(Lesson 00)。

---

## 0. ペネトレーションテストとは — 「許可された攻撃」

**ペネトレーションテスト(ペンテスト)** は、実際の攻撃者と同じ手口で、**許可を得て**システムに侵入を試み、悪用可能な弱点を証明する営みです。

```
脆弱性スキャン: ツールで「弱点かもしれない箇所」を機械的にリストアップ(点)
ペネトレーションテスト: 人間が弱点を「実際に悪用」し、繋いで被害を実証(線・面)
レッドチーム演習: 検知・対応も含めた総合的な模擬攻撃(組織全体を試す)
```

スキャナは「窓の鍵が開いているかも」と教えます。ペンテスターは「その窓から入り、金庫まで到達できた」と証明します。**"実際に悪用できる" ことの証明**が、ペンテストの価値です。

---

## 1. 何より先に — 契約とスコープ(Rules of Engagement)

プロのペンテストは、技術の前に**紙**から始まります。ここを飛ばすと、優れた技術者が一瞬で犯罪者になります。

```
必須の合意事項(Rules of Engagement):
  □ 書面による許可(authorization letter)— 誰が許可したか
  □ スコープ — テスト対象の IP/ドメイン/アプリ。対象外の明記
  □ 期間・時間帯 — いつ実施してよいか(業務影響を避ける)
  □ 禁止事項 — DoS 禁止、本番データ破壊禁止、など
  □ 緊急連絡先 — 障害や本物の侵害を見つけた時の連絡ルート
  □ データの扱い — 見つけた情報の保管・削除方法(守秘義務)
  □ "Get Out of Jail" レター — 法的保護の書面
```

**スコープ外には指一本触れない。** これはプロの絶対規範です。バグバウンティ(Lesson 14)でも、対象範囲(scope)の逸脱は報奨ゼロどころか法的責任を問われます。

---

## 2. ペンテストの方法論(PTES / OWASP)

業界標準の流れ。Lesson 01 の Kill Chain と対応します。

```
1. 事前合意(Pre-engagement)   … スコープ・契約(上記)
2. 偵察(Reconnaissance)        … 標的の情報収集
3. スキャン・列挙(Enumeration) … サービス・脆弱性の特定
4. 攻略(Exploitation)          … 侵入する
5. 権限昇格・横展開(Post-exploitation) … 深く・広く(Lesson 09)
6. 報告(Reporting)             … 最重要。価値はここに宿る
```

---

## 3. フェーズ2: 偵察(Reconnaissance)

「攻撃は情報収集が9割」。標的を知るほど攻略は容易になります。

### パッシブ偵察(標的に触れない)

標的に痕跡を残さず、公開情報から集めます(**OSINT**)。

```
✅ WHOIS / DNS レコード、証明書透明性ログ(crt.sh でサブドメイン発見)
✅ Google ドーキング(google hacking):
     site:example.com filetype:pdf     … 公開文書
     site:example.com inurl:admin       … 管理画面
✅ GitHub 検索(漏れた API キー・内部情報)
✅ Shodan(インターネットに露出した機器の検索エンジン)
✅ 従業員情報(LinkedIn 等)→ ソーシャルエンジニアリングの下地
```

### アクティブ偵察(標的に触れる/許可必須)

```bash
# サブドメイン列挙・ポートスキャン(Lesson 03)
nmap -sV -sC -T4 -oA scan target.example.com    # -oA で全形式保存(報告用)

# Web の技術スタック特定
whatweb https://target.example.com
```

---

## 4. フェーズ3: 列挙(Enumeration)

見つけたサービスを深掘りし、「入れそうな穴」を特定します。ペンテストで最も時間をかける地味で重要な工程です。

```bash
# Web ディレクトリ/ファイルの探索(隠れた管理画面・バックアップ)
ffuf -u https://target/FUZZ -w wordlist.txt
gobuster dir -u https://target -w /usr/share/wordlists/dirb/common.txt

# Web 脆弱性の自動チェック(補助)
nikto -h https://target
```

そして手動での確認——ログイン、入力欄、API。ここで Lesson 04〜08 の知識(SQLi・XSS・IDOR・SSRF…)を総動員します。**自動ツールは入口を見つけるだけ。深い脆弱性は人間が見つける。**

## 5. フェーズ4-5: 攻略と侵入後

### 主要ツールの役割整理

| ツール | 役割 |
|--------|------|
| **Burp Suite** | Web 攻撃の主力。傍受・改ざん・Repeater・Intruder(Lesson 00) |
| **sqlmap** | SQLi の自動攻略(Lesson 05) |
| **Metasploit** | 既知脆弱性の exploit フレームワーク。ペイロード生成・実行 |
| **Hydra** | 認証の総当たり(許可・レート配慮) |
| **hashcat / John** | 入手したハッシュのオフライン解析 |
| **BloodHound** | Active Directory の権限関係を可視化し攻略経路を発見 |

### Metasploit の考え方(概念)

```
# 概念的な流れ(自分のラボの Metasploitable 等に対して)
msfconsole
search <脆弱性名>        # 既知 exploit を探す
use exploit/...           # 選ぶ
set RHOSTS <標的>         # 標的を指定(スコープ内のみ!)
set PAYLOAD <ペイロード>  # 侵入後に何をするか(逆シェル等)
exploit                   # 実行
```

### 侵入後(Post-exploitation)

侵入したら、Lesson 09 の権限昇格、Lesson 03 の横展開(lateral movement)、そして**「どこまで到達できたか」を証拠として記録**します。攻撃者が実際にどれだけの被害を出せるかを示すためです。**破壊はしない**(ROE を守る)。証明できれば十分です。

## 6. フェーズ6: 報告 — ここが本当の仕事

**ペンテストの成果物は「侵入した自慢話」ではなく「報告書」です。** どんなに華麗に侵入しても、依頼者が直せなければ価値はゼロ。報告書の質が、ペンテスターの評価を決めます。

### 良い報告書の構成

```
1. エグゼクティブサマリ(経営層向け・非技術)
   - 全体リスク評価、ビジネスへの影響、最優先で直すべきこと
   - 「技術用語ゼロで、役員が5分で理解できるか」が勝負

2. 発見事項一覧(重大度順)
   - 各脆弱性: 深刻度(CVSS)、影響、再現手順、証拠(スクショ)、修正案

3. 技術的詳細(エンジニア向け)
   - 攻撃の完全な再現手順(誰でも追試できるレベル)
   - 根本原因と、具体的な修正コード/設定

4. 付録: スコープ、方法論、使用ツール、タイムライン
```

### 各発見の書き方テンプレート

```markdown
## [High] SQL インジェクションによる認証バイパス

**深刻度**: High (CVSS 8.6)
**対象**: https://target/api/login

**概要**: ログイン API が入力を文字列連結で SQL に埋め込んでおり、
認証を回避して任意ユーザーとしてログインできる。

**影響**: 全ユーザーアカウントの乗っ取り、顧客データベース全体の窃取が可能。

**再現手順**:
1. ログイン画面で email 欄に `' OR 1=1--` を入力
2. 任意のパスワードで送信
3. 管理者としてログインが成立する(スクリーンショット参照)

**根本原因**: パラメータ化クエリを使わず文字列連結している(該当箇所: auth.js:42)。

**修正案**: プレースホルダを用いたパラメータ化クエリに変更する。
（コード例を添付）加えて DB ユーザーを最小権限にし、多層防御とする。
```

### CVSS で深刻度を客観化

**CVSS(Common Vulnerability Scoring System)** は脆弱性を 0.0〜10.0 で採点する国際標準(Lesson 01)。「攻撃の難易度」「必要な権限」「機密性/完全性/可用性への影響」などから算出します。主観的な「やばい」ではなく、共通言語で優先度を伝えられます。

## 7. 責任ある開示(Responsible Disclosure)

許可のない場所で偶然脆弱性を見つけたら? **悪用せず、静かに、正しく報告する**のがプロの作法です(詳細は Lesson 14)。勝手に公開したり、悪用したりすれば、あなたが加害者になります。

## 💡 コラム: 「入ってしまった」あと、どうするか — 二人のハッカーの分かれ道

セキュリティの世界には、技術力が同等でも、たった一つの選択で運命が正反対になった人々の物語が無数にあります。

2013年、あるセキュリティ研究者が Facebook に深刻な脆弱性を報告しましたが、担当者に軽視され、取り合ってもらえませんでした。彼はそれを証明するため、**その脆弱性を使ってマーク・ザッカーバーグ本人のタイムラインに投稿**してしまいます。脆弱性は本物だと即座に証明されましたが、彼のやり方は「スコープを越えて実際に悪用した」ものでした。結果、彼はバグバウンティの報奨を受け取れませんでした——技術は正しかったが、一線を越えたのです。一方、同じ穴を「再現手順の報告」だけに留めていれば、彼は報奨とともに賞賛を受けていたでしょう。

対照的な例もあります。ハッカーの **サンティアゴ・ロペス**(通称 try_to_hack)は、アルゼンチンの10代の若者でした。彼は YouTube の動画で独学し、バグバウンティのルール——**スコープを守り、悪用せず、報告する**——を徹底しました。1600以上の脆弱性を正しく報告し、19歳で**バグバウンティによる報奨総額100万ドル**を達成した世界初のハッカーになりました。同じ「侵入する技術」が、一方を報奨ゼロに、一方を億万長者にしたのです。

分かれ道はいつも同じ場所にあります。**「入れた」あと、証明に留めるか、踏み越えるか。** Lesson 11 の全技術は、この一線の手前で使うためのものです。侵入できることを示すのがあなたの仕事。踏み荒らすのは、あなたの仕事ではありません。ペンテスターとは、**入れる場所を見つけても、依頼された範囲で立ち止まれる自制心を持った人**のことなのです。

## まとめ

| 概念 | 要点 |
|------|------|
| ペンテスト | 許可を得た攻撃。弱点を「実際に悪用できる」ことで証明する |
| スコープ/ROE | 技術より先に契約。スコープ外に触れない絶対規範 |
| 方法論 | 偵察→列挙→攻略→権限昇格→横展開→報告(Kill Chain 対応) |
| 偵察 | 情報収集が9割。OSINT・Shodan・Google ドーキング |
| ツール | Burp/sqlmap/Metasploit/BloodHound を役割で使い分ける |
| 報告 | 最大の成果物。エグゼクティブサマリ + 再現手順 + CVSS + 修正案 |
| 開示 | 悪用せず正しく報告。踏み越えれば加害者になる |

---

## 確認問題

1. ペネトレーションテストと脆弱性スキャンの違いを、具体例で説明してください。
2. ペンテストで「技術より先に契約・スコープが重要」なのはなぜか説明してください。
3. パッシブ偵察とアクティブ偵察の違いと、それぞれの手法を1つずつ挙げてください。
4. 「ペンテストの成果物は侵入ではなく報告書だ」と言われる理由を説明してください。
5. 発見した脆弱性の深刻度を CVSS で表す利点を述べてください。
6. スコープ外で偶然脆弱性を見つけたとき、プロとして取るべき行動を説明してください。
