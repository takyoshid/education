# Lesson 01: 攻撃者の思考と脅威モデリング

## 学習目標

- 「作る」視点から「壊す」視点へと頭を切り替えられる(adversarial mindset)
- 攻撃面(attack surface)・信頼境界(trust boundary)を特定できる
- Cyber Kill Chain と MITRE ATT&CK の役割を説明できる
- STRIDE を使って設計段階で脅威を洗い出せる
- リスクを「起こりやすさ × 影響度」で優先度づけできる

---

## 1. なぜ「攻撃者の思考」から始めるのか

普通のエンジニアはこう考えます。「ユーザーがメールアドレスを入力する → 登録する」。
セキュリティエンジニアはこう考えます。「ユーザー**でない者**が、メールアドレス**でないもの**を入力したら?」

```
開発者の問い:  「どうすれば動くか?」    (happy path)
攻撃者の問い:  「どうすれば壊れるか?」  (unhappy path / abuse case)
```

この視点の転換が、このコース全体の土台です。良い設計者は仕様書(what it should do)を読みますが、優れたセキュリティエンジニアは**仕様書に書かれていないこと(what it must never do)**を読みます。

### 「悪用シナリオ(abuse case)」を書く習慣

ユーザーストーリー「ユーザーとして、パスワードをリセットしたい」に対して、攻撃者ストーリーを併記します。

| ユーザーストーリー | 悪用シナリオ(abuse case) |
|---|---|
| 自分のパスワードをリセットしたい | **他人の**パスワードをリセットしたい |
| メールでリセットリンクを受け取りたい | リンクのトークンを**推測・総当たり**したい |
| 新しいパスワードを設定したい | リセット後に**元の所有者を締め出したい** |

この一手間で、設計レビューの質が劇的に変わります。

## 2. 攻撃面(Attack Surface)を可視化する

**攻撃面**とは、攻撃者が入力を送り込める、あるいは相互作用できるすべての点の集合です。攻撃面が広いほど、守るべき場所が増えます。

典型的な Web サービスの攻撃面:

```
外部からの入力(すべて「信用できない」と見なす)
├── HTTP リクエスト(URL, クエリ, ヘッダ, Cookie, ボディ)
├── ファイルアップロード
├── WebSocket / API エンドポイント
├── サードパーティ Webhook(決済・OAuth コールバック)
├── DNS / メール(SPF, DKIM を悪用した偽装)
└── 依存パッケージ(npm/pip 経由の悪意あるコード)

内部の攻撃面(侵入後の横展開に使われる)
├── 管理画面 / デバッグエンドポイント(/actuator, /debug)
├── 内部 API・サービス間通信
├── データベース・キャッシュ・メッセージキュー
├── クラウドメタデータ(169.254.169.254 ← SSRF の標的)
└── CI/CD パイプライン・シークレット
```

### 信頼境界(Trust Boundary)

データが「信用できない領域」から「信用できる領域」へ渡る線を **信頼境界** と呼びます。**検証はこの境界で行う**のが鉄則です。

```
[ブラウザ] --信頼境界--> [Web サーバ] --信頼境界--> [DB]
   信用しない              ここで検証            パラメータ化で守る
```

クライアント側の JavaScript バリデーションは「UX のための親切」であって「セキュリティ」ではありません。攻撃者はブラウザを使わず、`curl` で直接サーバを叩くからです。**サーバ側で必ず再検証する。**

## 3. 攻撃の全体像を掴む2つの地図

### Cyber Kill Chain(攻撃の時系列モデル)

Lockheed Martin が提唱した、攻撃を7段階に分けたモデル。「攻撃はどの順で進むか」を教えてくれます。

```
1. 偵察(Reconnaissance)     — 標的を調べる(Google, SNS, ポートスキャン)
2. 武器化(Weaponization)     — 攻撃ツール/マルウェアを準備
3. 配送(Delivery)           — メール/USB/Web でペイロードを届ける
4. 攻略(Exploitation)        — 脆弱性を突いてコード実行
5. インストール(Installation) — バックドアを設置し居座る
6. C2(Command & Control)     — 遠隔操作の通信路を確立
7. 目的の実行(Actions)        — データ窃取・破壊・身代金要求
```

**防御の含意**: 攻撃者は全段階を成功させる必要がありますが、**防御側はどれか1段階を断ち切れば勝てる**。これが「多層防御(Defense in Depth)」の理論的根拠です。

### MITRE ATT&CK(攻撃手法の百科事典)

Kill Chain が「順序」なら、ATT&CK は「**実際に観測された攻撃手法のカタログ**」です。「Tactics(戦術=なぜ)」と「Techniques(技術=どうやって)」のマトリクスで、現実の攻撃者(APT グループ)がどんな手を使うかを網羅しています。

| Tactic(目的) | Technique の例 |
|---|---|
| Initial Access(初期侵入) | フィッシング、公開アプリの脆弱性 |
| Execution(実行) | PowerShell、スケジュールタスク |
| Persistence(永続化) | 起動スクリプト改ざん、新規アカウント作成 |
| Privilege Escalation(権限昇格) | sudo 悪用、トークン窃取 |
| Defense Evasion(回避) | ログ削除、正規プロセスへの偽装 |
| Credential Access(認証情報窃取) | メモリダンプ、キーロガー |
| Lateral Movement(横展開) | SSH/RDP、Pass-the-Hash |
| Exfiltration(持ち出し) | 暗号化して外部へ送信 |

**使い方**: 防御側は「自分たちは ATT&CK のどの技術を検知/防御できているか」をマップ化して、穴を見つけます(これを検知エンジニアリングと呼び、Lesson 10 で扱います)。

## 4. STRIDE — 設計段階で脅威を洗い出す

事故が起きてから直すのは高くつきます。**設計図の段階で脅威を見つける**のが脅威モデリングです。マイクロソフトが考案した **STRIDE** は、6種類の脅威の頭文字です。

| 文字 | 脅威 | 意味 | 破られる性質 | 主な対策 |
|---|---|---|---|---|
| **S** | Spoofing(なりすまし) | 他人を騙る | 認証(Authentication) | 強力な認証・MFA |
| **T** | Tampering(改ざん) | データを書き換える | 完全性(Integrity) | 署名・ハッシュ・入力検証 |
| **R** | Repudiation(否認) | 「やっていない」と嘘 | 否認防止(Non-repudiation) | 監査ログ・署名 |
| **I** | Information Disclosure(情報漏洩) | 見えてはいけない情報が漏れる | 機密性(Confidentiality) | 暗号化・アクセス制御 |
| **D** | Denial of Service(サービス妨害) | 使えなくする | 可用性(Availability) | レート制限・冗長化 |
| **E** | Elevation of Privilege(権限昇格) | 権限を不正に上げる | 認可(Authorization) | 最小権限・認可チェック |

STRIDE は、有名なセキュリティの三大原則 **CIA(Confidentiality / Integrity / Availability)** を、攻撃側の言葉に翻訳したものだと考えると腑に落ちます。

### 脅威モデリングの実践4ステップ

Adam Shostack の「4つの問い」が最もシンプルで実用的です。

```
1. 何を作っているのか?     → データフロー図(DFD)を描く
2. 何がうまくいかないか?   → 各要素に STRIDE を当てる
3. それにどう対処するか?   → 対策を決める(緩和/移転/受容/回避)
4. ちゃんとできたか?       → レビューして検証する
```

### データフロー図(DFD)の例

シンプルなログイン機能を図にします。

```
  [ユーザー] ──(1) ログイン要求──> ((Web API)) ──(2) 認証照会──> [DB]
      ↑                              │
      └──────(4) セッション ─────────┘
                                     │
                              信頼境界(外部↔内部)
```

各データフロー(矢印)とプロセス(丸)に STRIDE を当てます。

| 要素 | 脅威(STRIDE) | 対策 |
|---|---|---|
| (1) ログイン要求 | **S**: 総当たり/クレデンシャルスタッフィング | レート制限・MFA・アカウントロック |
| (1) ログイン要求 | **T**: パラメータ改ざん | サーバ側検証・パラメータ化クエリ |
| (2) 認証照会 | **I**: SQL インジェクションで DB 全窃取 | プレースホルダ・最小権限の DB ユーザー |
| (4) セッション | **S**: セッションハイジャック | Secure/HttpOnly Cookie・短い有効期限 |
| ((Web API)) | **D**: 大量リクエストでダウン | レート制限・WAF・オートスケール |
| ((Web API)) | **R**: 「ログインしていない」と否認 | 認証イベントの監査ログ |

これを設計時にやるだけで、Lesson 03〜04 で学ぶ攻撃の多くは**そもそも作り込まれなくなります**。

## 5. リスクの優先度づけ

脅威を全部同時には直せません。**リスク = 起こりやすさ(Likelihood) × 影響度(Impact)** で優先順位をつけます。

```
影響度
 高 │  中     高     致命
    │
 中 │  低     中      高
    │
 低 │  低     低      中
    └──────────────────────
       低      中      高    起こりやすさ
```

- **致命(赤)**: 今すぐ直す。リリースを止めてでも
- **中(黄)**: 計画的に直す。次スプリント
- **低(緑)**: 記録して受容 or 後回し

業界標準の **CVSS(Common Vulnerability Scoring System)** は、この考えを 0.0〜10.0 のスコアに定式化したものです(Lesson 09・総仕上げプロジェクトで使います)。「攻撃の難易度」「必要な権限」「機密性/完全性/可用性への影響」などから算出します。

### リスクへの4つの対応

| 対応 | 意味 | 例 |
|---|---|---|
| 緩和(Mitigate) | 対策を打って下げる | WAF 導入、コード修正 |
| 移転(Transfer) | 他者に肩代わりさせる | サイバー保険、マネージドサービス |
| 受容(Accept) | リスクを承知で受け入れる | 影響が軽微で対策コストが見合わない |
| 回避(Avoid) | そもそもやめる | 危険な機能を実装しない |

「すべてのリスクをゼロにする」は不可能かつ不経済です。**どこにリソースを集中するかを決める**のがセキュリティエンジニアの仕事です。

## 💡 コラム: 一線を越えなかったハッカー — ケビン・ミトニックの転身

1990年代、FBI に「最重要指名手配」されたハッカーがいました。**ケビン・ミトニック**。彼が使った最強の武器は高度なエクスプロイトではなく、**ソーシャルエンジニアリング** — 電話一本で社員を信じ込ませ、パスワードを聞き出す話術でした。「システムで最も脆弱なのは、キーボードと椅子の間に座っている人間だ」という彼の言葉は、今もセキュリティの真理を突いています。

逮捕・服役の後、彼は**ホワイトハット(善玉)側に転向**し、世界的なセキュリティコンサルタントになりました。攻撃者の思考を知り尽くした者こそ、最強の防御者になれる——彼のキャリアはそれを体現しています。

ここに、このコース全体を貫く原則があります。**攻撃技術を学ぶことと、それを悪用することの間には、越えてはならない一線がある。** ミトニックの前半生と後半生を分けたのはこの一線でした。あなたが学ぶ技術は、許可された環境で人々を守るためだけに使ってください。技術に善悪はありませんが、**それを使うあなたには責任があります。**

## 🌟 コラム: 電脳をハックされる時代 — 攻殻機動隊が描いた「究極の攻撃面」

ミトニックは「システムで最も脆弱なのは、キーボードと椅子の間に座っている人間だ」と言いました。この言葉を、フィクションが極限まで突き詰めた作品があります。士郎正宗の『**攻殻機動隊(GHOST IN THE SHELL)**』です。

その世界では、人々の脳が電子化され(**電脳**)、直接ネットワークに接続されています。便利さと引き換えに、**人間の脳そのものが攻撃面(attack surface)** になりました。作中で描かれる「**ゴーストハック**」——他人の電脳に侵入し、知覚や記憶を書き換える攻撃——は、まさにミトニックの言葉の究極形です。ある登場人物は、独身であるにもかかわらず「妻と娘がいる」という**偽の記憶を植え付けられ**、それを心から信じたまま、知らずに攻撃の道具として操られます。彼にとってその記憶は完全に「本物」でした。だからこそ、疑うことすらできない。

この物語が、このレッスンの核心を突いています。**攻撃者は「システムが想定していないこと」を狙う**、と学びました(§1)。攻殻機動隊が問いかけるのは、その究極版です——「**あなたが今『事実だ』と信じているものは、本当に検証されたものか?**」。自分の記憶さえ疑う、この徹底した猜疑心こそ、脅威モデリングで abuse case を書くときの姿勢そのものです。STRIDE で言えば、なりすまし(Spoofing)と改ざん(Tampering)が、データではなく**人間の認識そのもの**に対して行われる世界。

攻殻機動隊は1989年の作品ですが、SNS の偽情報、ディープフェイク、フィッシングで「信じ込まされる」現代の私たちは、すでにその入り口に立っています。**最強の暗号も最新のファイアウォールも、人間が「信じてしまう」隙は守れない。** だからこのコースは、技術と同じ重さで「疑う力」を鍛えます。素子(モトコ)がネットの海に潜るように、あなたも「当たり前」の裏側を覗く目を持ってください。

## まとめ

| 概念 | 要点 |
|---|---|
| 攻撃者の思考 | 「どう動くか」ではなく「どう壊れるか」。悪用シナリオを書く |
| 攻撃面 | 入力を送れる全地点。狭く保つほど守りやすい |
| 信頼境界 | 信用できない領域から入るデータは、境界で必ず検証する |
| Kill Chain | 攻撃の時系列。防御はどこか1段を断てば勝つ(多層防御) |
| MITRE ATT&CK | 現実の攻撃手法のカタログ。防御の穴の可視化に使う |
| STRIDE | 設計段階の脅威洗い出し。CIA + 認証/否認防止 の裏返し |
| リスク優先度 | 起こりやすさ × 影響度。CVSS で定量化。緩和/移転/受容/回避 |

## 確認問題

1. あなたが作ったパスワードリセット機能について、悪用シナリオ(abuse case)を3つ挙げてください。
2. 「クライアント側でバリデーションしているから安全」という主張のどこが誤りか、信頼境界の概念を使って説明してください。
3. Cyber Kill Chain と MITRE ATT&CK の役割の違いを、それぞれ一言で説明してください。
4. あなたが最近作った(または本編で作った)アプリのログイン機能について、DFD を描き、少なくとも4つの脅威を STRIDE で分類し、対策を挙げてください。
5. 「影響は甚大だが、悪用は極めて困難」な脆弱性が見つかりました。あなたはリスク対応として何を選び、なぜそう判断しますか。
