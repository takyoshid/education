# Lesson 00: ラボ環境を作る — 安全に暴れられる自分専用の実験場

## 学習目標

- なぜ攻撃練習に「隔離された環境」が必須なのかを理解する
- 攻撃側マシンとやられ役マシンを分離したラボを構築する
- やられ役アプリ(Juice Shop / DVWA)を起動する
- プロキシツール(Burp Suite / mitmproxy)で通信を傍受・改ざんできる
- 倫理と合法性の一線を、具体的なルールとして自分の中に持つ

---

## 0. なぜ最初に「環境」なのか

料理を学ぶとき、最初にやるのは包丁の握り方ではなく、**清潔で安全な調理台を用意すること**です。セキュリティも同じ。攻撃技術を学ぶ前に、**周囲を傷つけずに安全に練習できる場所**を作ります。これは面倒な前置きではなく、プロの第一歩そのものです。

この Lesson を終えると、あなたは「自分のマシンの中に閉じた、外に一切影響しない攻撃の遊び場」を持つことになります。

---

## 1. 倫理と合法性 — 技術より先に、これを身体に刻む

もう一度、いちばん大切なことを書きます。

> **許可のない攻撃は犯罪です。** あなたが攻撃してよいのは、(1) 自分が所有するシステム、(2) 書面で明示的な許可を得たシステム、(3) 学習用に用意された練習環境(このコースのやられ役アプリ、CTF、TryHackMe/Hack The Box などの合法サービス)だけです。

日本では **不正アクセス禁止法** により、他人の ID/パスワードでのログインや、脆弱性を突いた不正アクセスは処罰対象です。「試しにちょっと」「バレないだろう」は通用しません。米国の **CFAA(Computer Fraud and Abuse Act)** など、各国に同様の法律があります。

プロの世界では、この規律こそが信頼の源です。技術が高くても一線を越える人間は、業界から永久に排除されます。逆に、この一線を守り抜く人は、企業から「攻撃を任せられる数少ない人材」として重宝されます。

### 3つの黄金ルール

```
ルール1: 許可のない標的には、スキャン一つ・パケット一つ送らない
ルール2: やられ役アプリは絶対にインターネットに公開しない
ルール3: 実在の脆弱性を見つけたら「悪用」ではなく「報告」する(責任ある開示)
```

このコースの実習はすべて、あなたのマシンの中で完結します。外の世界には一切触れません。

## 2. ラボの全体像 — なぜ「分ける」のか

理想のラボは、**攻撃する側**と**攻撃される側**を別々のマシン(仮想マシン)に分け、両者を**外部から隔離されたネットワーク**でつなぎます。

```
       あなたのPC(ホスト)
   ┌───────────────────────────────────┐
   │  ┌──────────┐      ┌────────────┐  │
   │  │ 攻撃側VM  │─────>│ やられ役VM  │  │
   │  │ (Kali等) │      │ (脆弱アプリ)│  │
   │  └──────────┘      └────────────┘  │
   │        └── ホストオンリー網 ──┘      │
   │         (インターネットに出ない)      │
   └───────────────────────────────────┘
              ✗ 外部ネットワークへ出られない
```

**なぜ分けるのか**、理論を丁寧に説明します。

1. **事故の封じ込め**: 脆弱アプリはわざと穴だらけです。もしインターネットに面していると、あなたの練習中に**本物の攻撃者に乗っ取られ、踏み台にされる**危険があります。隔離すれば、最悪アプリが壊れても外に被害が及びません。
2. **現実の再現**: 実務のペネトレーションテストは「攻撃者のマシンから、標的のネットワークへ」という構図です。分離ラボはこの構図をそのまま学べます。
3. **後始末が楽**: VM やコンテナは、壊れたら破棄して作り直すだけ。ホスト OS を汚しません。

初学者はまず **Docker で手軽に**始め、慣れたら VM 分離型に発展させるのが現実的です。両方紹介します。

### 結論: まずは Docker を使うのがおすすめ

このコースの実習の**9割は Docker だけで完結します**。特別な理由がない限り、環境構築は Docker で始めてください。理由を整理します。

| 観点 | Docker(コンテナ) | 仮想マシン(VM) |
|------|------------------|----------------|
| 起動の速さ | 数秒。`docker run` 一発 | 数分。OS ごと起動 |
| 容量 | 数百 MB〜 | 数 GB〜数十 GB |
| 後始末 | `--rm` で自動消滅。汚さない | スナップショット管理が必要 |
| 再現性 | 誰の環境でも同じ状態(イメージ配布) | 手動セットアップになりがち |
| 学習コスト | Docker の基本コマンドだけ | 仮想化ソフト + Linux 運用の知識 |
| 向く用途 | Web アプリ攻防・やられ役アプリ(Lesson 04〜08 の主戦場) | OS/ネットワーク層・権限昇格・完全な隔離(Lesson 09・11) |

**判断の目安**:

- **Lesson 00〜08(Web 攻防が中心)** → Docker で十分。むしろ Docker が最適。やられ役アプリを `docker run` するだけで始められ、壊しても `--rm` で一瞬でリセットできます。
- **Lesson 09(OS・権限昇格)・Lesson 11(ペネトレーションテスト実践)** → より現実に近い OS/ネットワーク層を触るため、Kali Linux などの **VM 分離型**が学びが深いです(本 Lesson の「5. 発展」で解説)。ただし Docker でも代替可能。

> ⚠️ **Docker の隔離は VM より“薄い”ことは知っておく**: コンテナはホスト OS のカーネルを共有します(VM は OS ごと分離)。つまりコンテナ脱獄(container escape)という攻撃が理論上あり得ます(Lesson 10 で扱います)。**信用できないイメージを `--privileged` で動かさない**、公開ポートは `127.0.0.1:` で縛る、といった基本を守れば、学習用途では Docker で十分安全です。逆に「未知の本物のマルウェアを解析する」ような場面では、カーネルまで分離される VM(できれば専用の隔離マシン)を使うのが定石です。

まとめると——**このコースは Docker を第一選択にして始め、OS 層を深掘りする段階で VM を足す**、が最も効率的です。次節でまず Docker のやられ役アプリを起動しましょう。

## 3. 最短ルート: Docker でやられ役アプリを起動

まず Docker がなければ [Docker Desktop](https://docs.docker.com/get-docker/) を入れてください。確認:

```bash
docker --version
```

### OWASP Juice Shop(このコースの主役)

**Juice Shop** は OWASP が公式に提供する、意図的に脆弱な現代的 Web アプリ(ジュース通販サイト風)です。SQLi・XSS・認可不備など、実在する脆弱性が**ゲームの挑戦課題**として仕込まれています。世界中の研修・CTF で使われる定番です。

```bash
docker run --rm -p 127.0.0.1:3000:3000 bkimminich/juice-shop
```

- `--rm`: コンテナ終了時に自動削除(汚さない)
- `-p 127.0.0.1:3000:3000`: **ここが重要**。`127.0.0.1:` を付けることで、ポート 3000 を**自分のマシンからしかアクセスできない**ように縛ります。`-p 3000:3000` だと LAN 内の他端末からも見えてしまう場合があります。

ブラウザで `http://localhost:3000` を開いてジュースショップが表示されれば成功です。

### DVWA(Damn Vulnerable Web Application)

難易度を Low/Medium/High と切り替えられる古典的なやられ役アプリ。SQLi やコマンドインジェクションの「段階的な難化」を体験するのに最適です。

```bash
docker run --rm -p 127.0.0.1:8080:80 vulnerables/web-dvwa
# http://localhost:8080  (初期ログイン admin / password、DB セットアップを実行)
```

> 🧪 これらのアプリは**穴だらけ**です。`127.0.0.1:` でローカル限定にし、使い終わったら停止(`Ctrl+C` または `docker stop`)しましょう。公共 Wi-Fi 下では特に注意。

## 4. 通信を「傍受・改ざん」する — プロキシツール

セキュリティの実習で最も使う道具が **傍受プロキシ(intercepting proxy)** です。

### なぜプロキシが必要か(理論)

ブラウザとサーバの間に自分を割り込ませ、**通信を一時停止して中身を書き換えてから送る**ためです。攻撃者はブラウザの画面ではなく、その裏で飛ぶ生の HTTP リクエストを操作します。

```
通常:   [ブラウザ] ───────────────> [サーバ]

プロキシ経由:
        [ブラウザ] ──> [プロキシ] ──> [サーバ]
                        ↑ ここで一時停止し、
                          パラメータを書き換えられる
```

例えば画面上のフォームで「数量: 1」しか選べなくても、プロキシで `quantity=1` を `quantity=-1` に書き換えて送れば、サーバがマイナス値をどう扱うか試せます。**クライアント側の制限は、攻撃者には存在しないも同然**——これを体感するのが第一歩です。

### 選択肢A: mitmproxy(軽量・無料・CLI/Web UI)

```bash
pip install mitmproxy
mitmweb          # ブラウザ UI 版(http://127.0.0.1:8081 で操作)。CLI 版は mitmproxy
```

ブラウザのプロキシ設定を `127.0.0.1:8080`(mitmproxy の既定)に向けます。HTTPS を復号するには、`http://mitm.it` にアクセスして mitmproxy の CA 証明書をインストールします。

> **なぜ CA 証明書を入れるのか**: HTTPS は暗号化されているため、そのままではプロキシも中身を読めません。mitmproxy は「その場で偽の証明書を作ってブラウザに見せる」ことで復号します。ブラウザにこの偽証明書を信頼させるのが CA インストールです。**これは本質的に中間者攻撃(MITM)そのもの**——だからこそ、自分のマシン以外で絶対にやってはいけません(Lesson 03 で原理を深掘りします)。

### 選択肢B: Burp Suite Community Edition(業界標準)

プロのペンテスターが最も使うツール。[公式サイト](https://portswigger.net/burp)から無料版をダウンロード。

- **Proxy**: リクエストの傍受・改ざん
- **Repeater**: 同じリクエストを何度も微修正して送る(手動テストの主力)
- **Intruder**: パラメータの総当たり(Community 版は速度制限あり)
- **Decoder/Comparer**: エンコード変換・差分比較

このコースでは mitmproxy と Burp のどちらでも進められますが、**将来の実務では Burp が事実上の標準**なので、早めに慣れておくと有利です。

### 動作確認(ハンズオン)

1. プロキシを起動する
2. ブラウザ(専用プロファイル推奨)のプロキシを起動したプロキシに向ける
3. Juice Shop でログインを試す
4. プロキシに `POST /rest/user/login` が流れてくるのを確認する
5. リクエストボディの `email` / `password` が生で見えることを確認する

これが見えたら、あなたはもう「画面の裏側」に立っています。

## 5. 発展: VM 分離型ラボ(慣れてきたら)

より現実に近い環境が欲しくなったら、仮想化ソフト([VirtualBox](https://www.virtualbox.org/) は無料)で以下を構築します。

- **攻撃側 VM**: [Kali Linux](https://www.kali.org/)(nmap, Burp, Metasploit, sqlmap などが最初から入ったペンテスト用ディストリ)
- **やられ役 VM**: [Metasploitable 2/3](https://docs.rapid7.com/metasploit/metasploitable-2/)(意図的に脆弱な Linux サーバ) や、上記の Juice Shop を別 VM で
- **ネットワーク**: VirtualBox の「ホストオンリーアダプター」で両 VM をつなぐ。**NAT/ブリッジは使わない**(外に出さないため)

```
攻撃側(Kali)  eth0: 192.168.56.10  ─┐
                                    ├─ ホストオンリー網 192.168.56.0/24
やられ役       eth0: 192.168.56.20  ─┘   (インターネット非接続)
```

この構成なら、Lesson 11 のペネトレーションテスト実践(nmap でスキャン → 脆弱性を突く → 権限昇格)を、実務さながらに練習できます。

## 6. スナップショットを取る習慣

VM を使うなら、**きれいな初期状態でスナップショット**を取っておきましょう。攻撃で壊しても一瞬で元に戻せます。Docker なら `--rm` で毎回新品、あるいはイメージを再 `run` するだけ。

「壊すのが怖くて手が止まる」のが初学者最大の壁です。**いつでも戻せる**という安心が、大胆な実験を可能にします。

## 💡 コラム: 世界を止めかけた「モリスワーム」と、境界線の物語

1988年11月、コーネル大学の大学院生 **ロバート・タッパン・モリス** は、インターネットの規模を測るための実験プログラムを放ちました。しかし増殖速度の設定を誤り、そのプログラム(後に「**モリスワーム**」と呼ばれる史上初の大規模ワーム)は当時のインターネットの約1割にあたる数千台のマシンを次々に感染させ、**ネットワークを事実上麻痺させました**。

彼に破壊の意図はなかったとされます。それでもモリスは、CFAA(コンピュータ不正行為防止法)で有罪となった**最初の人物**になりました。皮肉なことに、彼の父は国家安全保障局(NSA)の著名なコンピュータ科学者でした。

この事件が生んだものは処罰だけではありません。インターネットのインシデント対応を担う世界初の組織 **CERT(Computer Emergency Response Team)** が、この直後に設立されました。今日あなたが恩恵を受けるセキュリティ対応体制の原点は、ここにあります。

そしてモリス自身は後に MIT の教授となり、著名なスタートアップ投資家にもなりました。彼の物語が教えるのは残酷なほど明快な教訓です——**「意図が善良でも、許可なく他人のシステムに影響を与えれば、それは罪になる」**。あなたがこの Lesson でラボを隔離するのは、この一線を、指が覚えるまで習慣にするためです。

## まとめ

| 項目 | 要点 |
|------|------|
| 倫理 | 許可のない攻撃は犯罪。標的は「自分/許可済み/練習環境」だけ |
| 隔離 | やられ役アプリは `127.0.0.1` 限定 or ホストオンリー網。外に出さない |
| やられ役 | Juice Shop(主役)・DVWA。Docker で即起動 |
| プロキシ | mitmproxy か Burp。通信を止めて改ざんするのが実習の基本動作 |
| 復元 | Docker `--rm` / VM スナップショット。壊してもすぐ戻せる安心 |

## 確認問題

1. `docker run -p 3000:3000` と `docker run -p 127.0.0.1:3000:3000` の違いを、セキュリティの観点から説明してください。
2. 傍受プロキシが「クライアント側のバリデーションを無意味にする」とはどういうことか、具体例で説明してください。
3. mitmproxy で HTTPS の中身を読むために CA 証明書をインストールする行為が、本質的に何と同じか答えてください。それを自分のマシン以外でやってはいけない理由も述べてください。
4. あなたが練習環境を作るとき、「外部ネットワークに出さない」ためにどんな設定をしますか(Docker と VM の両方で)。
5. モリスワームの事件から、エンジニアとして何を教訓にすべきか、あなたの言葉で書いてください。
