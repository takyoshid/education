# 総仕上げプロジェクト: セキュリティ診断レポート

## 概要

このコースの集大成。意図的に脆弱な Web アプリを対象に、**実務のペネトレーションテストと同じ流れ**で診断し、プロ品質の報告書を作る。完成した報告書は、そのまま**転職・バグバウンティのポートフォリオ**になる。

> ⚠️ 対象は必ず **自分のローカルに立てた脆弱アプリ、または合法的な練習環境**(Lesson 00 の隔離原則)。実在サービスへの無許可診断は犯罪。

---

## 目標

コースで学んだすべて(Lesson 00〜14)を一つの成果物に統合する。

- 脅威モデリング(Lesson 01)から始め
- Web 攻防(Lesson 04〜08)で実際に脆弱性を突き
- 発見を CVSS で評価し(Lesson 11)
- 修正案を設計し(全 Lesson)
- ブルーチーム視点の検知・防止も提案する(Lesson 12〜13)
- 責任ある態度で(Lesson 14)報告書にまとめる

## 進め方(4フェーズ)

### フェーズ1: 計画と偵察(Lesson 01, 11)
- [ ] 対象を決め、スコープ(何を対象/対象外にするか)を明記
- [ ] 対象の脅威モデル(DFD + STRIDE)を作成
- [ ] 偵察・列挙(ディレクトリ探索・技術スタック特定・隠しファイル)

### フェーズ2: 脆弱性の発見と悪用(Lesson 04〜09)
- [ ] **最低6件**の脆弱性を発見し、実際に悪用して証明する
- [ ] 最低でも次のカテゴリを網羅: インジェクション / XSS / 認証・認可(IDOR等) / アクセス制御 / 設定・情報露出 / ビジネスロジック
- [ ] 各件、Burp/mitmproxy でリクエストを記録し、再現手順と証拠を残す

### フェーズ3: 評価と修正設計(Lesson 11, 13)
- [ ] 各脆弱性に CVSS スコアを算出([計算機](https://www.first.org/cvss/calculator/3.1))
- [ ] 各件の根本原因を特定し、具体的な修正コード/設定を書く
- [ ] 組織的改善(SDLC・自動検査・検知)を提案

### フェーズ4: 報告書の作成(Lesson 11, 12, 14)
- [ ] 下記フォーマットで報告書を完成
- [ ] エグゼクティブサマリを非エンジニアに読んでもらい、伝わるか検証
- [ ] GitHub に公開(ポートフォリオ化)

## 提出物: 報告書の構成

```markdown
# セキュリティ診断報告書: <対象アプリ名>

## 1. エグゼクティブサマリ(非技術)
   - 目的・スコープ / 全体リスク / 深刻度別件数 / 最優先の推奨 TOP3

## 2. スコープと方法論
   - 対象・条件・Rules of Engagement(学習環境である旨)
   - 準拠方法論(OWASP/PTES)・使用ツール

## 3. 脅威モデル(任意だが加点)
   - DFD + STRIDE の要約

## 4. 発見事項(重大度順に6件以上)
   各件:
   - タイトル / 深刻度 + CVSS ベクトル
   - 概要 / 影響
   - 再現手順(追試可能に)
   - 証拠
   - 根本原因(該当箇所)
   - 修正案(コード/設定)

## 5. 防御側の提案(ブルーチーム視点)
   - 検知ルール・ログ・監視・DevSecOps での予防

## 6. まとめと組織的推奨

## 付録: タイムライン・参考(OWASP/CWE/CVSS)
```

## 評価ルーブリック

| 観点 | 不十分 | 良い | 優秀 |
|------|--------|------|------|
| 発見数と多様性 | 3件未満 | 6件・複数カテゴリ | 8件+・全カテゴリ網羅 |
| 再現性 | 手順が曖昧 | 追試可能 | 誰でも即再現できる |
| 根本原因の理解 | 表面的 | 原因を特定 | 設計レベルで説明 |
| 修正案 | 「気をつける」 | 具体的な対策 | コード + 多層防御 |
| CVSS | なし | スコアあり | ベクトルの根拠が妥当 |
| エグゼクティブサマリ | 専門用語だらけ | 概ね平易 | 非エンジニアに完全に伝わる |
| 防御提案 | なし | 検知案あり | 予防〜検知〜対応を横断 |
