# 模範解答/ヒント 04: Juice Shop 攻略

> Juice Shop は「自分で見つける」ことに価値がある。ここでは**考え方のヒント**と、詰まったときの方向性を示す。答えを丸写しせず、必ず自分の手で再現・記録すること。

## 1. SQLi でログイン突破

- ヒント: ログインの email 欄。Lesson 05 の `' OR 1=1--`。
- 観察: Burp で `POST /rest/user/login` を捕捉し、email に注入すると、認証を回避して最初のユーザー(管理者 `admin@juice-sh.op`)としてログインできる。
- 根本原因: email をパラメータ化せず連結。修正: プレースホルダ + 入力検証。

## 2. IDOR(認可不備)

- ヒント: バスケット(basket)の ID を変えてみる。ログイン後、自分の basket ID を別の数値に変えて API を叩く。
- 観察: 他ユーザーの basket 内容が見える/操作できる。
- 根本原因: 「その basket がログインユーザーのものか」を検証していない。修正: 所有者チェック。

## 3. XSS

- ヒント: 検索欄(DOM 型)や、一部の入力フィールド。`<iframe src="javascript:alert(\`xss\`)">` 等。
- 観察: 入力がエスケープされず DOM に反映され、スクリプトが実行される。
- 根本原因: 出力エスケープ不足。修正: フレームワークの自動エスケープ + CSP。

## 4. アクセス制御(管理画面)

- ヒント: クライアント側の JS(main.js)を読むと、ルーティングに `administration` パスが見つかる。`/#/administration` へ直接アクセス。
- 観察: 管理者以外でも到達できてしまう / ロールチェックがクライアント頼み。
- 根本原因: 認可をサーバ側で強制していない。修正: サーバ側でロール検証。

## 5. 機密情報の露出(偵察)

- ヒント: `/ftp` ディレクトリ、`robots.txt`、レスポンスヘッダ、JS 内のコメント。Lesson 11 の列挙。
- 観察: 隠しファイルや過剰な情報が公開されている。
- 修正: 不要なファイルを公開しない・ディレクトリリスティング無効化。

## 6. ビジネスロジック

- ヒント: 数量にマイナス値、クーポンの再利用、他人宛の注文。Burp でパラメータを改ざん。
- 観察: 画面では選べない値をプロキシで送ると、サーバが検証せず受理する。
- 根本原因: サーバ側のビジネスルール検証不足(Lesson 01 の abuse case)。

## 記録の型(再掲)

各件、**発見の経緯 → 攻撃手順 → 証拠 → 根本原因 → 修正案**を必ず書く。攻略の達成(スコアボード)は入口。**「なぜ・どう直す」を書けて初めて演習完了**。
