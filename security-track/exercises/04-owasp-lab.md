# 演習 04: OWASP Juice Shop 攻略チャレンジ

対応 Lesson: [04](../lessons/04-browser-security-model.md)〜[08](../lessons/08-ssrf-deserialization.md)

## 目的

実際のやられ役アプリで、複数カテゴリの脆弱性を「攻撃 → 理解 → 修正案」まで通しで実践する。Web 攻防の総合演習。

## 準備(Lesson 00)

```bash
docker run --rm -p 127.0.0.1:3000:3000 bkimminich/juice-shop
# http://localhost:3000 にアクセス
```

Burp Suite または mitmproxy を併用すること。Juice Shop には「スコアボード」(`/#/score-board`)があり、各課題の達成が記録される。

## 課題

以下の各カテゴリで**最低1つずつ**、脆弱性を実際に攻略し、記録せよ。

| # | カテゴリ | 課題例(Juice Shop) | 対応 Lesson |
|---|---------|---------------------|-------------|
| 1 | SQLi | ログインを SQL インジェクションで突破 | 05 |
| 2 | 認証/認可(IDOR) | 他ユーザーのバスケット/データにアクセス | 07 |
| 3 | XSS | 反射型または DOM 型 XSS を成立させる | 06 |
| 4 | アクセス制御 | 管理者ページ(admin section)を見つけて入る | 07 |
| 5 | 機密情報の露出 | 隠されたファイル/情報を発見(偵察) | 11 |
| 6 | ビジネスロジック | 数量にマイナス値、値引きの悪用など | 01/08 |

### 各課題で記録すること(1件ごと)

```markdown
## [カテゴリ] 課題名
- 発見の経緯(どう気づいたか): 
- 攻撃手順(再現可能に): 
- 使ったツール(Burp のどの機能等): 
- 証拠(レスポンス/スクショの説明): 
- 根本原因(なぜ脆弱か): 
- 修正案(具体的なコード/設定): 
```

### レベル別

- **レベル1**: 上記から3カテゴリを攻略
- **レベル2**: 6カテゴリすべてを攻略
- **レベル3**: 攻略した脆弱性のうち1つを選び、Lesson 11 の報告書フォーマット(CVSS 付き)で1件フル報告書を書く

## ルール

- **必ずローカルの Juice Shop に対してのみ**行うこと(Lesson 00 の隔離原則)
- 「解けた」で終わらず、必ず「なぜ脆弱か・どう直すか」まで書く。攻略はゴールではなく理解の入口

## 評価の観点

- 攻撃を再現可能な手順で記述できているか
- 攻略だけでなく根本原因と修正案を言語化できているか
- Burp/mitmproxy を実際に使ってリクエストを操作したか
