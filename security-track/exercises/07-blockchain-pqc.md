# 演習 07: ブロックチェーンの署名検証 & 耐量子暗号ハンズオン

対応 Lesson: [02](../lessons/02-applied-cryptography.md)(§5 公開鍵・§6 署名・§8 ビットコイン・§9 量子/PQC)

## 目的

暗号を「読む」から「動かす」へ。ビットコインが使う **ECDSA(secp256k1)** の署名検証と、改ざん不可能な**ハッシュ連結**を自分で実装し、さらに **耐量子暗号(PQC)** を実際に走らせて、古典暗号との違いを体感する。

## 準備

```bash
pip install cryptography          # ECDSA / SHA-256(Part A。コース既定の依存)
# Part B(PQC)は Open Quantum Safe の Python バインディング
pip install liboqs-python         # import oqs で使う。ビルドに時間がかかる場合あり
# ↑ 入らない環境では Part B はコードを読んで理解するだけでも可(解答に出力例あり)
```

## Part A: ブロックチェーンの心臓を実装する

### レベル1: 「所有＝秘密鍵」を署名で証明する(§6, §8)

`cryptography` を使い、以下を実装せよ。

1. secp256k1 の鍵ペアを生成する(ビットコインと同じ曲線)
2. 取引メッセージ `"alice -> bob : 10 BTC"` に**秘密鍵で署名**する
3. **公開鍵で検証**し、成功することを確認する
4. メッセージを1文字だけ改ざんして検証し、**失敗(例外)する**ことを確認する
5. 別の鍵ペアの公開鍵で検証し、失敗することを確認する

**問い**: この結果から「秘密鍵を持つこと=そのコインを動かせること」がなぜ言えるか、自分の言葉で説明せよ。

### レベル2: ミニ・ブロックチェーンで改ざんを検出する(§2, §8)

SHA-256 の**ハッシュ連結**で、3〜4個のブロックからなる簡易ブロックチェーンを実装せよ。各ブロックは少なくとも `index / data / prev_hash / hash` を持つ。

1. ジェネシスブロックから鎖を作る(各ブロックの `hash` は「自分の中身 + prev_hash」の SHA-256)
2. チェーン全体の整合性を検証する関数 `is_valid(chain)` を書く
3. **途中のブロックの data を書き換える**と、それ以降のハッシュが崩れて `is_valid` が `False` になることを示せ

**問い**: なぜ1つのブロックを改ざんすると「それ以降すべて」が壊れるのか、§2 の雪崩効果に触れて説明せよ。

### レベル3(発展): Merkle root と nonce 再利用(§5.2, §8)

いずれか一方(または両方)に挑戦せよ。

- **(a) Merkle 木**: 4件の取引から Merkle root を計算する関数を書け。1件でも取引を変えると root が変わることを示せ。
- **(b) nonce 再利用の危険を再現(概念)**: 同じ ECDSA 秘密鍵で「同じ nonce を使って」2つのメッセージに署名すると、数式上、秘密鍵が復元できてしまう。この攻撃の流れを説明し、なぜ Ed25519(決定論的 nonce)や RFC 6979 がこれを防ぐのかを述べよ(実装は任意)。

## Part B: 耐量子暗号(PQC)を走らせる

### レベル1: ML-KEM で鍵をカプセル化する(§9)

`oqs` を使い、**ML-KEM(旧 Kyber)** で鍵交換(KEM)を実装せよ。

1. 受信者が鍵ペアを生成し、公開鍵を送信者へ渡す
2. 送信者が公開鍵で共有秘密を**カプセル化(encap)** し、暗号文を返す
3. 受信者が暗号文を**デカプセル化(decap)** する
4. 両者の共有秘密が**一致する**ことを確認する

### レベル2: ML-DSA で署名する(§6, §9)

**ML-DSA(旧 Dilithium)** で、Part A と同じ「署名 → 検証 → 改ざんで失敗」を実装せよ。

### レベル3: 古典 vs 耐量子の「サイズ」を比較する

古典(Ed25519 / X25519)と PQC(ML-DSA / ML-KEM)で、**公開鍵・署名・暗号文のバイト数**を出力して表にせよ。

**問い**:
1. PQC は古典と比べて鍵や署名がどれくらい大きいか。それは実務(TLS ハンドシェイク、証明書、帯域)にどんな影響を与えるか。
2. 「ハイブリッド方式(X25519 + ML-KEM を併用)」が移行期に推奨されるのはなぜか(§9)。
3. あなたが「10年後も秘匿すべきデータ」を扱うサービスを設計するとして、今日どんな判断をするか。「Harvest Now, Decrypt Later」に触れて述べよ。
