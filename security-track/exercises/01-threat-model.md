# 演習 01: 脅威モデルを作る(DFD + STRIDE)

対応 Lesson: [01](../lessons/01-attacker-mindset-threat-modeling.md)

## 目的

実在するタイプのアプリを題材に、攻撃者の視点で脅威モデルを作成する。**攻撃の前に「どこが危ないか」を設計段階で見抜く**訓練。

## 題材

「オンライン家計簿 SaaS」を想定する。機能は以下。

- メール + パスワードでユーザー登録・ログイン
- 銀行 API 連携で取引明細を自動取得
- 家族メンバーを招待して家計を共有
- CSV エクスポート
- 管理者向けダッシュボード

## 課題

### レベル1(基礎)

1. このアプリの**攻撃面(attack surface)** を最低8個挙げよ(外部入力・内部の両方)。
2. **信頼境界(trust boundary)** を最低3本特定せよ(どこで「信用できない」から「信用できる」へ変わるか)。

### レベル2(標準)

3. 主要な機能について **データフロー図(DFD)** をテキストまたは図で描け(ユーザー・Webアプリ・DB・銀行API・メール送信を含む)。
4. DFD の各要素に **STRIDE** を当て、**最低10個**の脅威を洗い出し、表にせよ(要素・STRIDE分類・脅威内容・対策)。

### レベル3(発展)

5. 洗い出した脅威を **リスクマトリクス(起こりやすさ × 影響度)** で優先度づけし、「今すぐ直す」トップ3を選び、理由を述べよ。
6. 「家族メンバー招待」機能について、**悪用シナリオ(abuse case)** を3つ書き、それぞれの対策を設計せよ。

## 提出物

- 攻撃面リスト・信頼境界・DFD・STRIDE 表・リスク優先度・abuse case をまとめた Markdown 1枚。

## 評価の観点

- 攻撃面を「機能」だけでなく「内部リソース」まで挙げられているか
- STRIDE の6カテゴリを偏りなく使えているか(特に見落としやすい R = 否認、E = 権限昇格)
- 対策が具体的か(「気をつける」ではなく技術的施策)
