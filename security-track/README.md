# セキュリティエンジニア養成トラック(実戦編) — 世界で通用するセキュリティエンジニアへ

> このコースは、既存のソフトウェアエンジニア教材(本編 Phase 0〜11)とは**独立した単独コース**です。本編を終えていなくても、**プログラミングとコマンドラインの基礎がある人**なら、ここから始めて世界基準のセキュリティエンジニアを目指せます。

## このコースについて

セキュリティは「あとから足す機能」ではありません。それはソフトウェアの見方そのものです。このコースを終える頃、あなたは一行のコードを見るたびに「これはどう悪用されるか」を反射的に考えるようになります。それは職業病ではなく、世界のどこでも通用するプロの証です。

このコースの設計思想は3つ。

1. **手を動かして学ぶ(実戦重視)** — 意図的に脆弱に作られた「やられ役アプリ」を実際に攻撃し、そして直します。読むだけでは1ミリも身につきません。攻撃を再現できて初めて、防御を本当に理解できます。
2. **理論を、丁寧に、分かりやすく** — 「なぜ SQL インジェクションが起きるのか」「なぜ HTTPS は盗聴を防げるのか」を、暗記ではなく**原理から**理解します。原理が分かれば、まだ見たことのない攻撃にも対応できます。手品のタネを知れば、新しい手品も見破れるのと同じです。
3. **世界基準・倫理第一** — 技術用語は英語併記。OWASP・MITRE・NIST といった国際標準に沿い、バグバウンティや CTF、資格を通じて世界のコミュニティで戦える力を育てます。そしてすべての土台に、**攻撃技術を許可された場所でだけ使う規律**を置きます。

> ⚠️ **最重要 — 倫理と合法性(必ず読んでください)**
> このコースで学ぶ攻撃技術は、**あなたが所有するシステム、書面で明示的な許可を得たシステム、または学習用に用意された練習環境(CTF・やられ役 VM)** に対してのみ使ってよいものです。許可なく他者のシステムにアクセス・攻撃することは、世界のほぼすべての国で**重大な犯罪**です(日本: 不正アクセス禁止法/米国: CFAA など)。
> プロのセキュリティエンジニアの第一の資質は技術力ではなく、**この一線を絶対に越えない規律**です。このコースは一貫してその原則の上に立っています。Lesson 00 で最初にラボ環境の隔離方法を学ぶのは、そのためです。

## 🌟 旅の始まりに: 75セントの謎が暴いた、国家ぐるみのスパイ

1986年、カリフォルニア州ローレンス・バークレー研究所。天文学者から流れてきたばかりのシステム管理者 **クリフォード・ストール** は、上司から些細な雑用を任されます。コンピュータの利用課金に **75セント(約100円)の会計の不一致** があるので調べてくれ、と。

普通なら「端数の丸め誤差だろう」で片付ける話です。しかしストールは、天文学者らしい執拗さでこの小さな綻びを引っ張り続けました。誰が、たった9秒間、料金を払わずにシステムを使ったのか。追っていくと、それは登録されていない幽霊のようなユーザーでした。

彼はプリンタを何台も並べ、侵入者のセッションをすべて紙に記録し始めます。眠るときも研究室の床で寝袋にくるまり、侵入者がログインするたびにポケベルで飛び起きました。追跡は数ヶ月に及びます。侵入者は研究所を**踏み台(pivot)**にして、米軍基地、NASA、防衛関連ネットワークへの侵入を試みていました。ストールは偽の機密文書(**ハニーポット**)を仕掛けて相手を長く釣り、通信経路を一本ずつ手繰り寄せます。

たどり着いた先は、西ドイツのハノーバー。侵入者は **KGB(ソ連国家保安委員会)に情報を売っていたハッカー集団** の一員でした。75セントの会計エラーが、国家をまたぐスパイ事件を暴いたのです。

ストールはこの顛末を『**カッコウはコンピュータに卵を産む(The Cuckoo's Egg)**』という本に記し、それは今もセキュリティエンジニアの必読書です。この物語が教えるのは、高価なツールでも天才的なひらめきでもありません。

> **「おかしい」という小さな違和感を、面倒がらずに最後まで追いかける執念。** — それがセキュリティの核心です。

あなたがこのコースで身につけるのも、結局はこの姿勢です。ログの一行、レスポンスの数ミリ秒の差、いつもと違うプロセス。世界を守るのは、その違和感を見逃さない人です。ようこそ、攻撃と防御の芸術へ。

## このコースの対象者と前提

**対象**: プログラミングは書けるが、セキュリティは体系的に学んだことがない人。「セキュリティに興味はあるが、何から手をつければいいか分からない」人。

**前提知識**(以下があれば、セキュリティ側の知識はすべてゼロから丁寧に教えます):

- 何らかの言語で**プログラムが読み書きできる**(このコースは主に Python を使います。読めれば OK)
- **コマンドライン(ターミナル)** に強い抵抗がない(`cd`, `ls`, `grep`, パイプ程度)
- **HTTP と Web の基本**(ブラウザが GET/POST する、くらいのイメージがあれば十分。詳細は Lesson 04 で作り直します)
- Git が使える(成果物をポートフォリオとして残すため)

ネットワーク・暗号・OS・クラウドのセキュリティに必要な理論は、**このコースの中で必要なぶんだけ、そのつど丁寧に解説**します。「前提として知っておくべき」とは突き放しません。

## 修了条件チェックリスト

### 知識(理論を自分の言葉で説明できるか)

- [ ] STRIDE の 6 カテゴリと対策、CIA との対応関係を説明できる
- [ ] 対称鍵/公開鍵/ハッシュ/署名の役割の違いを説明できる
- [ ] TLS ハンドシェイクの流れと、証明書が「何を」保証するかを説明できる
- [ ] 同一オリジンポリシー・CORS・CSP の関係を説明できる
- [ ] SQLi/XSS/CSRF/SSRF/IDOR の原理と対策をそれぞれ説明できる
- [ ] OAuth 2.0 認可コードフロー(+PKCE)を図示できる
- [ ] 最小権限・多層防御・フェイルセーフを具体例で説明できる
- [ ] SAST/DAST/SCA の違い、プロンプトインジェクションの緩和策を説明できる

### 実技(実際に手を動かせるか)

- [ ] やられ役アプリで SQL インジェクションを再現し、パラメータ化で修正した
- [ ] 反射型・格納型 XSS を再現し、出力エスケープ + CSP で修正した
- [ ] JWT の `alg:none` / 弱い署名鍵を攻撃し、修正した
- [ ] Burp Suite / mitmproxy でリクエストを傍受・改ざんした
- [ ] nmap でポートスキャン、Wireshark でパケットを観察した
- [ ] CI に SAST/SCA を組み込み、脆弱な依存を検出した
- [ ] ログから不審なアクセスを見つけ、インシデントのタイムラインを書いた
- [ ] 総仕上げプロジェクトの診断報告書を完成させた

### 姿勢

- [ ] コードを見ると「これはどう悪用されるか」を自然に考える癖がついた
- [ ] 攻撃技術を**許可された環境でのみ**使う規律が身についた
- [ ] 脆弱性を見つけたら、責任ある開示(responsible disclosure)の作法を知っている

## 環境準備(概要)

詳細は [Lesson 00](lessons/00-lab-setup.md) で丁寧に案内します。ここでは全体像だけ。すべて無料で用意できます。

```bash
# やられ役アプリ(意図的に脆弱。学習専用。絶対にインターネットに公開しない)
docker run --rm -p 3000:3000 bkimminich/juice-shop     # OWASP Juice Shop
docker run --rm -p 8080:80 vulnerables/web-dvwa          # DVWA

# プロキシ / 傍受ツール
# Burp Suite Community Edition: https://portswigger.net/burp
pip install mitmproxy                                    # 軽量な代替

# ネットワーク調査 / スクリプト
brew install nmap wireshark                              # Mac(Ubuntu は apt)
python3 --version                                        # 3.10+ 推奨
pip install requests pyjwt cryptography scapy pip-audit

# コンテナ/イメージ脆弱性スキャン
brew install aquasecurity/trivy/trivy
```

> 🧪 **ラボの鉄則**: やられ役アプリは**絶対にインターネットへ公開しない**。攻撃側とやられ役はホストオンリーネットワークで隔離する。「自分のマシンの中の閉じた世界」で暴れるのがプロの遊び場です。
