# Phase 12: 総合プロジェクトと OSS 貢献

## 概要

Phase 12 は、これまでの学習を統合し、実際に世界へ向けて成果を発信するフェーズです。
キャップストーンプロジェクトを通じて「0 から本番稼働まで」を経験し、オープンソースソフトウェア(OSS: Open Source Software)への貢献を通じて実際の開発現場に近い経験を積みます。

このフェーズを修了したとき、あなたは「コードが書けます」ではなく「動いているプロダクトを届けた実績があります」と世界に向けて主張できるエンジニアになっています。

---

## 🌟 旅の始まりに: 必要なのは、ピザとコーラと決意

DOOM や Quake で 3D ゲームの歴史を作った伝説のプログラマー、ジョン・カーマックの言葉があります(『Masters of Doom』より)。

> 「情報化時代において、障壁というものは存在しない。**障壁は自分で課しているだけだ。** 壮大な何かを作り始めるのに、数百万ドルの資本は要らない。**冷蔵庫に入れるピザとコーラ、安い PC、そしてやり遂げる決意があればいい。**」

彼自身がその証明です。数人の若者が借家の一室で、夜通しコードを書いてゲーム産業を変えました。

そしてこれは1990年代より、今のあなたに一層当てはまります。開発環境は無料、学習資料は無料、公開の場(GitHub)も無料、クラウドもほぼ無料で始められる — Phase 10 までで、あなたはすでに全部持っています。

Phase 12 は、このカリキュラムで唯一「教わる」より「作る」章です。ここから先の差は、知識ではなく決意でつきます。ピザを冷蔵庫に入れて、始めましょう。

## 前提知識

**Phase 10 までを修了していること。**

具体的には以下の技術・概念を理解・実践済みであることを前提とします。

- React によるフロントエンド開発(Phase 6)
- FastAPI による RESTful API の設計と実装(Phase 7)
- PostgreSQL によるデータモデリングと SQL(Phase 7)
- Docker / Docker Compose によるコンテナ化(Phase 10)
- GitHub Actions による CI/CD パイプラインの構築(Phase 10)
- Git によるバージョン管理とブランチ戦略(Phase 3)
- 基本的なクラウドデプロイ(Phase 10)

### Phase 11(分散システム)は前提ではありません

以前ここには「Phase 11 までを修了していること」と書いてありました。**しかし上の一覧に Phase 11 由来の項目は 1 つもありません。**

capstone の仕様・週次マイルストーン・評価ルーブリックを確認したところ、レプリケーション、整合性モデル、パーティショニング、合意といった概念は**どこからも要求されていませんでした。**capstone は単一構成の Web アプリだからです。

したがって **Phase 10 を終えた時点で、この Phase を始められます。** Phase 11 は次のどちらでも構いません。

| 進め方 | 向いている場合 |
|---|---|
| **11 → 12** | 順番に積みたい。分散システムを落ち着いて学びたい |
| **11 と 12 を並走** | 早く公開したい。作りながら学ぶほうが定着する |

**急いで並走させる必要はありません。**capstone は 8 週間の重い課題です。ただ、**必要のない待ち時間を制度として課さない**というだけです。

### OSS 貢献は、早く読み始めてください

Lesson 05 が必要とするのは **Git と Pull Request(Phase 3)、そして他人のコードを読む力**だけです。capstone は要りません。

にもかかわらず最後に置いてあると、**時間の使い方として損をします。**

```
貢献先を探す      → 数週間(自分が使っている道具から選ぶのが近道)
コードベースに慣れる → 数週間(Issue を眺め、議論を読む)
good first issue   → 出るのを待つ
初 PR → レビュー → マージ → さらに数週間
```

**着手から最初のマージまで、数か月かかるのが普通です。**Phase 12 に入ってから始めると、就職活動の時期に間に合いません。

Phase 3 を終えたら、まず Lesson 05 を読んで**貢献先を 1 つ決めてください。**その後は「毎週 Issue を 10 分眺める」程度で構いません。実際に PR を出すのは、後の Phase になってからで大丈夫です。

## 修了条件チェックリスト

以下をすべて達成することで Phase 12 修了とします。

### キャップストーンプロジェクト

- [ ] 要件定義書(または Design Doc)を GitHub リポジトリに配置してある
- [ ] フロントエンド(React)、バックエンド(FastAPI)、データベース(PostgreSQL)が Docker Compose で一発起動できる
- [ ] ユーザー認証(サインアップ / ログイン / ログアウト)が動作する
- [ ] コア機能が最低 3 つ実装され、それぞれに E2E テスト(またはインテグレーションテスト)がある
- [ ] GitHub Actions で lint / test / build が自動実行される
- [ ] 本番環境 URL が存在し、インターネットからアクセスできる
- [ ] README.md にスクリーンショットまたはデモ動画リンクが含まれている
- [ ] 評価ルーブリックで「中級」以上のスコアを自己評価できる

### ポートフォリオ

- [ ] GitHub プロフィール README を整備した
- [ ] キャップストーンリポジトリの README が英語で書かれており、デモリンクがある
- [ ] LinkedIn または個人サイトにプロジェクト実績が掲載されている

### OSS 貢献

- [ ] 貢献先リポジトリを 1 つ以上選定し、CONTRIBUTING.md を読んだ
- [ ] good first issue に対して Issue コメントまたは PR を送った
- [ ] PR がオープン状態(マージされなくても可)になっている

### 振り返りと発信

- [ ] 技術ブログ記事(日本語または英語)を 1 本以上公開した
- [ ] Phase 12 で学んだことを 3 つ以上箇条書きで言語化できる
- [ ] [Phase 12 実技試験](assessment/)に合格した

## 学習の進め方

キャップストーンを実装して公開した後、[Phase 12 実技試験](assessment/)として実ユーザーのフィードバックを収集し、少なくとも1回改善します。利用記録、外部レビュー、改善前後の差分までを修了証拠として残してください。

## このフェーズを終えた先

Phase 12 を修了したエンジニアは、次のステップとして以下を検討できます。

- 実際の就職・転職活動(ポートフォリオを武器に)
- OSS メンテナーへの挑戦
- 技術カンファレンスへの登壇応募
- 個人プロダクトの立ち上げ・マネタイズ
- 技術スペシャリスト(SRE、セキュリティ、ML エンジニア等)への深化

世界基準のエンジニアへの道は、このフェーズで「作り、届け、貢献する」ことから始まります。
