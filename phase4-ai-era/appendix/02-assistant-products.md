# 付録: AI コーディングアシスタントの製品と使い方

> **この付録は、この教材で最も早く古くなる部分です。**
>
> AI ツールの領域は動きが速く、製品名・料金・モデル・権限の仕組み・データの扱いは**数か月単位で変わります。**ここに書かれた製品が、数年後に存在しない可能性も十分にあります。
>
> [Lesson 02](../lessons/02-ai-coding-assistants.md) 本文の考え方 — 3 つのモード、責任は移らないという原則、使わないほうがよい場面、道具の選び方 — は、製品が入れ替わっても変わりません。
>
> **ここに書かれた手順が実物と合わなければ、公式ドキュメントを見てください。**そして、この付録のほうを直してください。

対応する本文: [Lesson 02: AI コーディングアシスタントの使い方](../lessons/02-ai-coding-assistants.md)

## 1. 製品の例

以下は**製品例であり、特定製品の採用を推奨する一覧ではありません。**選定するときは、本文の「道具の選び方」にある評価軸で、必ず公式情報を比較してください。

| 製品 | 主な形態 | 特徴 |
|---|---|---|
| GitHub Copilot | エディタ拡張 | 補完が中心。多くのエディタに組み込める |
| Claude Code | CLI | エージェントが中心。コードベース全体を読んで複数ファイルを扱う |
| Cursor | エディタ | AI 機能を前面に出したエディタ。モデルを選べる |
| Gemini Code Assist | エディタ拡張 / クラウド連携 | Google のクラウドと統合 |
| Amazon Q Developer | エディタ拡張 / クラウド連携 | AWS と統合 |

多くの製品が複数のモードを備えつつあります。**「この製品は補完専用」といった分類は、すぐに古くなります。**本文で学ぶのはモードの区別であって、製品の分類ではありません。

## 2. エディタ拡張型の使い方(補完中心)

```
1. エディタに拡張機能をインストールする
2. アカウントでサインインする
3. コードを書き始めると、グレーの文字で補完候補が出る
4. Tab キーで採用、Esc キーで却下
5. 採用したら、必ず一読して意図に合っているか確認する
```

多くの製品で、選択範囲について質問できる「インラインチャット」が用意されています(`Cmd + I` / `Ctrl + I` が一般的)。

**手順 5 が最も重要です。** 本文で述べたとおり、Tab を反射的に押す癖は、この道具で最も危険な習慣です。

## 3. CLI エージェント型の使い方

```bash
# インストール（製品によって異なる）
npm install -g @anthropic-ai/claude-code

# プロジェクトディレクトリで起動
cd your-project
claude

# 起動後は会話形式でタスクを依頼する
# 例: "このプロジェクトの構造を説明してください"
# 例: "src/auth.py の validate_token 関数のバグを見つけてください"
```

エージェントを使うときの原則は、製品が変わっても同じです。

| 原則 | なぜ |
|---|---|
| **Git 管理下でだけ使う** | 変更を差分で確認でき、いつでも戻せる |
| **作業前にコミットしておく** | 「どこから AI が触ったか」の境界が明確になる |
| **権限は最小にする** | 実行できる範囲を絞れば、事故の被害も絞られる |
| **差分と実行結果を必ず読む** | 自信のある口調と、正しさは別のものだから |

## 4. 選ぶときに公式情報で確認すること

本文の評価軸に沿って、次を**公式のドキュメントで**確認してください。他人のまとめ記事は、書かれた時点で古くなっています。

- どのモデルが使われ、選べるのか
- 送ったコードが学習に使われるか(データの保持と利用)
- 履歴がどこに、どれだけ残るか
- 実行できる操作の範囲と、承認の仕組み
- 監査ログが取れるか
- 料金の体系
- 組織のポリシーに適合するか

**業務で使う前には、必ず所属組織のポリシーを確認してください。** 個人の判断で機密コードを外部サービスに送ると、技術ではなく契約の問題になります。
