# 付録: AWS を実際に触る

> **この付録は「早く古くなる側」です。**
>
> ここに書いてあるのは、ある時点の特定の製品の画面と手順です。ボタンの位置、メニューの名前、無料枠の条件は、**予告なく変わります。**
>
> [Lesson 05](../lessons/05-cloud-basics.md) 本文の原理 — 何を借りているのか、最小権限とは何か、可用性ゾーンはなぜ複数使うのか — は変わりません。**手順が実物と合わなくなっていたら、公式ドキュメントを見て、この付録のほうを直してください。**本文を疑う必要はありません。
>
> 他社のクラウドを使う場合も、やることの順序はほぼ同じです。名前だけが違います。

対応する本文: [Lesson 05: クラウド基礎](../lessons/05-cloud-basics.md)

## 1. 始める前に — 課金事故を防ぐ

クラウドの学習で最も多い事故は、技術的な失敗ではなく**請求書**です。作ったまま忘れたリソースが、静かに課金され続けます。

**手を動かす前に、必ずこの順序で進めてください。**

1. 請求アラートを設定する
2. root ユーザーではない作業用ユーザーを作る
3. そのあとで初めてリソースを作る
4. 使い終わったら削除する

順序を守れば、事故の大半は起きません。

---

## 2. アカウントと作業用ユーザー

### root ユーザーを日常使いしない

アカウント作成時のメールアドレスで入るユーザー(root)は、**すべての権限を持ち、権限を制限できません。**これは本文で学んだ最小権限の原則に真っ向から反します。

root は次の 2 つだけに使います。

- 初回設定(請求アラート、作業用ユーザーの作成)
- root にしかできない操作(アカウントの解約など)

### 作業用ユーザーを作る

```
IAM → Users → Create user
  - ユーザー名を決める
  - コンソールへのアクセスを有効にする
  - 権限: 学習用なら AdministratorAccess で始めてよい
  - アクセスキーは作らない(画面から操作するだけなら不要)
```

**アクセスキーを作らない**のが重要です。アクセスキーは長期間有効な認証情報で、うっかり Git に混入させると、その瞬間から誰でも使えます。実際に、公開リポジトリに置かれたキーは**数分で発見され悪用されます。**必要になるまで作らないのが最も安全です。

root には多要素認証(MFA)を必ず設定してください。

### 請求アラート

```
Billing → Budgets → Create budget
  - 月 $5 を超えたらメールで通知、程度から始める
```

金額の大小は問題ではありません。**「気づける状態にあること」**が目的です。

## 3. 仮想サーバを 1 台立てる

```
EC2 → Launch instance
  - AMI (OS イメージ): Ubuntu の LTS 版
  - Instance type: 最小の無料枠対象インスタンス
  - Key pair: 新規作成して .pem ファイルをダウンロードする
  - Security group: SSH(22) と HTTP(80) を許可
```

### 鍵ファイルの扱い

```bash
chmod 400 ~/.ssh/my-key.pem
ssh -i ~/.ssh/my-key.pem ubuntu@<パブリック IP>
```

`chmod 400`(所有者だけが読める)が必要です。これを省くと SSH が接続を拒否します。他人が読める場所に秘密鍵を置くのは、鍵を玄関マットの下に置くのと同じだからです。

### ファイアウォールの設定

AWS では Security Group と呼びます。他社では別の名前ですが、やることは同じです。

| 向き | ポート | 許可する範囲 | 理由 |
|---|---|---|---|
| 受信 | 22 (SSH) | **自分の IP だけ** | 全世界に開けると、数分でログイン試行が始まる |
| 受信 | 80 / 443 (HTTP/HTTPS) | 全 IP | 公開サービスなので全員に見せる |
| 送信 | すべて | 全 IP | 通常は制限しない |

SSH を `0.0.0.0/0`(全世界)に開けないでください。インターネットに面したサーバへの総当たり攻撃は、**立てた直後から始まります。**これは脅しではなく、ログを見れば分かる事実です。

## 4. 費用を抑える

| やること | なぜ |
|---|---|
| 使わないサーバは停止する | 停止中は計算リソースの課金が止まる(ディスクは課金され続ける) |
| 使わない固定 IP は解放する | **付けていない**固定 IP に課金する仕組みがある。直感に反するので事故りやすい |
| 練習が終わったら削除する | 停止では消えない課金がある。学習目的なら消すのが確実 |
| コストを週 1 回見る | 見る習慣がないと、月末の請求で初めて気づく |

無料枠の具体的な条件(何時間、何 GB まで)は変わり続けるので、ここには書きません。**公式の料金ページを見てください。**書き写した数字は必ず古くなり、古い数字は無いより悪いからです。

---

## 5. 片付ける

**練習が終わったら、作ったものを消してください。** 消し忘れは、この付録で唯一取り返しのつかない失敗です。

消す順序は、依存の逆順です。

```
1. EC2 インスタンスを終了(Terminate)する
2. 使っていない EBS ボリュームを削除する
3. 固定 IP (Elastic IP) を解放する
4. 作った Security Group を削除する
5. Cost Explorer で、翌日に課金が止まっていることを確認する
```

最後の確認まで含めて「片付け」です。消したつもりで消えていないことがあります。

## 6. 他社クラウドの場合

本文の [Lesson 05](../lessons/05-cloud-basics.md) にある対応表のとおり、役割は同じで名前が違うだけです。この付録の手順は、次のように読み替えられます。

| この付録の記述 | 一般的な言い方 |
|---|---|
| IAM ユーザー | クラウド上のアイデンティティ |
| EC2 インスタンス | 仮想マシン |
| Security Group | ネットワークのファイアウォール規則 |
| Elastic IP | 固定のパブリック IP アドレス |
| AMI | OS イメージ |

どの事業者でも、**請求アラートを先に設定し、root を日常使いせず、SSH を全世界に開けず、使い終わったら消す。**この 4 つは変わりません。
